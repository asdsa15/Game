# 问道长生 · 网页实现体

《问道长生》设定下的**可运行网页版**：纯静态前端，双层源码（数据／规则／表现），双击即玩。
手机端已适配，可装 PWA 或打包成 APK；桌面端可打 Electron。

> **当前版本 v10.7**（源码 `VER = '10.2'`，存档格式未变；功能批次至 v9.0 M4 + v10.1 三梯队
> + v10.2 界面优化 + v10.3 P0/P1 修复 + v10.4 P0/P1/P2 + v10.5 P0 上限/经济/三分
> + v10.5 P1 战斗经济调整 · P2 账本与口径收口 + v10.6 叙事素材落地
> + **v10.7 阶段一：左导航替代底部功能坞 / 战斗口径修复 / 敌我状态归位**）。
> 测试基线 **1308 项断言全绿**（1276 主测 + 32 项 smoke_econ），静态检查三项通过。
> 源码分层：`data`（107 张表）→ `rules`（34 个纯函数，含 `SAVE_VER`）→ `game`（薄缝）→ 十五个扩展。
> 新玩法写在 `wxcs3-ext-*.js`，`build.py` 自动收集，不再往 `game.js` 里堆。
> v10.7 方案按**三个进度阶段**推进（阶段一已完成），见 `docs/01_审查与诊断/v10.7_三阶段推进计划_20261121.md`。

## 六、维护约定

0. **每一次改动都必须同步更新 `docs/00_项目地图.md`**（行数、体量、测试基线、新增接缝与入口）。
   项目地图是「先读它、别通读源码」的唯一入口，它一旦落后，下一次排查就会按旧行号走错路。
   规矩是硬的：**代码改了、数据改了、产物重建了，地图没改完，这次改动就不算完成。**
1. **改数值前先看 `docs/01_` 最近的审查报告**，尤其是已经踩过的坑（香火需求曲线、跨体系位格换算、字符串中文名比英文键）。
2. **改 `data.js` 里任何 `act:` 之后，跑一次 `check_actions.py`**——`dispatch` 只认 `do;` / `act:` / `enc:` / `tx:` 等前缀，写错就是静默失败。
3. **`dispatch` 末尾的兜底 toast 不要删**，它能把"静默卡死"降级成"明确提示"。
4. **面板代码块内不留空行**，Markdown 严格解析下会切断 `\(...\)`。
5. **新文档放 `docs/` 对应子目录**，别堆回根目录。
6. **改存档 / 经济 / 结局三处，先读项目地图第六章的接缝**，并跑 `node tools/test_save.js`、`node tools/test_reachability.js`、`node tools/smoke_econ.js`。
