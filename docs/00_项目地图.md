## 三、加载顺序（改代码前必须知道）

```
wxcs3-data.js → wxcs3-art.js → wxcs3-icons.js → wxcs3-rules.js
  → wxcs3-game.js → wxcs3-ext-*.js（文件名排序：10→20→…→93→94→95）
```

- `rules.js` 必须早于 `game.js`：后者开头把 `RULES.*` 绑成同名局部常量，缺了直接 `throw`。
- `mobile/build.py` 用 `EXT_GLOB = 'wxcs3-ext-*.js'` 自动扫描，按 Python `sorted()` 字典序内联。
  **不要用 100+ 前缀**：`100-*` 会排到 `10-*` 前面。
- 开发页 `问道长生v6.html` 已直接列出 10~95 的 `<script>` 标签；新增扩展要**同时**改 HTML 与构建扫描。
- 顺序有依赖：10 命格先于 20 天劫；91/92 先于 93；94 提供 `registerMul` 遗物乘区，95 提供 `fruitSnapshot/applyFruit`。

## 四、每层放什么

| 层 | 文件 | 判据 |
|---|---|---|
| 数据 | `wxcs3-data.js` | 纯表：数值、文案、词库 |
| 规则 | `wxcs3-rules.js` | **不碰 DOM、不写 `S`、不产 HTML** |
| 表现 | `wxcs3-game.js` | 状态、渲染、ACT |
| 扩展 | `wxcs3-ext-<名字>.js` | 新玩法一律放这里 |

判断某函数能否搬进 `rules.js`：**不看它自己写了什么，看它调用链上还有谁在读 `S`。**

### 6.2 经济：零售价 vs 回收价

```
零售价（买入）        PILL_EXT / TALISMANS / ARTIFACT_EXT / MATERIAL_EXT 的 price
成品基准 outPriceOf() 同上（按 recipe.kind 取产物表）；阵盘无 price → 材料成本 × 1.6
回收价 sellPriceOf()  基准 × RECOVER_BASE(0.6) × 行情 × 品相 × 渠道倍率 × 拍卖抽成
```

- `SELL_CHANNELS.mul` 是**相对回收基准**的系数，不是相对零售价的溢价；最高档黑市 0.87× 仍低于进货价。
- 面板报价一律走 `outPriceOf` + `RECOVER_BASE`，与结算同源；不要再出现「面板一套、结算一套」。
- 材料卖出（`do_sellmat`）与成品卖出走同一条 `sellPriceOf`，黑市同样背业力。

### 6.3 结局判定

| 位置 | 规则 |
|---|---|
| `resolveEnding` | **顺序是有语义的**：`endingId` → `reincShown` → 登仙/道胎/世尊/真君/果位/名望/魔道 → 寿元 → 失锚（`/道化\|锚\|枯朽/`）→ 横死 |
| 为什么 | 进入结局屏的唯一路径 `finalizeDeath` **必定写 `deathReason`**；任何排在死因之后的判定都永远执行不到（v10.3 前的 7 个结局就是这么死的） |
| `do_burn` | 烧页时置 `S.reincShown`，这是 `reinc` 结局唯一的游戏内出口 |
| `tools/test_reachability.js` | 用**真实死亡流程**（hp→0 → 临终 → 闭眼）验结局，不要再用 `deathReason:null` 手工构造不存在的状态 |
