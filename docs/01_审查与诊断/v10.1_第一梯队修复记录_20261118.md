## 一、软死档：百世书页数耗尽后无处可去

### 病灶（实测复现）

| 环节 | 事实 |
|---|---|
| `newGame` | `pages: 3`（初始 3 页） |
| 消耗 | 每次轮回 `S.pages = Math.max(0, pageCount() - 1)` |
| 补充 | **全局检索确认无任何补充机制** |
| 结局界面 | 唯一按钮是「百世书 · 烧一页重来」 |
| `do_burn` | `pages===0` 时 `toast('没有页可烧')` 直接 return |

第 4 次死亡后：结局界面有一个点了没反应的按钮，只能走系统菜单的 `do_reset`——而那会连跨世成就一起清空。

更矛盾的是：成就 `guo_reinc`（烧尽）的条件正是 `s.pages === 0`，**成就鼓励你烧到 0，烧到 0 就锁死**。

### 修法

结局界面按页数分叉：

```
pageCount() > 0  →  「百世书 · 烧一页重来」（原逻辑不变）
pageCount() === 0 → 「空手投胎 · 从零再走」（新增 do_rebor）
```

`do_rebor` 刻意与 `do_legacy` 只差两点：

| | `do_legacy`（烧页） | `do_rebor`（空手投胎） |
|---|---|---|
| 扣页 | −1 | 不扣（本来就没有） |
| 传承 | 三选一（宝物/修为/寿元） | **不带任何传承** |
| 血债 | +10% | **+10%（照加）** |
| 功过格/前世记忆 | 保留 | 保留 |

这样「烧尽」是真有代价，而不是换个名字继续拿好处。对应成就文案「末页亦焚，来世无物可带，**包括所应之事**」——所应之事即临终所托 `legacyPact`，这一项仍然生效，因为那是别人的承诺，不是你的遗产。

## 二、两个永不触发的结局

### `ascend`（登仙）

原文案：**「补回断掉的四境」**。此前代码里没有任何对应机制，零调用。

**不改造成新系统**（上古残卷收集是另一批工作量），改用道胎之后**真实存在**的进展：

```
isXian() && xRealm >= 5（道胎）
  && 四锚各 >= 1（全固）
  && merit >= 100 && karma < 100
  → ascend
```

道胎无寿元，只靠四锚钉住自己。**四锚全固＝把自己一段一段接回来**，与文案「一段一段接回来。最后一段接上的时候，天没有开，也没有雷」正好同义。

### `reinc`（百世书）

原文案「烧一页重来」。此前 `do_legacy` 直接 `newGame()`，从不展示结局，所以这个结局永远不显示。

修法：在**烧页面板顶部**展示该结局名与正文。语义上「烧一页」本身就是这一世的结尾，玩家点开面板先看到自己以「百世书」收尾，再选择带什么走。

### 判定顺序

```
endingId（显式指定，如 shizun/zhenjun/reinc）
  → 死因（寿元 / 道化 / 其他）  ← 死亡类结局优先
  → ascend（道胎 + 四锚 + 功德）← 新增，置于 daotai 之前
  → daotai / shizun / zhenjun / guowei / xianzun / modao
```

`ascend` 必须排在 `daotai` 之前：否则道胎一律落 `daotai`，永远轮不到登仙。

## 三、成就 `oldGrudge` 被白名单永久屏蔽

`tools/check_ach.js` 的归档理由写的是「需要旧仇寻仇与击杀流程（S.enemy 只置位，无击杀路径）」。

**但击杀链早在 v8.0 就通了**：`noteCombatWin` 里 `c.isVengeance && S.enemy` 分支会清 `S.enemy`、加声望、给灵石——唯独忘了 `bump('oldGrudge')`。

于是：玩法在、计数器没接、白名单把它伪装成「设计如此」，检查器永远报绿。

修法：在该分支补 `bump('oldGrudge')`，同时删掉白名单条目。

| | 修复前 | 修复后 |
|---|---|---|
| 归档 | 8 条 | **7 条** |
| 可达 | 100 | **101** |

## 四、战斗状态可见性

### 病灶

`renderCombat` 的状态区只显示 2 条（守势 / 看破），而真正影响伤害的还有六七项：

`foeMark`（我方 ×1.25）、`foeWeaken`（敌方 ×0.7）、`talBuff`、`talShield`、`noFoeFlee`、`momentum`（敌方增伤）——**全部没有 UI**。

玩家挨刀少掉一半血，不知道是守势、金刚符还是本命法器挡的；打出 ×1.25 也看不到标记。

### 修法

**零改公式**，只把已有字段渲染成 chip，接进 `renderCombat` 现有的 tags 区：

| chip | 来源字段 | 显示 |
|---|---|---|
| 破绽 | `foeMark` | 我方伤害 ×1.25（N 回合） |
| 压制 | `foeWeaken` | 敌方伤害 ×0.7（N 回合） |
| 神通加成 | `talBuff` | 伤害 +N% |
| 护体 | `talShield` | 本次减伤 N% |
| 锁灵 | `noFoeFlee` | 敌方不能遁走 |
| 敌方气势 | `momentum` | 增伤 +N% |

剩余回合数直接读字段本身（`foeMark`/`foeWeaken` 在 `foeTurn` 里递减），所以数字就是「还剩几回合」，不是估算。

本命法器的 `bmVeil`（出鞘待挡）与器损在 `wxcs3-ext-40-benming.js` 里注册了 `fightInfoHooks` 自报——沿用灵兽已有的钩子模式，主文件不需要知道扩展细节。

## 五、顺带修掉的一处测试缺陷

`smoke_econ.js` 有一条断言 `S.stones >= 500`，前提是「打坐不花钱」。但 v8.1 落地固定开销后，打坐推到月末会结算庙宇修缮，灵石必然低于初始值——**这条断言约 1/6 概率随机失败**。

已改为断言「香火钱确实入账」这一件事本身（查账本里有该笔收入），并连跑 6 次确认稳定。

> 这不是本轮引入的，但它会让「全绿」失去可信度，顺手修掉。
