## 二、问题7：通用瓶颈校验器（`wxcs3-ext-80-gate.js`）

### 设计

`breakGate()` 是**表驱动**的门槛校验器——复用 `bookLayerOk` 的 need 结构思路，但独立成通用函数，不绑死在道书上。每道门槛都带三样东西：

```
{ id, label, check(), text(), hint() }
```

**`hint()` 是硬要求**：说不清「怎么补」的门槛，与死档没有区别。这一点从第一版就写进了规则，并有断言守着。

### 四道门槛

| 门槛 | 生效境界 | 判定 | 解法 |
|---|---|---|---|
| 灵根与功法相合 | 筑基起（xRealm ≥ 1） | 主修功法的五行与**主灵根**同源或相生 | 换一本相生的功法设为主修；无属性功法（聚气诀）不受此限 |
| 道书已读 | 筑基→紫府（xRealm ≥ 2） | 至少读通 1 层道书 | 去「道书」读一卷能读懂的书 |
| 悟性门槛 | 金丹起（xRealm ≥ 3） | 有效悟性 ≥ 12 | 机缘/读书/破境失败；**每 20 点悟道折 1 点悟性** |
| 香火虔诚 | 神道二柱起（pillar ≥ 1） | 虔诚达「日日供奉」档 | 显圣、庙会、施香 |

### 两个刻意做的「不设」

1. **胎息（xRealm 0）不设任何门槛** —— 新手第一课不能是"被拦住"。
2. **灵根门槛只看主系，不要求覆盖全部已选五行**。
   第一版写成「覆盖 rootEls 过半」，测试立刻暴露问题：四系伪灵根几乎不可能满足，等于把最需要出路的灵根直接锁死。这与方案要治的病是同一类错误。多系继续在**战斗克制**（ext-70 的 `bestKe`）里发挥作用，不在这里重复收费。

## 三、问题6：盘活死表（`wxcs3-ext-90-revive.js`）

逐张处理方案盘点出的死表/死字段：

| 字段 | 原状 | 本轮落点 |
|---|---|---|
| `PIETY`（4 档名） | 只在公式里当连续值乘，档位名一次都没显示过 | 状态栏显示「日日供奉 1.6」；破柱门槛用档位判定 |
| `QIHE`（benming/guest/clash） | **零引用**，`game.js:284` 硬编码 1.2/0.8；clash 0.6 从未用过 | `xianghuoQiheMul()` 读表，三态按破柱三法判定 |
| `FAXIANG.zodiac` | 只在创角界面显示一个生肖字 | 生肖→五行，接进显圣强度（×0.95~1.10） |
| `insightXp` | 6 处产出、**零消费** | 破境悟性门槛可折算；状态栏显示「悟道 60（折悟性 +3）」 |
| `ZODIAC_CLASH` | —— | **经查已在 NPC 系统消费（`game.js:4960`），非死表，不动** |

### QIHE 三态的设计弯路（值得记下）

最初想按「本柱真君生肖 vs 法相生肖」判相冲。查表后发现 **`D.ZHENJUN` 与 `D.FAXIANG` 是同一套**（id 都 g1~g12、生肖一一对应），本柱真君恒等于自己的法相，**clash 永远不会触发**——那是写了个死分支。

改为绑定「**破柱三法**」，三态各有真实出处：

- **自建**（正祀）→ `benming` 本命线 ×1.2，庙是自己立的
- **借祀**（附祀）→ `guest` 客庙 ×0.8，香火要分出去两成
- **夺祀**（抢祀）→ `clash` 相冲法相 ×0.6，砸来的庙气机相冲

这样三态与神道主线强相关，而不是靠生肖巧合。

## 六、过程中修掉的真实 bug

1. **灵根门槛会锁死四系伪灵根**
   第一版要求「功法五行覆盖 rootEls 过半」，四系几乎无解。改为只看主系后，伪灵根配水行功法可过。
   **教训**：设门槛时先问「最难的那个组合有没有解」，而不是「常规组合能不能过」。

2. **insightXp 的消费端接错了位置**
   门槛判定最初用 `st('insight')`（面板值），而悟道点折算是另算的——等于消费端没接上。
   改为 `effInsight() = st('insight') + insightBonus()`，并单独实现一份在 ext-80 里，避免依赖 ext-90 的加载顺序。

3. **QIHE 的 clash 是死分支**
   见上文「设计弯路」。靠 ZHENJUN/FAXIANG 生肖永远判不出相冲。

4. **门槛被「功法所限」抢先返回**
   `openBreak` 里「功法所限」分支在门槛之前 return。这个顺序其实是**对的**（品阶不够是更根本的限制），但测试场景选错了，一度误判为 bug。修正测试而非代码。
