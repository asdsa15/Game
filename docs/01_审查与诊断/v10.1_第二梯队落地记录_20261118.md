## 二、做了什么

### 1. 功法 eff 数据化（`wxcs3-ext-60-gongfa.js`）

新增 `EFFECT` 表：把 `GONGFA_EXT` 的 `eff` 文案**逐条编译成可结算字段**，而不是另起一套新数据。字段口径：

| 字段 | 含义 | 落地功法举例 |
|---|---|---|
| `dims` | 按招式五行/类别的伤害乘区 | 玄元剑经 `sword:1.40`、烈火掌 `fire:1.25` |
| `all` | 无条件伤害乘区 | 天河剑诀 `1.50`、鸿蒙紫气诀 `1.35` |
| `ward` | 我方减伤 | 金光咒 `0.10`、金殿煌元诀 `0.12` |
| `escape` | 遁走成功率 | 御风术 `0.05`、凌波仙经 `0.12`、天遁剑诀 `0.15` |
| `life` | 寿元上限 | 龟息延年诀 `+10`、补天真经 `+80`、太阴吐纳养轮经 `+60` |
| `heal` | 疗伤效率 | 长春功 `0.25`、续脉决 `0.30` |
| `fate` | 机缘 | 梅花易 `+6` |
| `mpCap` | 灵力上限 | 吞海功 `0.15` |
| `xianghuo` | 香火产出 | 香火成神法 `0.15` |
| `gapUp` | 位格压制抵消 | 乾天一元统摄诸天神法 `1` |
| `lifeStop` | 寿元无上限 | 太阴蜕形尸解真法 |
| `needEl` | 灵根门槛 | 紫霄雷法 `thunder`（原「需雷灵根」零 gating） |

**关键取舍**：文案里没写具体数值的功法（聚气诀/敛气诀/九寰天书/造化丹经等），一律按「无特殊」处理，**不编造数值**。宁可这 2 本没有专属机制，也不让 effect 表变成第二个空头支票。

审计结果：**45 本全覆盖，43 本有真实结算出口**（其余 2 本原文本就只写了功能描述）。

### 2. 施法接功法（同一文件 + `game.js` 一处缝口）

`sub === 'cast'` 分支原本的伤害公式里，`g` 只出现在 note 字符串中：

    const g = getGongfa();
    dmg = Math.round(c.foe.hpMax * Math.max(0.08, 0.22 * ratio) * mult * keK * (1 + artBonus('atk')));
    note = '施展《' + g.name + '》';   // g 只用在这里

现在多了 `castMul()` 三重乘区：

1. **品阶底子** `1.00 / 1.10 / 1.22 / 1.36 / 1.55`（黄→仙）。
   刻意把原本 `GONGFA_TIERS.mul` 的 `1.0→3.0` 压平——那套是月修为倍率，直接搬进战斗会让一本天阶功法顶掉整个战斗系统。
2. **effect.all / effect.dims**：只有该功法真的承诺过才乘。
3. **功法五行 × 招式五行**：同源 ×1.10、相生 ×1.05。

并把**来源链写进战斗日志**：`施展《天河剑诀》（地阶 ×1.22、功法 ×1.50、功法同源 ×1.10）`——伤害不再是黑箱。

端到端实测：聚气诀 522 → 百炼成仙道法 906（同敌人同境界）。

### 3. 常驻修正接线

原先硬编码在 `monthlyHeal` 里的 `changchun ×1.25` / `xumai ×1.3`（且续脉决「只要拥有就生效，不需装配」）改为由 `gongfaHeal()` 统一结算，**主修功法不同，回血速度不同**，「装配改变体验」第一次成立。

### 4. 灵根战斗出口（`wxcs3-ext-70-root.js`）

新增 `ROOT_POW` 表，给五种资质各自的 `pow`（质的系数）与 `concentration`（精的系数）：

| 灵根 | pow | concentration | 副系数 | 香火上限档 |
|---|---|---|---|---|
| 天灵根 | 1.12 | 1.10 | 0 | 2.60 |
| 变异灵根 | 1.06 | 1.08 | 0 | 2.45 |
| 地灵根 | 1.06 | 1.05 | 1 | 2.20 |
| 真灵根 | 1.02 | 1.00 | 2 | 1.90 |
| 伪灵根 | 0.96 | 0.92 | 3 | 1.70 |

`computePower()` 末尾乘 `rootPowerMul()`。端到端：同境界同功法，天灵根普攻 428 vs 伪灵根 352。

**香火上限五档还原**：原 `load >= 1.5 ? 2.5 : 2` 把五种灵根压成两档，现由 `xianghuoCapMul()` 给五档。

### 5. 多系真多系

`mainEl()` 仍是 `rootEls[0]`（不破坏道统/神通池语义），但战斗克制改为**在所有已选五行里取对敌最优**（`bestKe()`），且非主系按 `concentration` 折价。

效果是「**系多则宽、不挑对手**」而非「系多更强」：

- 主选 metal 打 wood 敌人 → 1.3（主系已够，副系不动）
- 主选 metal 打 fire 敌人 → 0.85（被克），此时第二系 water → 1.30 顶上来（按 0.92 折价）

这样伪灵根的四系从「状态栏彩色装饰」变成一种真实 build：打什么都有一点克制面，但每一系都不够狠。

### 6. UI：让改动看得见

- **功法面板**：道基功法详情新增「**实际结算**」一栏，把 effect 翻译成人话；功法列表每一项直接标出该功法真正的机制。
- **状态栏**：灵根区改为 `主系 | 副 xxx`，并显示 `战力 ×1.23 · 副系按专精度 0.92 折价`。

## 五、过程中真实修掉的 3 个 bug

这轮不是一次写对，以下三处是测试暴露后改的，记下来避免重犯：

1. **`maxXianghuo()` 引用外层 `G` 崩溃**
   `tools/test_econ.js` 用 `grab()` 从源码里**抠出孤立函数**在沙箱跑，那里没有闭包内的 `G`。
   修法：`const _X = (typeof G !== 'undefined') ? G.WXCS3_EXT : null;`，缺扩展时退回旧两档。
   **教训**：往「会被 grab 抽出来单测」的函数里加东西，不能依赖外层闭包变量。

2. **施法五行取错来源**
   最初 `sub === 'cast'` 传 `null` 当招式，导致 `dims` 永远拿不到 `sel`，专属五行加成永不生效。
   修法：无招式对象时，五行取**功法自身 el**（施法＝按主修功法的路子打出去）。

3. **五行键名写错**
   我按拼音写了 `jin/mu/shui`，实际 `ELEMENTS` 是 `metal/wood/water/fire/earth`，雷/风/冰/阴/阳另有 `MUT_ELEMENTS`。
   修法：加 `elName()` 同时查两张表。
