## 一、一句话总结

P0 不是「加新玩法」，是**把已经写进数据表、却没接进结算的承诺兑现掉**。
本轮之后：26 个双属神通名不再降级成单属；`foeBurn`/`foeSlow` 从「写了没人读」变成看得见、算得动的状态；
7 个死钩子全部找到消费位置；**14 本空头功法 14/14 产生可见数值变化**；剑系功法的 `dims['sword']` 不再空转。

顺带修掉两处会让玩家对不上账的问题（下详），以及上一轮瘦身留下的一个断测试。

## 二、P0 五项

### P0-1 神通双属复合生效（方案 S1）

| 项 | 内容 |
|---|---|
| 现状 | `shenTongSpec` 用 `k.charAt(0)` 取首字，`（命身）`的「身」完全失效；`do_cbt` 的 `if/else if` 链也只认 `k0 = sp.kind.charAt(0)` |
| 纠正方案误判 | 方案说「至少 6 种组合」「26 个带括号标注」。实测：26 个标注里 **22 个是单属标注**（只是把默认分类写明），真双属只有 **6 道、2 种组合** —— `命身`×5（位从险/往生泉/如重浊/洞泉声/洗劫露）、`命术`×1（顺平征） |
| 改法 | 新增 `stParts(k)` 把标注串拆成去重的类别数组；`shenTongSpec` 按 parts 聚合：倍率取 `max(各类) × 1.1`（封顶，避免 1.85+1.15 变成 ×3.0），消耗取「两类之和 × 0.7」，`kindName` 拼成「命身双属」，`desc` 拼接两段；`do_cbt` 改为遍历 `sp.parts` 逐个叠加效果 |
| 结果 | 《位从险（命身）》出手时**同时**结算「必中」与「自愈 12% + 护体」，菜单显示「命身双属 · −53 灵 · ×2.04」 |
| 护栏 | 双属倍率 ≤ 单属 ×1.12（实测 ×1.103）；双属消耗 > 单属（45 → 53） |

### P0-2 灼烧 / 迟滞结算 + UI（方案 S3）

| 项 | 内容 |
|---|---|
| 现状 | `foeBurn=2`、`foeBurnMul`、`foeSlow=2` 只在 `do_cbt` 的 cast 分支写入两行，**全项目 0 处读取**——烈火掌、流火剑诀、冰魄诀承诺的「灼烧／缓其行」是空头支票 |
| 改法 | ① `foeTurn` 开头结算灼烧（`burnTickOf(c)` 统一口径），烧死敌人走同一段胜利结算；② 迟滞在敌方伤害公式里乘 0.85 并递减；③ 战斗面板补两条状态标签 |
| 关键取舍 | **点火当回合不落伤**（`burnFresh` 标记，下回合起烧）。否则「灼烧 2 回合」实际只在点火后烧 1 次，玩家看到 2 却只烧 1，名实不符。现在「2 回合」精确烧 2 次（已有断言守住） |
| 单一口径 | 新增 `burnTickOf(c)`，面板与结算都读它。修前 UI 按 4%、结算按 4.5%，同一状态给出两个数字——已统一为 4.5% |

### P0-3 功法 7 个死钩子接线（方案 3.1）

| 钩子 | 功法 | 消费位置 | 端到端证据（实测） |
|---|---|---|---|
| `gongfaWard` | 金光咒/金殿煌元诀/九变化龙诀/明华煌元经/白首叩庭经 | `deflectOf(c,'me')` | 同一刀受击 −11.8% / −14.1% / −9.4% / −7.1% / −5.9% |
| `gongfaMpCap` | 吞海功 | 新增 `syncMpCap()`，换功法/月初/读档三处对齐 | 灵力上限 100 → 115，换回聚气回落 100 |
| `gongfaLifeBonus` | 龟息延年诀/补天真经/太阴吐纳养轮经 | 新增 `syncLifeBonus()`（同上三处） | 200 → 210 / 280 / 260 |
| `gongfaLifeStop` | 太阴蜕形尸解真法 | 月初寿元判定（month===1 分支） | 寿元到限改为「护一次」：上限续至 231、修为折半；`lifeStopUsed` 保证只挡一次 |
| `gongfaFate` | 梅花易 | 奇遇 `encRate`、交涉判定、遁走 | 奇遇率 18% → 24% |
| `gongfaXianghuo` | 香火成神法 | `monthXianghuo` 回报侧（不动 cap） | 月香火 ×1.15 |
| `gongfaGapUp` | 乾天一元统摄诸天神法 | `do_cbt` 开头压 gap | 越两境伤害 ×1.67 |

**接线纪律**：`mpMax` 与 `lifeMax` 是缓存字段（受箓 ×1.5、丹药、破境重设都会改它），所以不能每次重算。
采用「记住上次应用的乘区（`mpGfMul` / `lifeGfBonus`），乘区变了就按差额换算」——受箓的加成不会被功法重算抹掉，破境重设 `lifeMax` 时也不会丢。

### P0-4 剑系命名空间空转修复（方案 3.4）

三处独立的 bug，合起来让「剑系功法」整条线白给：

| # | bug | 后果 | 修法 |
|---|---|---|---|
| 1 | `dims` 里写 `{sword:1.40}`，而 `skillElOf` 解析出的是五行 `metal` | 玄元剑经/太虚剑典/月阙剑典/天河剑诀/天遁剑诀的剑系加成**全部命中不了** | 编译期 `aliasDims()` 给类别键补五行别名，只补原本没有的键（执金秘章的 sword 1.25 与 metal 1.15 各自保留） |
| 2 | `if (g.el === sel)` 在施法（`sk=null`）时恒真——`skillElOf(null)` 回的正是 `g.el` | **每次施法白拿 ×1.10** | 同源判定加 `&& sk`，只在招式自己有五行时成立 |
| 3 | `dims:{all:1.06}` 把顶层字段塞进五行键位 | 天语焜烨龙章的威压从未生效 | 改为顶层 `all: 1.06` |

另加一个新出口 `EXT.gongfaSkillMul(sk)`：**招式侧从此也吃功法**。旧版只有「施法」分支接功法，
而玩家 90% 的输出走「招式」——玄元剑经的「剑系 +40%」在剑气纵横上一点作用都没有。
招式侧品阶只给一半权重（`1+(tm-1)*0.5`），避免一本天阶直接盖掉招式之间的取舍。

**验收（实测）**：玄元剑经放剑气纵横 967084 → 1502849；换焚山掌时剑经相对加成明显更小（×1.11 vs ×1.55）。

### P0-5 `test_tier2.js` 从探针自检改为真实路径断言

原第 4 节只验 `EXT.gongfaXxx() === n`——这只证明「数据表编译对了」，不证明「游戏读了它」。
**这正是 14 本功法空转多年没被发现的根本原因。** 新增 `4b` 段，每条都走玩家真会走的那条路：

- 换功法 → `S.mpMax` / `S.lifeMax` 真的变（且换回会回落，不是一次性白送）
- 同一敌人同一随机种子 → 金光咒真的少挨打
- 越阶 → 乾天一元真的打得动
- 寿元到限 → 尸解真的挡一次；无此功法时照常终局（对照组）

`test_tier2` 断言数 45 → 61。

## 三、顺手修的两个「对不上账」

### 3.1 灼烧标签与结算数字不一致

修前：UI 按 `0.04`、结算按 `0.045`，同一状态面板写 18 万、实际掉 20.25 万。
玩家看到两个数字对不上，会先怀疑游戏坏了。已抽 `burnTickOf(c)` 单一真源。

### 3.2 状态标签在括号中间断行

截图实测：`破绽 · 我方伤害 ×1.25（1 回合）` 被拆成「（1 回」+「合）」，读起来像两个数。
标签是 `inline-block`，容器一窄中文就在任意字间断开。给括号与数字套 `nowrap` 片段。

### 3.3 上一轮瘦身留下的断测试（v10.3 P1 遗留）

`v10.3 P1` 把 `ACT.do_selldan` / `ACT.do_selltal` 当死代码删了，但 `tools/smoke_econ.js` 第 8 节仍在调用。
**README 记「913 全绿」，实际 smoke_econ 在第 8 节崩掉，32 项只跑了 23 项 → 真实基线是 904。**
已恢复这两个一行转发（面板走 `do_sellitem`，别名给脚本与扩展一个稳定入口）。

## 七、风险与后续

1. **数值手感待实机调**：灼烧取 4.5%/回合、双属 1.1 封顶、ward 5%~12%，都落在方案护栏内，但「打起来爽不爽」要真玩几场才知道。已留的单点都在一个函数里，改动成本低。
2. **尸解的方向性决定**：现在写成「护一次 + 续 30 年 + 修为折半」，不是永久免死。若后续觉得仙阶功法太弱，可考虑改成「每境界限一次」，但不要改成永久——那会让寿元这条线整条失效。
3. **招式侧的品阶权重是拍的 0.5**：这是本轮唯一没有方案依据的数字（方案只说招式该吃功法，没给系数）。若发现「换天阶立刻压过一切招式取舍」，把它调到 0.35 或 0.3。
4. **P1 起点**：道统气质表（S2）是 P1 第一项，落地位置已在方案里指明（`shenTongSpec` 读 `S.daotong`），本轮已把 `sp.parts` 结构准备好，接气质时不用再动双属逻辑。
