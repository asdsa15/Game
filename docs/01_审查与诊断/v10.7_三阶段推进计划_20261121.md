# 问道长生 v10.7 · 三阶段推进计划

> 日期：2026-11-21
> 基线：`v10.7_界面战斗与本命外物优化方案_20261120.md`（下称「方案」）
> 性质：**执行计划文档。** 方案给出四个批次（批次 A/B/C/D），本计划按用户要求把它们收敛为**三个进度阶段**，并写清每阶段的范围、验收口径与边界。

---

## 一、为什么是三阶段而不是四批次

方案第九节列的是四个**批次**（A 布局与口径 / B 破境与本命 / C 战斗决策层 / D 符丹扩充与平衡）。批次是实施单元，阶段是**交付进度**——玩家和策划能对每一阶段说「这一轮结束后多了什么」。

合并原则：**C 与 D 必须同批交付**，因为 D 的 12 战斗符、8 新丹与 14 个配方，其战术意义要靠 C 建立的「敌方意图 / 蓄力 / 调息 / 状态生命周期」才能被玩家读懂。单独交付 D 只会得到「多了一堆道具，但没有可读的决策」。

| 阶段 | 对应方案批次 | 一句话交付物 | 风险等级 |
|---|---|---|---|
| **阶段一** | 批次 A | **入口归位 + 战斗口径说人话**：左导航替代底部功能坞，符箓与减伤的真实结算对齐文案，敌我状态归位 | 低（不改业务状态） |
| **阶段二** | 批次 B | **本命归位 + 破境不丢**：筑基锻造本命，普通法器彻底解除认主，破境手续改成可靠 FIFO | 中高（动存档结构） |
| **阶段三** | 批次 C + D | **战斗有决策 + 丹符成体系**：敌方意图/蓄力/调息/术法结构化效果，12 战斗符 + 8 新丹 + 14 配方与平衡 | 高（动数值与经济） |

## 二、阶段一：布局迁移与战斗口径修复（对应批次 A）

### 2.1 范围

**做**：

1. **桌面布局迁移**
   - 取消页面底部通栏功能坞，改为**左侧常驻全功能导航**。
   - 一级功能直接显示，不再需要先点「修炼 / 经营 / 人事 / 更多」再找功能。
   - 纪事从左栏移到**中栏主行动之后**（近期 7 条 + 本月收支摘要），完整纪事仍走年谱面板。
   - 右栏**吸顶**（`position: sticky`），超高内容在右栏内部滚动；中栏保持文档流。
2. **移动端策略**
   - 不把桌面左栏硬压成窄缝；收为**五项常驻底栏**：修行 / 外物 / 出行 / 人事 / 更多。
   - 要务（有人来访、限时急事、拍卖会、待清人情、锚定危险）在底栏以红点提示。
3. **符箓与外物口径修复**（文案 / 结算 / 使用时机三者对齐）
   - 增益符：三回合内直接伤害 +30%，刷新不叠层，普攻 / 术法 / 符箓 / 神通 / 施法五条伤害路径口径一致。
   - 金刚符：下一次受击**总**减伤 60%，与守势取强，不再叠乘出 95%。
   - 五雷符：伤害 +80% 且无视卸力，命中普攻与术法首击。
   - 传音符：改为占一旬的**平时外物**（好感 +5），从战前菜单移出。
   - 拘仙敕神符：当场生效于本场战斗，不再被战前结算提前读走。
4. **敌我状态归位**
   - 破绽 / 压制 / 灼烧 / 迟滞 移回**敌方卡**；守势 / 增益 / 护体 / 净化留在**我方卡**。

**不做**（本阶段边界）：

- 不改任何业务状态机：破境、修炼、经济、结局判定一律不动。
- 不新增术法效果、不新增敌方行为、不新增丹符配方。
- 不重建战斗引擎，不另建第二套状态系统——只把**已有**结算算对、算到文案上。
- 不重做视觉风格：保留 v10.2 已落地的右栏分组、异常置顶、焦点管理、对比度、移动端安全区。

### 2.2 验收

| 项 | 口径 |
|---|---|
| 入口零丢失 | 原 `dockItems()` 每个有效入口都能在左导航/底栏找到；`check_actions` 无孤儿动作、无死按钮 |
| 分组不重不漏 | `navGroups()` 分组后条目数 = `dockItems()` 条目数，无重复、无落「其他」兜底 |
| 要务置顶 | 有访客时访客在要务组首位；事件消失后不保留空位 |
| 战斗口径 | 五类符箓的**实际结算值**与面板文案逐条一致（新增专项断言） |
| 敌我归位 | 敌方卡只出现敌方状态，我方卡只出现我方状态 |
| 静态检查 | `check_actions` / `check_time` / `check_ach` 三项全过，未分类动作 0 |
| 回归 | 全部 `tools/test_*.js` 0 失败 |
| 视口 | 1600×1200 / 1366×768 / 1280×720 / 1024×768 / 390×844 无横向溢出、无遮挡、按钮可达 |

### 2.3 阶段一产出

## 三、阶段二：破境队列与本命锻造（对应批次 B）

### 3.1 范围

1. **破境手续改 FIFO**
   - 把「仙基 → 本命锻造 → 道印 → 神通/命格」拆成真正的顺序队列，每步只 `shift()` 当前项，完成后统一续接 `do;afterbreak`。
   - 修 `do_yin` 选完道印就 `closeModal()` 不再续接的问题——这是加锻造步骤的前置任务。
   - 每一步都能读档继续；重复点击不重复发奖、不生成第二件本命。
2. **本命独立化**
   - 新增静态 `NATAL_FORMS`（飞剑 / 法印 / 宝镜 / 神钟 / 魂幡五种器形），各自被动与法技行为不同。
   - 首次仙道筑基成功（`xRealm=1 → 2`）进入强制锻造仪式：择器形 → 择主五行 → 正名 → 预览法技。
   - 仪式**提供基础器胚**：不检查炼器等级、不额外占旬、不再掷成功率（玩家已经通过筑基判定，不能因未学炼器被卡死）。
   - 本命不再进 `S.arts`、不占普通装备槽、不可出售；普通法器加成只由 `artBonus()` 算一遍。
3. **普通法器解除认主**
   - `wxcs3-ext-40-benming.js` 删除「从 `S.arts` 选法器认主」的入口。
   - 九转飞剑、万灵幡、青叶舟、太阴宝鉴等继续作为普通法器购买 / 炼制 / 装备，但文案删除「可为本命」。
   - 删除「同一件普通法器 bonus 再算一遍」的双倍机制。
4. **旧档迁移**（一次性、幂等、可重复读档验证）
   - 旧 `S.benming.artId` → 按物映射器形，保留自定义名、四阶、祭炼经验、器损，生成 `ver:2` 独立本命。
   - 原普通法器仍在 `S.arts` 与装备槽，但只提供普通加成。
   - 已是筑基及以上、却从未有本命的仙道旧档，提供一次「补铸本命」入口（不伪造破境、不重复发其他破境奖励）。
   - 新档未筑基时，本命面板只显示「筑基时可铸」，不显示普通法器候选。

### 3.2 验收

- 练气期买九转飞剑只得到普通法器，`S.benming` 仍为空，任何入口都不能认主。
- 首次筑基必定出现锻造选择；不依赖炼器等级、不随机失败、不卡死后续仙基/道印/神通/命格。
- 五种器形的被动与法技确实不同；普通法器 bonus 不翻倍。
- 破境手续每一步读档都能继续；重复点锻造不生成两件本命、不重复扣料。
- 旧本命迁移保留培养、原普通物品仍在；迁移执行两次结果完全一致。
- 筑基以上无本命旧档可补铸；纯神道角色不被强制转仙道。

### 3.3 阶段二产出（预期）

- `wxcs3-data.js`：`NATAL_FORMS`。
- `wxcs3-ext-40-benming.js`：删除普通认主，改为独立本命祭炼 / 法技 / 器损 / 合道。
- `wxcs3-game.js`：破境 FIFO 队列、锻造仪式、`applyState` 迁移段。
- `tools/test_v107_natal.js`：锻造、五器形、破境队列、旧档迁移。

## 四、阶段三：战斗决策层 + 丹符扩充与平衡（对应批次 C + D）

### 4.1 范围

**战斗决策层（批次 C）**

1. **术法结构化效果**：`SKILLS` 增加 `effects`，由统一解释器处理；`skill` 分支不再只按名称和倍率出伤。
   第一批兑现：焚山掌（伤害 + 灼烧）、缠木根（伤害 + 压制）、毒火丝（伤害 + 中毒 3 回合）、镇压八方（打断蓄力）、流转剑罡（伤害 + 本次守势）、落石诀（伤害 + 破甲 2 回合）、白骨飞剑（改为器损 / 耗灵代价）、惊雷引 / 神霄御剑（必中 + 部分无视卸力）。
2. **状态统一生命周期**：在现有 `S.combat` 上建立四个唯一入口——`applyCombatEffect` / `tickCombatEffects` / `consumeCombatEffect` / `renderCombatEffects`。
   同名状态刷新不叠层；不同来源取最高；持续伤害致死必须进 `settleCombatWin()`；控制失效 / 刷新 / 被净化都写日志。
3. **敌方路数与意图**：剑修 / 法修 / 体修 / 诡修四条路数，每条 3~4 个行动；固定时序「选意图 → 玩家应对 → 敌方执行该意图 → 结算状态 → 选下一意图」。
   「蓄力」跨一回合，玩家有真实反制窗口；硬控后给 2 回合「定神」，防连控。
4. **新增「调息」**：恢复 `max(20, mpMax × 12%)` 灵力，不造成伤害、不附带守势，敌方仍执行本回合意图，可清一层自身迟滞。
5. **首批可读联动**：雷火引爆余焰、压制换资源窗口、蓄力可被镇压/雷符打断、护体意图先破防再爆发。
6. **战利品接入四艺**：按路数掉铁木心 / 金灵砂 / 符纸 / 朱砂 / 合神花等材料（约 45% 一份材料、约 12% 一张基础丹符），防止战斗刷材料全面取代历练与采集。

**符丹扩充与平衡（批次 D）**

1. **符箓统一**：`TALISMANS` 成为唯一符箓配置表，`S.talismans` 成为唯一符箓库存。
   火云符 / 传音符 / 五雷符 / 祈雨符箓 / 拘仙敕神符从一次性法器迁入符箓体系；破宝锥仍是法器。
   每种符增加 `use:'combat'|'preCombat'|'outCombat'` 与结构化 `effect`。
2. **12 种战斗符**：火符 / 金刚符 / 遁符 / 增益符 / 雷符 / 冰封符 / 缚灵符 / 破甲符 / 净符 / 聚灵符 / 神行符 / 雷火符，每一种都有真实效果、配方、来源、图标、日志。
3. **8 种新丹**：护脉丹 / 清神丹 / 解毒丹 / 烈元丹 / 生生丹 / 归元丹 / 开脉丹 / 悟心丹。
4. **补 14 个配方**：8 新丹方 + 6 个现有高需求方（疗伤药 / 接骨膏 / 复原丹 / 回灵散 / 小破障丹 / 筑基丹）。
5. **外物使用节奏**：丹药每场最多 2 次且不可连续两回合；同种符用后冷却 1 回合；器物弹窗按「攻 / 防 / 控 / 助 / 丹」分类，去掉 `slice(0,6)` 造成的「持有却不可达」。
6. **数值平衡**：跑战斗模拟 / 经济模拟 / 全量回归后再调数值；普通胜场目标中位数 4~7 回合，寻仇 6~10 回合。

### 4.2 验收

- 每个新术法效果都通过**真实 `skill` UI 路径**触发（不能用无可见入口的 `cast` 代替验收），状态数值、持续回合、日志一致。
- 敌方面板展示的意图与实际执行一致；保存 / 读档后意图不重新随机。
- 蓄力能被指定手段打断；定神期间不能无限硬控；持续伤害致死正常发奖励。
- 调息回灵准确，敌方仍行动；灵力不超过上限，气血和库存不为负。
- 12 种战斗符、8 种新丹均有真实效果、库存、来源、配方、图标、日志与测试；持有超过六种时最后一种仍可在分类菜单使用。
- 新掉落不破坏月账与无套利规则；所有新增配方材料可达；成功 / 失败 / 重复制作 / 材料不足都只结算一次。

### 4.3 阶段三产出（预期）

- `wxcs3-data.js`：术法 `effects`、敌方行动模板、`NATAL_FORMS` 后续、`TALISMANS` 12 种、新丹与 14 配方。
- `wxcs3-game.js`：状态生命周期四入口、意图 / 蓄力 / 调息、符丹使用节奏、掉落。
- `tools/test_v107_combat.js`、`tools/test_v107_consumables.js`；扩充 `tools/sim_combat.js`。

## 五、三阶段的共同底线

1. **不另建第二套战斗引擎，不另建第二套本命库存。** 修复集中在公共结算与配置入口，不在多个下游动作里各复制一份规则。
2. **每个新效果必须六件套齐全**：真实结算、正确的状态归属、日志、获取来源、旧档兼容、玩家主路径测试。缺一件就不算落地。
3. **验收走玩家可见路径。** 测试不得用内部探针代替真实 UI 入口。
4. **数值改动必须过模拟。** 战斗模拟、经济模拟、全量回归三项跑完再调数，不能靠手感改常数。
5. **每阶段独立提交、独立可回滚。** 阶段之间不交叉改动同一功能面，避免回滚时互相牵连。
6. **旧档兼容是硬约束。** 每次涉及 `S` 结构的改动都要有幂等迁移段，且迁移执行两次结果完全一致。
