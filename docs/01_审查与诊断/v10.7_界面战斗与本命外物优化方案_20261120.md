# 问道长生 v10.7 · 界面、战斗与本命外物优化方案

> 日期：2026-11-20  
> 基线：v10.6 当前源码  
> 性质：**审查与设计方案，尚未实施。** 本文不包含任何业务代码、配置、存档或发布产物改动。  
> 范围：桌面/移动布局、回合战斗、本命法宝、普通法器、符箓、丹药及其获取链。  
> 行号说明：以下行号仅用于定位本次审查快照；实施时应以函数名、表名和字段名为准。

---

## 一、结论与本轮决策

当前问题不是简单的“按钮太少”或“物品数量不够”，而是四件事：

1. **功能入口的位置错了**：桌面三栏之下再放一个通栏指令坞，功能被压到页面下方；左右栏高度不同，指令坞又必须等最高一栏结束，于是出现“下面找不到、左右又空着”的反差。
2. **战斗的有效决策少**：已有攻、术、御、器、遁、谋和若干扩展动作，但多数敌人每回合只做同一种直接攻击；不少术法只是倍率不同，部分文案承诺没有进入玩家实际使用的 `skill` 路径。
3. **本命的来源与语义错了**：当前是“先买/炼普通法器，再认主”，九转飞剑甚至直接写在坊市货架上。要改为：**普通法器永远只是外物；本命只在首次筑基时亲手锻造，不占商店、不进普通法器库存。**
4. **丹符不是没有数据，而是战术种类和产出链不足**：丹药有 19 种，但战斗中主要只显示恢复类，炼丹配方仅 5 个；制符产物只有 5 种，另有 6 种一次性法器，其中 5 种符类与制符产物分属两套库存，使用时机和效果口径也不统一。

本轮直接作以下产品决策，不再保留多套平行解释：

- 桌面端取消底部通栏功能坞，改为**左侧常驻全功能导航**；纪事移到中栏主操作之后，右栏继续承担状态与告警。
- 战斗保持“一次玩家行动、一次敌方行动”的轻量文字回合制，**不改动作游戏、不抽卡、不引入灵气牌组**。
- 新增敌方意图、少量有行为差异的敌人模板和“调息”，先让已有术法、符丹、本命、灵兽真正形成配合。
- 本命在**首次由练气成功晋入筑基后**进入强制锻造仪式；不再允许从 `S.arts` 选择任意法器认主。
- 符箓第一批形成 12 种战斗符，丹药新增 8 种战术/修炼丹，并同步补配方和来源，不做只有名字的伪扩充。
- 所有新效果必须同时有：**真实结算、正确归属的状态标签、日志、获取来源、旧档兼容、玩家主路径测试。**

## 二、现状审查：以当前代码为准

### 2.1 布局与入口

当前 `render()` 在 `wxcs3-game.js:1260-1264` 固定输出：

```text
左栏：天时、月账、纪事
中栏：场景、境界、目标、五项主操作、自由输入、能力摘要
右栏：异常、生存、修为、资源、关系
下方通栏：常用入口 + 修炼/经营/人事/更多折叠组
```

关键证据：

- `问道长生v6.html:83-98`：三栏为 `272px / minmax(0,1fr) / 312px`，各栏 `align-self:start`。
- `问道长生v6.html:373-386`：`.dockrow` 横跨全部列，是 Grid 的下一行。
- `wxcs3-game.js:1795-1902`：`dockItems()` 仍承载功法、四艺、坊市、法宝、宗门、乾坤袋、本命等大量核心入口。
- `wxcs3-game.js:1914-1937`：非“常用”入口仍需先展开分组，再点功能。

因此，左右空白不是缺一张装饰卡，而是**三栏不等高 + 功能坞另起一行**的结构性结果。继续往空白处塞常驻数字，只会增加信息噪声，不能解决入口过深。

需要保留的既有改进：右栏分组、异常置顶、中栏关键状态快照、弹窗吸顶标题、焦点管理、对比度、数值变化反馈和移动端安全区。此次是调整信息架构，不是推翻 v10.2 的全部界面工作。

### 2.2 战斗

当前主操作已有六类，见 `renderCombat()`：

- 攻：必中普攻；
- 术：术法与神通；
- 御：本回合守势；
- 器：符箓、丹药、神道权柄；
- 遁：概率撤退；
- 谋：观察、交涉、虚张声势；
- 扩展另有本命法技、灵兽指令和战前准备。

真正的问题在结算层：

| 问题 | 当前代码证据 | 玩家感受 |
|---|---|---|
| 敌方行为单一 | `foeTurn()` 除滑头低血逃跑外，基本始终走同一段直接伤害 | 每回合只是换血，无法针对下一招 |
| 敌人没有招式模板 | `startCombat()` 内联生成通用敌人，主要是名字、性格、五行、战力差异 | 敌名不同，打法相同 |
| 术法承诺未完整兑现 | `SKILLS` 写有缠木减半、毒火三回合、镇压不能攻、剑罡攻守等；`do_cbt('skill')` 主要只特判血炼和雷 | 菜单写得丰富，实际多为不同倍率的伤害 |
| 状态效果断链 | `gongfaSpellStatus()` 在 `cast` 分支调用，而可见术法菜单发出的是 `skill` | 测试能走通的效果，玩家主路径未必能触发 |
| 状态归属混乱 | `foeMark/foeBurn/foeSlow` 等作用于敌方，却集中渲染在我方卡的状态区 | 很难一眼判断谁中了什么 |
| 外物口径不稳定 | 增益符写三回合，实际本场累加且只直接增幅普攻；金刚符与守势叠加后实际约减伤 95% | 文案无法用于决策 |
| 战利品不支持构筑 | `settleCombatWin()` 主要给灵石、声望、修为/香火 | 战斗与炼丹、制符、炼器缺乏产出联动 |

所以，“加更多攻击按钮”不会解决问题。应先让**不同动作改变下一回合的局势**。

### 2.3 本命与普通法器

当前真实链路是：

```text
ARTIFACT_EXT 全部进入 SHOP
→ 购买后进入 S.arts
→ 本命面板筛选所有 slot !== 'once' 的法器
→ bm_pick 写入 S.benming={artId,...}
→ artBonus 对本命对应普通法器再加一次 bonus
```

具体事实：

- `wxcs3-data.js:349`：九转飞剑标价 3200，文案写“可为本命”。
- `wxcs3-data.js:2074-2078`：`ARTIFACT_EXT` 全量拼入坊市。
- `wxcs3-ext-40-benming.js:218-301`：可从已有普通法器中认主，并非只能选九转飞剑。
- 同文件 `:53-62`：本命加持实质是普通法器 bonus 再算一遍。
- 筑基成功队列 `wxcs3-game.js:3300-3308` 当前只有仙基、道印、神通、命格，没有锻造本命。
- 普通九转炼器配方要求地阶、炼器 5 品，且受紫府境界门槛限制，不能直接拿来做筑基仪式。

另有一个必须先修的队列风险：`ACT.do_yin` 当前选完道印后直接 `closeModal(); advanceXun(1); render()`，没有继续 `do;afterbreak`。新增锻造步骤前，应先把破境手续改成可靠的顺序队列，避免“锻造做完，后续命格/神通丢失”。

### 2.4 符箓与丹药

#### 符箓

- `TALISMANS` 只有火符、金刚符、遁符、增益符、雷符 5 种，全部靠制符产出。
- `ARTIFACT_EXT` 另有破宝锥、火云符、传音符、五雷符、祈雨符箓、拘仙敕神符 6 种一次性物品。
- 两套物品分别进入 `S.talismans` 与 `S.arts`，战中与战前入口也不同。
- 五雷符文案的“伤害 +80%”没有完整兑现；传音符在战前使用会被消耗但没有对应效果分支；拘仙敕神符存在本场/下一场读取时机错位。

#### 丹药

- `PILL_EXT` 共 19 种，数量并非个位数。
- 战斗菜单只列 `hp/hpPct/hpFull/cure/mp/mpPct/mpFull`，本质仍是回血、回灵、疗伤。
- `RECIPES` 只有回春丹、聚气丹、清心丹、生肌续骨丹、玉华灵水 5 个炼丹配方。
- 战中丹药目前没有一场次数限制，`usedPill` 只用于“未服丹获胜”统计，不参与禁用判断。

因此目标应是“**增加效果轴与制作可得性**”，不是把五种回血丹再换十个名字。

## 四、前端布局改造

### 4.1 目标结构

桌面端改为“**左导航 / 中行事与纪事 / 右状态**”，不再保留页面底部通栏功能坞。

```text
┌──────────────────────── 顶栏：道号 / 时间 / 系统 ────────────────────────┐
│ 左侧常驻导航       │ 中栏：场景与当前目标              │ 右栏：异常告警     │
│ ─ 修行             │ 境界与关键资源快照                │ 生存 / 修为        │
│  功法 四艺 道书     │ 场景插画、地点文本、旬数           │ 资源 / 关系        │
│  构筑 命格 道果     │ 当前五项主行动                     │                    │
│ ─ 外物             │ 自由输入                           │ 吸顶，内部滚动     │
│  乾坤袋 法宝 本命   │ 道基 / 术法 / 神通摘要             │                    │
│  灵兽 神器 愿物     │ ─ 近期纪事（5~8条，展开看全部）    │                    │
│ ─ 经营             │ ─ 本月收支摘要                     │                    │
│  洞府 家族 宗门     │                                    │                    │
│ ─ 人事             │                                    │                    │
│  情缘 人情 门下     │                                    │                    │
│ ─ 出行             │                                    │                    │
│  历练 舆图 坊市     │                                    │                    │
│  拍卖 遗迹 洞天     │                                    │                    │
└──────────────────────────────────────────────────────────────────────────┘
```

### 4.2 左侧导航规则

1. **一级功能直接显示，不再默认折叠。** 组名只负责分类，不需要先点“修炼/经营”再找功能。
2. 保留 `dockItems()` 作为入口真源，先改展示容器，不重写各面板 ACT。新增 `navItems()` 只负责分组和排序，避免同一功能在多处各维护一份动作名。
3. 紧急事项独立置顶：有人来访、限时急事、拍卖会、待清人情、锚定危险。紧急项消失后不保留空位。
4. “未解锁”不展示空入口；已解锁功能不能因为换道途而无提示消失。
5. 本命与法宝分开：法宝进入普通装备面板，本命进入独立锻造/祭炼面板。
6. 所有入口继续使用统一 `data-act` 委托和 `enhanceA11y()`，键盘焦点、ESC、弹窗滚动锁不能回退。

建议六组映射：

| 分组 | 入口 |
|---|---|
| 修行 | 功法、四艺、道书、构筑、命格、道果、化道胎 |
| 外物 | 乾坤袋、法宝、本命、灵兽、神器、愿物 |
| 经营 | 洞府/庙宇、家族、宗门、道统 |
| 人事 | 情缘、人情、门下 |
| 出行 | 历练/显圣、舆图、坊市/庙市、拍卖、遗迹、洞天 |
| 记录 | 年谱、功过格、账本；存档与设置仍留顶栏系统菜单 |

### 4.3 中栏与右栏

- 中栏只保留当前可做的事、目标和最近反馈，不把所有系统面板塞进首页。
- 近期纪事从左侧移到主行动之后，默认 5~8 条；“查看全部”复用年谱/纪事面板。
- 月账保留摘要，完整明细仍走现有账本面板。
- 右栏沿用异常、生存、修为、资源、关系五组；宽屏吸顶，超高内容在右栏内部滚动。
- 左右栏可采用 `position:sticky; top:...; max-height:calc(100dvh - ...)`，中栏随页面滚动。这样左右空间用于持续呈现导航与状态，而不是靠假卡片填满。
- 不做三栏各自独立页面滚动：桌面只让导航和状态的超高内容内部滚动，中栏保持文档流。

### 4.4 响应式策略

| 宽度 | 布局 |
|---|---|
| ≥1200px | 三栏：约 232px / 弹性中栏 / 300px；最大内容宽度可提升至 1560px |
| 880~1199px | 左导航 + 中栏；关键状态仍在中栏顶部，完整状态通过明确的“状态”侧栏入口打开 |
| <880px | 单列；主行动优先，底部五项移动导航打开对应功能清单；纪事和完整状态后置 |
| <360px | 战斗操作保持两列，文字缩短但不隐藏遁走和关键资源 |

移动端不是把桌面左栏硬压缩，而是将六组收为“修行 / 外物 / 出行 / 人事 / 更多”五个常驻导航项；当前主行动与气血、灵力、寿元摘要无需进入菜单即可看到。

### 4.5 战斗界面同步调整

```text
敌方卡：姓名 / 境界 / 气血 / 敌方状态
【下回合意图：蓄力·离火剑——预计重击；可用雷符、镇压或守势应对】

我方卡：气血 / 灵力 / 道基 / 法宝 / 我方状态

行动区：攻 / 术 / 御 / 息 / 器 / 谋 / 遁 / 扩展动作
战况：最近 4 条，可展开本场完整记录
```

- 敌方的破绽、灼烧、迟滞、压制移回敌方卡；我方的守势、增益、护体、净化留在我方卡。
- 意图是行动区附近最醒目的信息，不藏在“观察”弹窗里。
- 普攻和术法显示的是同一伤害口径的预计区间；位格、卸力、克制等修正可展开查看。
- 扩展动作仍走 `fightRowsHooks`，但放入固定区域，避免本命、灵兽按钮无限制向下追加。

## 五、战斗系统改造

### 5.1 第一原则：先兑现已有术法

为 `SKILLS` 增加结构化 `effects`，由统一解释器处理；`skill` 分支不再只按名称和倍率出伤。

建议效果类型控制在首版可维护范围：

```text
damage       直接伤害
burn         持续灼烧
poison       持续中毒
weaken       敌方造成伤害下降
shred        敌方受到伤害上升
slow         迟滞
stun         跳过一次可被打断的敌方行动
guard        本方守势/护盾
cleanse      清除本方负面
restoreMp    恢复灵力
```

第一批至少兑现：

| 术法 | 目标效果 |
|---|---|
| 焚山掌 | 直接伤害 + 灼烧 2 回合，刷新不叠层 |
| 缠木根 | 直接伤害 + 压制 1 回合；文案与实际倍率一致 |
| 毒火丝 | 较低直接伤害 + 中毒 3 回合，持续伤害统一走胜利出口 |
| 镇压八方 | 打断蓄力；非蓄力时使下一普通攻击失效，同一敌人短时间内不能反复硬控 |
| 流转剑罡 | 直接伤害 + 本次守势，攻守同时生效 |
| 落石诀 | 附加破甲 2 回合，而不是只有“破其防”文案 |
| 白骨飞剑 | 高倍率但有明确代价；若保留“命中偏难”就必须真做命中，否则改为器损/灵力代价并更新文案 |
| 惊雷引、神霄御剑 | 必中、部分无视卸力、对蓄力目标有打断价值 |

测试必须走玩家可见的 `ACT.openSkills → do;cbt:skill` 路径，不能再用无可见入口的 `cast` 代替术法验收。`cast` 若保留为自由施法，应明确其与术法的职责；否则在本轮完成迁移后移除重复入口。

### 5.2 状态统一生命周期

不建议一次性重写全部战斗字段，先在现有 `S.combat` 上建立四个唯一入口：

- `applyCombatEffect(side, effect)`：写入、刷新、叠层与免疫；
- `tickCombatEffects(side, timing)`：回合开始/结束递减和持续伤害；
- `consumeCombatEffect(side, id)`：一次性效果消费；
- `renderCombatEffects(side)`：按归属渲染标签。

统一规则：

1. 同名状态默认“刷新持续时间，不叠加倍率”；不同来源只取最高值，特殊叠层必须单独声明。
2. UI 显示真实剩余回合/次数，禁止另算一套估算值。
3. 持续伤害若致死，必须进入 `settleCombatWin()`。
4. 控制失效、刷新、被净化都要写日志。
5. 普通减伤采用明确上限；同类减伤默认取最强，不做守势 × 符 × 法器无限乘算。
6. 金刚符改为“下一次受击总减伤 60%”，与守势同时存在时取较强的 60%，不再出现实际约 95% 的隐式结果。
7. 增益符改为“三回合内玩家直接伤害 +30%”，普攻、术法、符箓口径一致；刷新而非无限累加。

### 5.3 敌方意图与行动模板

保留现有四种性格作为数值和撤退倾向，再增加轻量“战斗路数”。性格不再代替招式。

首版四种路数：

| 路数 | 行动池 | 玩家应对 |
|---|---|---|
| 剑修 | 普攻、蓄力重剑、连击、低血强攻 | 蓄力时镇压/雷符打断，或守势、护体 |
| 法修 | 五行术、灼烧/迟滞、聚气、高耗灵大招 | 观察属性，净化负面，抓住聚气空档输出 |
| 体修 | 普攻、护体、蓄势、反击 | 破甲后再爆发，避免在反击意图下盲目普攻 |
| 诡修 | 毒、锁灵、虚张、低血撤退 | 净符/解毒丹、锁灵阵、快速压血 |

每个模板首版只需 3~4 个行动，不建设复杂 AI。行动结构包含：

```text
id / 名称 / 类型 / 权重 / 条件 / 冷却 / 伤害或效果 / 是否可打断 / 意图文本
```

固定时序：

```text
创建战斗 → 选择并保存首个意图
→ 玩家看到意图并行动
→ 敌方执行该意图（禁止临时重摇）
→ 结算持续状态、冷却和回合数
→ 选择并保存下一意图
```

“蓄力”必须跨一回合：第一回合只展示和蓄势，第二回合释放高伤；玩家因此有一个真实反制窗口。敌方硬控也采用同样可读规则。

控制防锁死：同一敌人被硬控后获得 2 回合“定神”，期间硬控转为压制；寻仇等高难敌人可缩短控制时间，但不能无提示免疫。

### 5.4 新增“调息”，不新增第二套资源

在仙道/双修主行动中加入“息”：

- 恢复 `max(20, mpMax × 12%)` 灵力；
- 不造成伤害，不附带守势；
- 敌方仍执行本回合意图；
- 可清除一层自身迟滞，但不净化中毒和灼烧；
- 神道保留自身香火权柄体系，不机械复制同一按钮。

这样普攻、调息、术法、外物形成资源取舍：是用一回合回灵，还是承担灵力耗尽后只能普攻的风险。暂不新增“剑气、架势、气机”等第四条战斗资源，避免继续堆字段。

### 5.5 首批可读联动

| 前置 | 后续 | 结果 |
|---|---|---|
| 观察 / 目类神通 | 剑术、雷术、本命飞剑 | 消耗看破/破绽，获得已展示的伤害收益 |
| 火系术法 | 雷符 / 惊雷引 | 触发一次“雷火”，按剩余灼烧追加小额伤害并消耗一层；不可递归触发 |
| 缠木根 / 压制 | 调息、丹药、蓄力类能力 | 用控制换资源窗口 |
| 敌方蓄力意图 | 镇压、雷符、法印本命 | 成功打断，敌方该次行动失效并进入定神 |
| 敌方护体意图 | 落石诀、破甲符 | 先破防再爆发，而非所有攻击都直接乘倍率 |

联动的来源、消费和伤害必须在日志中写清，例如：“雷火引爆余焰 +326；灼烧剩余 1 回合”。

### 5.6 外物使用节奏

首批数值作为模拟起点，而非不可调整的硬规定：

- 丹药每场最多使用 2 次，界面显示“丹药 1/2”；新增 `pillCount`，保留 `usedPill` 布尔值供旧成就逻辑使用。
- 同一丹药不能连续两回合使用；高阶全恢复丹仍受总次数限制。
- 符箓仍消耗本回合，不设总携带配额；同种符使用后冷却 1 回合，防止无限叠同一状态。
- 遁符直接离场但没有击杀奖励；神行符只是规避一次直接攻击，不等于必遁。
- 器物弹窗按“攻 / 防 / 控 / 助 / 丹”分类，显示库存、剩余回合、冷却和真实效果，不限制只能看到前六种而导致新物品不可达。

### 5.7 战斗奖励接入四艺

在保留现有灵石、声望、修为/香火的基础上，增加轻量掉落：

- 剑修/体修：铁木心、金灵砂，少量龙岩铁；
- 法修/诡修：符纸、朱砂、合神花、蓝幽草；
- 高难寻仇：额外丹方线索、器料或稀有符，不直接商店化全部产物。

建议初始期望：普通胜场约 45% 掉一份材料，约 12% 掉一张基础丹符；寻仇必有一份与路数相关的材料。具体概率必须结合现有月账和四艺毛利模拟，防止“战斗刷材料”全面取代历练、采集和坊市。

## 六、本命法宝：筑基锻造与普通法器分家

### 6.1 来源规则

1. **只有首次仙道筑基成功时锻造一件本命。** 双修角色有仙道线也适用；纯神道不强制插入仙道仪式。
2. 不再从坊市、拍卖、普通炼器或 `S.arts` 中选择本命。
3. 九转飞剑、万灵幡、青叶舟、太阴宝鉴等继续作为普通法器购买/炼制/装备，但文案删除“可为本命”，认主接口不再接受它们。
4. 本命不是商店商品，不进 `S.arts`，不可出售，不占普通 `atk/body/move` 装备槽。
5. 普通法器加成只由 `artBonus()` 计算；本命能力走独立计算口，删除“同一件普通法器 bonus 再算一遍”的机制。
6. 本命终身一件；器损高时沉眠和反噬，不随机永久删除全部培养。

### 6.2 筑基仪式流程

```text
破境成功诗
→ 仙基与道统确定
→ 本命锻造：择器形 → 择主五行 → 正名 → 预览法技
→ 道印
→ 神通 / 命格等后续手续
→ 返回正常游历
```

仪式约束：

- 只触发一次，条件为本次由 `xRealm=1` 成功进入 `xRealm=2`，不是每次小阶突破。
- 仪式本身提供基础器胚，**不检查炼器等级、不消耗额外旬、不再掷一次成功率**。玩家已经通过筑基判定，不能因未学炼器被卡在手续里。
- 自携铁木心、金灵砂等材料只影响初始品相或一条小加成，不决定能否完成锻造。
- 五行候选优先展示角色已有 `rootEls`，并允许选择与主修功法一致的一项；不在本命仪式里随机改变灵根。
- 正名沿用现有长度限制；默认名按“器形 + 五行”生成，玩家可跳过命名但不能跳过器形选择。
- 破境队列改成真正的 FIFO：每步只 `shift()` 当前项，完成后统一再调 `do;afterbreak`。修 `do_yin` 的续接是前置任务。

### 6.3 首版五种器形

所有数值进入模拟后调整，首版重点是行为差异，而不是五档输出倍率。

| 器形 | 认主被动 | 通灵法技 | 路线与代价 |
|---|---|---|---|
| 本命飞剑 | 剑系术法伤害小幅提高 | 单体高伤；对已有破绽目标追加收益，不在同一击自造自吃 | 纯输出，器损增长较快 |
| 本命法印 | 对蓄力敌人的控制效果更稳定 | 小额伤害 + 压制；可打断蓄力 | 控制后进入定神，不能连控 |
| 本命宝镜 | 敌方意图显示更精确的数值和附加状态 | 看破并移除一层敌方护体/增益 | 直接伤害低，依赖后续输出 |
| 本命神钟 | 常驻小额减伤，受全局减伤上限约束 | 获得一次护体，不减免持续伤害 | 输出能力弱，护体会增加器损 |
| 本命魂幡 | 对中毒/灼烧目标伤害提高 | 施加持续伤害，可消耗自身少量气血增强 | 魔道/持续流，有气血与业力叙事代价 |

四阶继续沿用现有认知，但重排职责：

1. **认主**：获得器形被动；
2. **通灵**：解锁主动法技，法技有灵力、器损和冷却成本；
3. **共命**：解锁战前“出鞘”及器形强化；器损过高反噬主人；
4. **合道**：与命格、道统或五行形成一条联动，并保留物锚稳定作用。

### 6.4 数据结构建议

本命不再借用普通商品 id 作为真值：

```text
S.benming = {
  ver: 2,
  form: 'sword | seal | mirror | bell | banner',
  el: 'metal | wood | water | fire | earth | thunder',
  name: '玩家正名',
  tier: 1,
  xp: 0,
  dmg: 0,
  quality: 'rough | normal | fine',
  forgedRealm: 2,
  skillsUsed: 0
}
```

新增静态 `NATAL_FORMS` 表，负责名称、被动、法技、描述和图标；普通 `ARTIFACT_EXT` 不再出现本命专属字段或文案。

### 6.5 旧档迁移

迁移必须一次性、幂等、可重复读档验证：

1. 若旧档有 `S.benming.artId`，按原物映射器形：九转飞剑→飞剑；百魂幡/万灵幡→魂幡；太阴宝鉴→宝镜；护身玉符→神钟；青叶舟等移行器→宝镜。
2. 保留玩家自定义名称、四阶、祭炼经验、器损；生成 `ver:2` 的独立本命。
3. 原普通法器仍留在 `S.arts` 和装备槽中，但从迁移完成起只提供普通加成，不再提供本命双倍 bonus。
4. 已是筑基及以上、却从未有本命的仙道旧档，提供一次“补铸本命”入口；走同一器形选择，不伪造一次破境，也不重复发其他破境奖励。
5. 新档未筑基时，本命面板只显示“筑基时可铸”，不显示普通法器候选。
6. 迁移中若旧本命字段残缺，按安全默认值修复；迁移不能删除普通物品、重复生成第二件本命或反复发材料。

## 十、验收方案

### 10.1 布局

- 1600×1200、1366×768、1024×768、390×844、320×740 均无横向溢出、遮挡和不可达按钮。
- 桌面所有已解锁一级功能在左侧直接可见或可在左导航内滚动到达，不需先展开底部分组。
- 原 `dockItems()` 中每个有效入口都有新位置；`check_actions` 不出现孤儿动作或死按钮。
- 中栏主行动、右栏告警、左导航可同时进行键盘操作；弹窗焦点与 ESC 行为不回退。
- 常见桌面视口下，不再出现“功能必须滚到三栏之后才能找、左右却大面积空白”的结构。

### 10.2 战斗

- 每个新术法效果都通过真实 `skill` UI 路径触发，状态数值、持续回合、日志一致。
- 敌方面板展示的意图与实际执行一致；保存/读档后意图不重新随机。
- 蓄力能被指定手段打断；定神期间不能无限硬控；持续伤害致死正常发奖励。
- 调息回灵准确，敌方仍行动；灵力不超过上限，气血和库存不为负。
- 敌我状态显示在各自卡片；玩家能在不查源码的情况下说出“下一回合为什么该守、该断或该调息”。
- 普攻到底、术法流、符丹流、守势流、本命流分别跑模拟；普通战目标中位数约 4~7 回合，寻仇约 6~10 回合，不允许单一消耗品成为所有局面的唯一最优解。

### 10.3 本命

- 练气期购买九转飞剑只得到普通法器，`S.benming` 仍为空，任何入口都不能认主。
- 首次筑基必定出现锻造选择；不依赖炼器等级，不再随机失败，不会卡死后续仙基/道印/神通/命格。
- 五种器形的被动与法技确实不同，本命不占普通装备槽，普通法器 bonus 不翻倍。
- 破境手续每一步读档都能继续；重复点击锻造不会生成两件本命或重复扣料。
- 旧本命迁移保留培养，原普通物品仍在；迁移执行两次结果完全一致。
- 筑基以上无本命旧档可补铸，纯神道不被强制转仙道。

### 10.4 符箓与丹药

- 12 种战斗符和 8 种新丹均有真实效果、库存、来源、配方、图标、日志与测试。
- 所有新增配方材料可达；成功、失败、重复制作、材料不足均只结算一次。
- 丹药次数、同种符冷却、状态刷新、净化、持续恢复与撤退规则符合面板文案。
- 旧一次性符类物品迁移后数量不增不减，破宝锥仍是普通法器。
- 持有超过六种丹药/符箓时仍可在分类菜单中使用最后一种。
- 全量战斗、四艺、经济、存档、可达性测试通过；新掉落不破坏月账和无套利规则。

建议新增专项回归：

- `tools/test_v107_layout.js`：入口映射、桌面/移动可达性；
- `tools/test_v107_combat.js`：真实术法、意图、控制、调息、持续伤害；
- `tools/test_v107_natal.js`：筑基锻造、五器形、破境队列、旧档迁移；
- `tools/test_v107_consumables.js`：新丹符、配方、次数/冷却、物品迁移；

## 十二、最终优先级

若后续需要继续压缩实施范围，顺序保持：

1. **左侧常驻导航 + 战斗真实效果/状态口径修复**；
2. **筑基锻造本命 + 普通法器彻底解除认主**；
3. **敌方意图、蓄力与四种路数 + 调息**；
4. **12 战斗符、8 新丹、14 个补全配方与获取链**；
5. 数值模拟、移动端细调、发布产物同步。

这样每一步都能独立改善真实体验，不会落入“界面换皮但玩法不变”或“物品加了很多但战斗仍只有换血”的旧问题。
