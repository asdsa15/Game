## 一、本阶段做了什么（一句话）

**把功能入口从页面底部搬回左栏，把战斗口径从「文案说什么」改成「结算算什么」，把敌我状态放回各自卡片。**

## 二、改动清单

### 2.1 布局迁移（`wxcs3-game.js` / `问道长生v6.html` / `mobile/mobile.css`）

| 改动 | 做法 | 位置 |
|---|---|---|
| 桌面三栏重排 | `render()` 由「三栏 + 底部通栏 `.dockrow`」改为 **左导航 / 中行事与纪事 / 右状态** | `wxcs3-game.js:render()` |
| 左导航 | 新增 `renderNavCol(groups)`：天时三行置顶，其下按分组直接列出**一级功能**，不再先点「修炼/经营」再找 | `renderNavCol()` |
| 纪事移中栏 | 新增 `renderChronCol()`：近期纪事 7 条 + 本月收支摘要，标题「纪事 · 月账」；完整纪事仍走年谱 | `renderChronCol()` |
| 右栏吸顶 | `.stage>.col-nav` 与 `.stage>.col-state` 改 `position:sticky; top:58px; max-height:calc(100dvh - …)`，内部滚动 | `问道长生v6.html` |
| 移动端底栏 | 新增 `renderMobileNav(groups)`：五项常驻底栏（修行/外物/出行/人事/更多）+ 要务红点 | `renderMobileNav()` |
| 删除旧坞 | 删 `renderDock()` / `dockBtn()` / `DOCK_GROUPS` / `ACT.do_dockGrp`；对应 CSS（`.dock/.dockbtn/.dockgrp/.dockgt`）一并删除 | — |

**导航真源不变**：`dockItems()` 原样保留（十来个扩展都往里追加入口），新增的 `NAV_GROUPS` / `navGroups()` / `navGroupOf()` **只负责分组与排序**，同一个动作名不在两处各维护一份。

`navStaticItems()` 把「年谱 / 功过格 / 账本」补进「记录」组——它们原本不在 `dockItems()` 里，不补就会在迁移中丢失。

**分组规则**（`NAV_GROUPS` 为唯一真源）：

| 组 | 收录 |
|---|---|
| 要务 | 有人来访、限时急事、拍卖会、待清人情、锚定危险、新手引导 |
| 修行 | 功法、四艺、道书、构筑、命格、道果 |
| 外物 | 乾坤袋、法宝、本命、灵兽、神器、愿物 |
| 经营 | 洞府/庙宇、家族、宗门、道统 |
| 人事 | 情缘、人情、门下 |
| 出行 | 历练/显圣、舆图、坊市/庙市、遗迹、洞天 |
| 记录 | 年谱、功过格、账本 |

- **要务置顶**：紧急项消失后不保留空位（空组不渲染）。
- **拍卖**按方案 §4.2.3 放进要务组（§4.2 表里它在出行组，两处冲突取更具体的 §4.2.3）。
- **本命（`k='命'`）归外物组**，命格（`k='构'`）归修行组——按各扩展实际注册的 `k` 值，不臆造。
- 未登记的 `k` 落「其他」兜底组并 `console.warn`，不静默丢入口。

**新增 ACT**：`do_navgrp`（开分组弹窗）、`do_navgo`（转发到目标面板，先关弹窗再 dispatch）、`do_navmore`（移动端「更多」全量列表）、`do_useart`（一次性外物的平时使用入口）。

**旧档兼容**：`S.dockOpen` 的存档迁移代码**保持不动**（旧档读入不报错），只是不再有对应的展开态。

### 2.2 战斗口径修复

| 符箓 | 旧行为 | 新行为 | 结算位置 |
|---|---|---|---|
| **增益符** | 每贴一张 +0.3 **无限累加**、无回合数、只增幅普攻 | `c.talBuff = t.v`（**刷新不叠层**）+ `c.talBuffTurns = 3+1`（贴符当回合递减一次，面板显示 3）；新增 `talBuffMul(c)` **统一乘到普攻 / 术法 / 符箓 / 神通 / 施法五条伤害路径** | `talBuffMul()` / `do_cbt` |
| **金刚符** | `red = 0.5 − talShield`，叠加守势后落到 0.05 下限，**实际减伤约 95%** | `c.talShield = Math.max(c.talShield\|\|0, t.v\|\|0.6)`；敌方回合改 `const _red = Math.max(c.defending ? 0.5 : 0, c.talShield \|\| 0); dmg *= clamp(1-_red, 0.05, 0.95)`——**守势与护体取强，不叠乘** | `foeTurn()` |
| **五雷符** | 文案写「伤害 +80%」但 `boost` 从未存在，只有 `sureHit` | `do_cbtpre` 写 `S.preBuff.sureHit = true; S.preBuff.boost = 0.8;`；新增 `preBoostMul()`，**普攻与术法首击都吃 +80% 并无视卸力**，日志写「（五雷符 +80%）」「（五雷符 · 无视卸力）」 | `preBoostMul()` |
| **传音符** | 在战前菜单里被**消耗但无对应效果分支** | 从战前菜单排除（`openPreFight` 过滤 `a.id !== 'jinchuan'`）；法宝面板把一次性之物**单列**，传音符给 `do;useart:jinchuan` 可用入口；随机选一位已相识 NPC 好感 +5（`clamp(fav+5,0,120)`），并 `advanceXun(1)` | `ACT.do_useart` |
| **拘仙敕神符** | 写 `S.preBuff.rankUp`，而 `rankUp` 是 `startCombat` 读走的一次性字段——**战前用等于白吃** | 改为**当场** `S.combat.rankUp = true` 并清 `S.preBuff.rankUp`（免得下一场白送） | `do_cbtpre` |

**新增 `endCombatRound(c)` 作为回合收尾唯一出口**：`foeTurn` 的三条出口（滑头逃跑、正常结算、其它分支）全部改调它，状态递减只在这一处发生——否则增益符永不过期这类 bug 会反复出现。

**传音符占一旬的理由**：规则是「产出好感 → 占旬」。不占旬的话它就是一个只花灵石、不耗时间的刷好感外挂。

**增益符回合数**：贴符这一手本身不是输出，所以内部记 4 回合、回合结束递减后面板显示 3。

**金刚符取强对两种护体都安全**：`c.talShield` 同时被本命法技复用（0.30 / 0.15），取强规则对两者都成立。

### 2.3 敌我状态归位

破绽 / 压制 / 灼烧 / 迟滞 **从「我方」卡移到「敌方」卡**（它们作用于敌方，之前集中渲染在我方状态区，玩家没法一眼判断谁中了什么）。

- 辅助类 `nw`（nowrap）样式上移到敌方段，避免重复声明。
- 我方卡改显「增益 · 直接伤害 +30%（N 回合）」「护体 · 下次受击减伤 60%」。

### 2.4 文案对齐（`wxcs3-data.js`）

`TALISMANS` 五条 `eff` 与 `ARTIFACT_EXT` 中火云符 / 传音符 / 五雷符 / 祈雨符箓 / 拘仙敕神符的 `eff`，全部改写为**与结算一致的表述**——文案不再承诺结算没做的事。

### 2.5 样式（`问道长生v6.html` / `mobile/mobile.css`）

- `.stage` 三栏改为 `240px / minmax(0,1fr) / 300px`，`max-width:1560px`；≤1199px 为 `220 / 1fr / 276`；≤880px 单列。
- 新增 `.stage>.col-nav>*, .stage>.col-state>*{flex:0 0 auto}`——可滚动栏是 flex 纵向列，给了 `max-height` 后子面板会被 `flex-shrink` 压扁。
- 移动端单列顺序改为 **要务 → 主行动 → 状态**；新增 `.navitem{min-height:40px}`、`.navmobtn{min-height:46px}` 与 560 / 360px 断点。

**两个必须记住的 CSS 顺序陷阱**（下次改布局会再踩）：

1. `.stage>*:not(.sceneart--backdrop){position:relative;z-index:1}` 与吸顶规则**权重相同**且原本更靠后，会把 `position:sticky` 静默压成 `relative`。吸顶规则必须**后置**且用 `.stage>` 前缀提权。
2. 窄屏媒体查询如果排在吸顶规则**之前**，窄屏覆盖会被吸顶规则反压。所以窄屏查询必须排在吸顶规则**之后**，并改用 `.stage>.col-nav` 提高权重。

7. **方案第十一节「本轮不做」全部遵守**：未改实时动作/卡牌/多敌人、未新增抽卡氪金、未重写神通功法、未引入耐药系统、未为填空白加装饰面板。
