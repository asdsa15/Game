### 2.2 行动清单的唯一真源（`wxcs3-game.js`）

| 新增 | 作用 |
|---|---|
| `combatActionList(c)` | 只产出数据：`{key, txt, tag, note, act, dis, grp, html}`；基础七项 + 扩展外物都在这里 |
| `combatKeyAction(k)` | 按 `key` 在**同一个数组**里找回 `act`；禁用项返回 `null`（按下去与点不动一致） |
| `renderCombatRow(it)` | 数组 → `<li>`；扩展自带整行 HTML 时原样输出（保住兽令/本命的图标） |
| `splitFightRows` / `rebindOptKey` | 把 `fightRowsHooks` 产出的 `optRow` 整行拆回数据，并把键位统一换成编号 |
| `FIGHT_EXT_MAX = 4` | 外物组硬上限；超出时渲染前 3 条 + 「其余 N 项」（`act:openFightExt`） |
| `fightLogOf(c)` | `S.log` 里 `seq > c.logFrom` 的条目，取 6 条、正序 |
| `ACT.openFightAll` / `ACT.openFightExt` | 「本场全部」与「外物全集」两个弹窗 |

**编号口径**：动作按出现顺序吃 `1~9`，第十项起键位写 `·`（不印一个按下去没反应的数字）。基础七项固定为 `1 攻 / 2 术 / 3 御 / 4 调息 / 5 器 / 6 遁 / 7 谋`；神道不出调息，编号顺延不留空号。

**键盘**：`keydown` 的守卫由 `S.phase !== 'play'` 改成按阶段分派——

```js
if (S.phase !== 'play' && S.phase !== 'combat') return;
const act = S.phase === 'combat' ? combatKeyAction(k) : mainKeyAction(k);
```

这一条同时修掉 bug A：按钮上印着 1~6，此前按下去毫无反应。

### 2.4 重绘保住滚动位置

```js
const SCROLL_SELS = ['.col-nav','.col-main','.col-state','.col-foe','.col-me','.col-acts','.fightlog'];
scrollSnap(stage)  // innerHTML 前记 scrollTop
scrollApply(stage, snap) // innerHTML 后写回
```

`render()` 内所有 `stage.innerHTML = …` 收口成一个 `paint(html)`：赋值 → `enhanceA11y` → 写回滚动位置。按 class 定位而不是 `children[i]`，三栏顺序以后再变也不会串栏。快照值 0 直接跳过，省一次强制布局。

### 2.5 移动端构建对齐（`mobile/mobile.css`）

`mobile.css` 原本按「对战保持左右并排」写死 `grid-template-columns:1fr 1fr`，与新的单列手机布局冲突，已同步改为单列 + 底部行动条留白；战况样式由「行动区底部的四条摘要」改为「我方卡下方的独立块」。

## 四、与方案的差异（都已落在实现里）

1. **外物组「统一编号」而非保留原标签**。方案只要求「硬上限 4 + 折叠」。实现时把 `fightRowsHooks` 的整行拆回数据、键位统一编号，这样「第 8/9 项」也有数字键；代价是兽令原来的「兽」字键位变成数字（图标与标签保留）。第十项起因超过 9 个数字键，键位写 `·`，不做假承诺。
2. **1199 以下不是「底部 sticky 六项 + 更多」**，而是「行动区通栏 + 四列一行」。1280×800 实测七项全见，比折叠成六项更省一次点击；真正的六项折叠留给 P1 的侧滑面板。
3. **手机底栏不是「两行高 + 上滑展开」**，而是四列两行（约 87px）、直接放完全部基础动作，不做展开层。390×844 实测三项验收目标（敌气血 / 敌意图 / 我气血 + 全部行动）都满足，没必要再加一层交互。
4. **手机隐藏了 `vsline`（回合/R/胜算）与行动面板标题**。底栏空间只够放按钮；胜算在敌方卡右上角仍有（`panel sub`），回合与战况改看战况区。桌面与 1280 完全保留 `vsline`。
5. **战况不印时间戳**。同一场里每条都是「三月上旬」，重复六遍只挤占高度；时间留在「本场全部」里看。

## 五、遗留项

1. **bug E（术/器/谋 整屏弹窗）未修**。`act:openSkills / openGear / openWits` 仍走 `openModal`，开弹窗时战斗画面被盖住。属 P1·顺手修第 5 项（右栏侧滑面板，≥880 生效）。**P0 只保证行动区不再出屏，没保证弹窗不遮屏。**
2. **`combatActionList` 是每次重绘现算**，没有缓存。它依赖 `computePower/deflectOf/artBonus`，这些本来就是每次重绘都在读的量，实测面板重绘无感知变慢；若 P1 加侧滑面板导致重绘频次上升，再考虑按 `c.round` 记忆。
3. **外物组的图标仍由扩展的 `optRow` 产出**，`splitFightRows` 依赖「一行 `<li class="opt…">` 是一整条」这一格式。扩展若改用别的行构造（不走 `ui().optRow`），该行会退化成「无键位但仍可点」。已在 `test_v108_ui.js` 用 fake hook 覆盖数组/字符串两种返回形态。
4. **`mobile/dist`（9666.4 KB）与 `desktop/app`（9690.4 KB）已按本批重建**（`.gitignore` 内，不入库）。桌面 Electron 安装包未重打包，仍是 v10.3 产物。
5. **P1 / P2 未动**：中栏分页、日志分类（`LOG_CATS`/`guessCat`）、批量执行器（`runBatch`）、坊市段控、采集 N 旬、炼制 N 炉、应用外壳 sticky 均未实施。
