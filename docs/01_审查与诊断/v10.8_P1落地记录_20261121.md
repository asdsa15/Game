## 一、本批做了什么（一句话）

**中栏从一条长卷拆成「行事 / 纪事 / 账目 / 道基」四页，横幅提为通栏、气血叠在图下沿；纪事按八类归档可筛，战斗内弹窗改右栏侧滑，结果窗给「再来一次」。**

本批**只动信息架构与呈现**：不改数值平衡、不改事件池、不改战斗公式；给 `S.log` / `S.chronicle` 条目补了可选字段 `cat`（旧档读时补、不回写），其余存档结构不动。

### 2.4 纪事/年谱共用筛选

`chronChips()` 产出「全部 + 8 类」九个 chip（`.cattab`），`do;mcat:<id>` 只改 `_chronCat` 再重绘；纪事页与年谱抽屉读同一份 `chronOf()`，筛的是同一张表。

### 2.5 战斗内弹窗改右栏侧滑（`openModal`）

```js
function sidePanelFight() { return S.phase === 'combat' && S.combat && window.innerWidth >= 880; }
```

命中时 `.modal` 加 `modal--side`（靠右、`background:linear-gradient(to right,…)`）、`.box{width:368px;max-width:44vw;height:calc(100vh - 82px)}`（`@supports(height:100dvh)` 用 dvh）、`<div class="sidegrip">` 抓条 + `sideIn` 动画。窄屏保持整屏——手机上侧滑只会把字挤成竖排。

### 2.6 结果窗「再来一次」

| 改动 | 做法 |
|---|---|

## 四、与方案的差异（都已落在实现里）

1. **chips 是九个而不是七个**。方案 §7.3 只列了七个分类，§7.4 又要求八类每种都能筛出条目。实现按数据层八类出「全部 + 8」，多出来的「杂记」正是 §7.4 要的兜底可筛；若砍掉它，`misc` 条目就只剩「全部」里翻。
2. **没有逐处手标战斗日志，改成一条上下文规则**。`S.phase==='combat' && S.combat` 时默认 `combat`，只给跨阶段的日志（结算、掉宝、战后纪事）显式标注。方案原估 35 处显式标注，实际 **31 处**——省下的四处正是被这条规则吃掉的。
3. **纪事页只放 8 条 + 页脚「看全部」**，不是方案草图的「15 条 + 内滚」。8 条刚好等于 `.logbox--scroll` 的 `min(58vh,440px)` 高度，再多就得滚，而滚起来不如点开年谱看全。
4. **侧滑面板只在 `≥880` 且 `S.combat` 存在时生效**。方案写「≥880」，实现多加了 `S.combat` 判断：`S.phase` 可能因脏状态停在 `combat` 而 `S.combat` 已清空，那种情况下按整屏走更安全。
5. **`do_retry` 落「中间步骤」而非「占一旬」**。它只是把参数转回 `do_gather` / `do_craftgo`，时间由被转的动作收；若在这里再 `advanceXun(1)`，一次采集会被收两次旬。

## 五、遗留项

1. **账目页只搬了月账摘要**，没有把「本月收支明细」按类分组。方案 §5.2 给的是「搬过去 + 不新增内容」，分组留到 P2 的批量执行器一起做（那时才有「一次批量花了多少」的账）。
2. **中栏底部仍有约 250px 空白**（1440×900）。四页都塞不满一屏是分页的必然结果，强行拉伸会让行事页的选项变成两行大字。若后续要填，优先考虑把「本旬计划」或「待办」放进行事页下半，而不是把纪事搬回来。
3. **`.opt--wide` 只在恰好奇数项时生效**。扩展若给主行动加第六项（例如神道多一项），末项就不再是单独一行，两列会排成三行——这是对的，但需要在加项时确认不是「留一个空格子」。
4. **`maybeEvent` 以探针形式导出到 `G.WXCS3`**，仅用于测试驱动真实随机事件通路（世情类零覆盖时靠它跑出来）。它是只读入口，不改状态。
5. **`mobile/dist`（9683.3 KB）与 `desktop/app`（9707.6 KB）已按本批重建**（`.gitignore` 内，不入库）。桌面 Electron 安装包未重打包，仍是 v10.3 产物。
6. **P2 未动**：批量执行器（`runBatch`）、坊市段控、采集 N 旬、炼制 N 炉、应用外壳 sticky、行情涨跌箭头、材料页「已有 N」均未实施。
