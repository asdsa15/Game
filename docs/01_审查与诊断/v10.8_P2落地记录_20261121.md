## 一、本批做了什么（一句话）

**把「坊市能批量、四艺不能」这件事按同一套口径抹平：一个 `runBatch` 执行器，三处接入（坊市数量段控 / 采集 N 旬 / 炼制 N 炉），同一套「每单位独立掷骰 + 命中即停 + 只弹一次汇总」；另把中栏做成 ≥1200 的吸顶内滚（外壳固定 B 版），并补上行情涨跌箭头与材料「已有 N」。**

本批**只动交互成本与展示**：不改任何数值平衡、不改配方与掉落、不改战斗公式；存档只新增一个可选字段 `S.batchN`（缺省 1，`SAVE_VER` 不动）。

## 二、改动清单

### 2.1 批量执行器 `runBatch(n, step)`（`wxcs3-game.js`）

```js
runBatch(n, step) → { n, done, stopped, why, results }
```

三条口径写死在执行器里，三处接入不再各写一遍：

| 口径 | 实现 |
|---|---|
| 每单位独立掷骰 | `step(i)` 逐次调用，**禁止「一次掷骰 ×N」**；`n` 是真正跑完的单位数 |
| 单位自报即停 | `step` 返回 `{stop:true, why:'料尽'}` 即 `break`，`why` 原样带回 |
| 阶段一变即停 | 单位跑完发现 `S.phase !== 'play'`（死亡 / 进战斗 / 弹奇遇）→ 记 `外界生变` 并停 |

`step` 抛错不会被吞：批量不是事务，出错停在原地比静默续跑好。

### 2.2 `S.batchN`：三处批量记忆（唯一的存档字段）

| 键 | 含义 | 收敛 |
|---|---|---|
| `shop` | 坊市「每次买几份」，`0` 表示「买满」 | ≥1，或 0 |
| `gather` | 采集一次几旬 | 1~3 |
| `craft` | 炼制一次几炉 | 1~12 |

- 旧档没有这个字段 → `applyState` 里补 `{shop:1,gather:1,craft:1}`，**读档不报错**；
- 万一旧档里写成裸数字，按同一值铺开再收敛；
- `SAVE_VER` 不动，旧档无需迁移。

### 2.3 坊市：数量段控 + 自动降档

- `.shop-tools` 下多一行段控：`买 1 / 买 5 / 买 10 / 买满`（`do;shopqty:<n>`），只对能叠的货（丹药 / 符箓 / 材料）出现；
- 点一下买 N 份：**只记 1 笔账**，摘要写「购 补气草 ×5」，金额 = 单价 × 实际份数；
- 余额不够**自动降档**并如实报「灵石只够 N 份，已买到上限」——不整单失败，也不悄悄少买；
- **法器 / 功法 / 术法 / 灵脉契强制 ×1**：它们是「买到就归你」的唯一物，段控不能把 v10.5 P0·E6 的「购买唯一」变成空话；
- 列表里多一句「买 5 份 300 石」，省得玩家心算。

### 2.4 采集：一次 N 旬

- `ACT.openGather` 顶部三档：`1 旬 / 2 旬 / 3 旬`（`do;gatherqty:<n>`），地点行动作带当前档位 `do;gather:<spot>:<n>`；
- 每旬独立：`advanceXun(1)` → 判能否采到 → 掷份数 → 逐份挑料 → 掷稀有；材料累加；
- **外界之事只掷一次**（与 `ACT.cultivate` 同一口径），结果窗写明「这 N 旬里头，外界之事一并略过」；
- 中止（此境采不到 / 进战斗）如实报「第 k 旬中止：…」；
- 结果窗沿用 P1 的「再来一次」，`do;retry:gather:<spot>:<n>` 直接复跑同参数。

### 2.5 炼制：一次 N 炉

- `openCraftRun` 底部段控：`1 炉 / 3 炉 / 5 炉 / 做满 · N 炉`（`do;craftqty:<id>:<n>`，做满按最紧的那种料算，封顶 12）；
- 火候一次选定、作用于全部 N 炉；`do;craftgo:<id>:<mode>:<n>`；
- **每炉独立扣料、独立判成败、独立结算炸炉**（气血 / 道心 / 残料回收都按炉算，不许「惩罚只算一次」）；
- 材料在第 k 炉不足 → 停，报「第 k 炉料尽」，不会把已炼的作废；
- 结果窗：成几炉、废几炉、按品相汇总的产出、总料钱 / 中品回收 / 净约，底部「再来一次」。

### 2.6 应用外壳固定（≥1200 才生效）

```css
@media(min-width:1200px){
  .stage>.col-main{position:sticky;top:58px;max-height:calc(100vh - 84px);
    overflow-y:auto;overscroll-behavior:contain}
  @supports(height:100dvh){ .stage>.col-main{max-height:calc(100dvh - 84px)} }
  .stage>.col-main .tabbar{top:0}
}
```

- 用 `max-height` 而不是 `height`：中栏内容短于一屏就自然回落到文档流，不会留一大片空白；
- Tab 条在中栏内滚时吸在栏顶（栏内滚动容器的 `top` 是 0，不是视口的 58）；
- 规则排在 `.stage>*:not(.sceneart--backdrop){position:relative}` **之后**——权重相同，写在前面会被静默压成 relative（v10.7 就栽过）；
- 前提是 P0 的重绘保滚动位置：没有它，吸顶 + 内滚 + 每次重绘归零会比不固定更难用。

### 2.7 顺手修 6 / 7

| 7 材料已有数 | 材料行 note 追加 `· 已有 N`，买料不必再开乾坤袋对数量 |

## 四、与方案的差异（都已落在实现里）

1. **每单位都重绘一次**（方案没提）。原因很硬：`render()` 里的场景句要掷地点、吃随机数。逐次采集/炼制每回合都重绘，批量若攒到最后只画一次，第二单位起的掷骰就会与手动错位——「同 seed 等价」当场不成立。所以批量循环里每单位各重绘一次，**总量与手动相同**（采集 3 旬 = 3 次重绘），且循环结束后不再补画。
2. **等价断言要求「外界无事」**。批量只掷一次 `maybeEvent`（方案 §6.3 明确要求），而手动是每单位一次；所以 deepEqual 的前提是把外界事件按住（`S.holdEvent`）——这也把「功过格落盘」清了盘，否则第二局会把成就当「前世已得」，日志与掷骰顺序都会变。断言验的是采集/炼制自身的掷骰链，不是事件池。
3. **采集上限取 3 旬**，不是「本月剩余旬数」。跨月是正常时间推进（`advanceMonth` 照常结算寿元、行情、NPC），把上限绑在剩余旬数上只会让「上旬只剩 1 旬」时不能连采，收益为零、困惑加倍。
4. **「买满」在段控里用 0 占位**，不是 99。它是一个「按余额算」的选项，不是一个数量；存档里 0 也照原样保留（读档收敛时特判）。
5. **`qtyChips` 三处共用一份外观**，标签由调用方给（每次买 / 采集几旬 / 炼几炉）。段控自己**不收时间**，时间由 `do_buy` / `do_gather` / `do_craftgo` 收——否则点一下数量就被收两次旬（已写进 `行动预算_分档表.md`）。
6. **行情箭头只给丹 / 器 / 料**。符箓与功法本来就不随行情动，标个「—」只会让人以为能等它跌。
