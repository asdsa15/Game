## 二、改动清单

### 2.1 P0-1 · 杀招：招式与招式之间的关系

**问题**：14 个招式各自独立，最优解永远是「伤害最高的那一招按到底」（`leiming 1.75` / `shenying 2.10`）。全项目 `组合技|连招|杀招` 关键词命中 0。

**实现**

```
杀招 = 2~3 个招式按序释放 + 满足条件 → 触发一次结算
      不是新招式，是「招式之间的关系」
```

- 数据：`D.COMBOS` 8 条（焚山煮海 / 雷落九霄 / 缚而后斩 / 落井下石 / 寒潭照影 / 血喂剑 / 流转不绝 / 镇压八荒），配方全部用现有 14 招拼；
- 判定：`comboMatch` → `comboCheck` → `comboForSkill` 三层，**菜单预览与结算同源**（看到的 = 发生的）；
- 条件全部读已有状态：`foeBurn / foeWeaken / foeShred / foeCalm / hpHigh / hpLow / wasGuard / seq`，**不新增状态字段**；
- 断链：`prevSkillRound` 用「回合距 ≤1」表达「紧接上一手」，中间隔任何一手自然断链，不需要显式清空；
- 反馈：触发时日志 `cls=combo`（橙色 + 左侧色条），写专属文案；未满足条件退回普通招式，**绝不「点了没反应」**。

**验收**：`tools/test_v11_combo.js` 32 项全绿，含「隔一手不成招」「无前招不成招」「预览与结算同源」「×2.2 乘区生效」。

### 2.2 P0-2 · 奇遇分境界：接通现成的 `when`

**问题**：`eventSlot()` 里的 `whenOk()` 早已能读 7 个条件（game.js:7925），**但 30 条奇遇一条都没写**——管道造好了没接水。

**实现**

| 档 | 条件 | 内容取向 | 条数 |
|---|---|---|---|
| 凡尘 | `maxRealm: 1` | 生计、山野、凡人纠葛 | 20 |
| 修行 | `minRealm: 2, maxRealm: 3` | 道统、宗门、遗迹线索 | 20 |
| 天机 | `minRealm: 4` | 果位、位格、天地异变 | 20 |

- `whenOk` 从 `eventSlot` 内的局部闭包**提为模块级函数**，语义一字未改，从「事件专属」变成「凡是带 when 的表都能用」；
- 新增 30 条奇遇（原 30 条保留），天机档此前为空白——金丹之后本没有专属奇遇；
- 每档 8 条 `common` + 1 条 `xian` + 1 条 `shen`，保证仙道/神道玩家在任何境界都有 ≥8 条可抽，池子不会退化到 `all[0]`；
- 新 30 条走**数据驱动结算器** `applyEncRes` / `encOp`：条目上的 `res` 写清「掷中给什么、没掷中给什么、说什么话」，不再为每条写 switch 分支。

**验收**：`tools/check_content.js` 断言「三档各 ≥10 条」「每境界每道途可抽 ≥8」「所有 res 操作名在 encOp 白名单内」。

### 2.3 P0-3 · 神通变体：4 模板 × 5 修饰 = 20 格

**问题**：227 个神通名，只有 4 个机制模板（命 1.85 / 术 1.55 / 身 1.15 / 目 1.30），按同余散列分配——「分阳钗」和「金窍心」除了名字和乘区小数没有任何区别。

**实现**

| 修饰 | 实现 | 感知 |
|---|---|---|
| 连击型 | `hits: 2, mul ×0.62` | 两段 |
| 穿透型 | `ignoreDeflect, mul ×0.85` | 无视卸力 |
| 持续型 | `turns: 3, mul ×0.55` | 三回合侵蚀 |
| 反转型 | `heal ×2, 下回合受伤 +25%` | 大补后虚弱 |
| 控制型 | `stun: 1` | 定身 |

- **不做 227 个机制**（方案明确说那是灾难），按「道统键 → 五行 → 修饰」映射到 20 格；
- 同一 `(模板, 道统)` 组合**永远派生同一变体**（稳定散列）——流派感的前提是可预期；
- 变体倍率**不并进 `base.mul`**，作为独立乘区 `variantAdj` 单乘：`mul` 保持纯净（v10.4「双属合成 ≤ max×1.1」与「气质 +0.10 是加法」两条护栏读的正是面板 ×N 的跨神通比值，掺进按名字漂移的变体会撞出 ×1.467 的假越界）。面板把变体名与增减百分比单独标出，**每一层都对得上账**；
- 神通三选一卡片补一行「变体：连击型」。

**验收**：`tools/test_v11_st.js` 23 项，验 49 个道统键全可解析、5 种修饰各自兑现（定神/剥护体/灼蚀/反虚/大补）。

**顺带修**：`test_p0_v104.js` 两条断言原本用「两道不同名字神通的伤害比」测「双属合成 ≤ max×1.1」，v11 变体成了按名字漂移的独立乘区，代理指标被带到 ×1.467。改为直接读 `shenTongSpec().mul`，标尺重新变纯；伤害比作为出口对照保留。

### 2.4 P0-4 · 金丹之后：从「修为满了」变成「果位要守」

**问题**：`XIAN_REALMS[4/5]` 的 `need: 0, base: 0` 让 `monthXiuwei()` 返回 0，打坐变成白坐，修为系统到此终止；30 个果位只在结丹那一刻用一次。

**实现**

```
S.guoweiStab  0~100（旧档兜底 60）
每月自然 −1；落到 0 → 果位被夺：掉级回紫府、果位消失、进入夺回支线
维持手段：法仪 +8（灵石，同月限一次）· 显圣 +5（香火）· 布道 +3（招觊觎）
          应战：赢 +15，输 −25
```

- **落库存副本**：结丹时 `S.guowei = Object.assign({}, g)`，不再存表行引用——旧写法会让 30 个果位共享同一行数据，改一个全改；
- **觊觎者**：每月按 `stab` 反比概率触发，复用 `openVengeance` 战斗框架，夺位者战力略高于普通寻仇；
- **位格压制**：`guoweiStanceRank` 按档位返回 0/1/2/3，让 `GUOWEI_RANK` 的 ×7/×15 从「结丹面板露一次脸」变成常驻数值；
- **果位经营**：30 个果位各补一句 `domain`（这一位管什么：海中金=沉宝、剑锋金=兵戈）；
- 入口：中栏「道基」页果位卡片（`gwbar` 稳固条 + `gwbuts` 三个维持按钮）。

**验收**：`tools/test_v11_guowei.js` 30 项，验自然衰减 / 法仪补给 / 被夺掉级 / 旧档无 stab 补 60 / 位格压制档位 / 应战胜负账。

### 2.5 P1-1 · 道书重读：读第二遍意思变了

**问题**：11 部道书 44 层，读完给一次加成就是死数据。而《蛊真人》的核心趣味是「同一段文字，读第二遍意思变了」。

**实现**

- `S.bookReread` 重读计数（与 `bookRead` 初读分开记两条账）；
- 11 部书各补 2 层 `reread`（共 22 段重读文案），读出的是**前人的注**；
- 重读产出「注疏」（`zhuShu`，可售 260 石），可在道书面板**以注易注**——花 1 份注疏直读一部已读尽之书的下一层重读；
- 读后改变选项：读完《人祖传·残页》/《玄景残卷》后，特定奇遇多出「以书中之言应对」的第 D 选项（`bookOpt`），读过才有，硬套会用错。

**入口**：现有道书面板，不新增面板。

### 2.6 P1-2 · 地点产生内容：五个洲各有各的事

**问题**：`PLACES` 5 个，`danger` 只做「境界不够不许去」的门槛，`lingqi` 只改修炼速度——**去哪都一样**。

**实现（三段）**

1. **专属月度事件**：`D.EVENTS` 新增 15 条，每洲 3 条（青岳 4 条，含原有灵田虫害），挂当地方物（宗门开山门 / 妖潮 / 浮屠讲经 / 雪族换盐 / 天阙拍卖）。
   `eventSlot` 改为：带 `when.place` 的条目**只在本地入池**，且本地条目在池里**再放一份**（双倍权重）——本地事件占比约 20%，住哪个洲，五分之一的日常是那个洲的事。
2. **专属奇遇**：`D.ENCOUNTERS` 新增 15 条，每洲 3 条（山门试 / 兽谷弃崽 / 塔下白骨 / 雪族孩子 / 三道争一席）。
   `tryEncounter` 同样按 `when.place` 过滤 + 本地双倍权重。
3. **产地货**：`SHOP` 里原有 10 件标了 `place` 的丹药与灵材，但**货架从不读这个字段**——南疆火丹在北极也买得到。
   现在 `shopListInner` 按 `S.place` 过滤：产地货只在本地进货架；买走后随行（库存不绑地点，只有「上货」绑）。坊市顶部加一行「此地特产」提示。

**验收**：`tools/test_v11_p1.js` 26 项，验五地各有 ≥3 条事件与奇遇、异洲事件绝不出现、本地双倍权重、坊市只上本地货、买后随行。

**顺带修两处断链**：
- `applyIntentEff` 缺 `ruinClue` 分支——事件里写「得遗迹线索」是一句空话，只有奇遇结算器认这个键。补上，复用地同一段解释。
- `encOp` 缺 `insightXp` 分支——奇遇里写「悟道 +3」会静默落空。补上，与事件同口径。
- `encOp` 补 `craftQi` / `craftZhen`：旧白名单只有 `craftDan`/`craftFu`，写「炼器 +12」只能借用炼丹，四艺面板一查就对不上。

### 2.7 P1-3 · 人情兑现：12 条钩子只进不出

**问题**：`HOOKS` 12 条、`hooksGiven` 有字段，但玩家只能「讨债」，没有「用人情办事」——恩义在账上，不在事上。

**实现**：一条人情三种用法，各有各的代价

| 用法 | 效果 | 代价 |
|---|---|---|
| 借灵石 | 立刻到手 `120 × 情分` | 情分 −1；情分耗尽即销账且**反目**（好感额外 −20） |
| 代为打听 | 指出一处未知遗迹/线索（探尽则折 200 石） | 情分 −1；不受实力限制（消息不要实力） |
| 出手助战 | 战斗中一次外援（按你的战力折算，不按对方血量百分比） | 用掉即销账；一场一次 |

- 入口：人情账面板「讨债 · 求人」→ 每条人情四个按钮（讨回来 / 借灵石 / 代为打听 / 出手助战）；
- 战斗侧：动作条多一个「援」，**只有已托人且本场未用**才出现，用过即消失；
- 讨债数额改为随情分走（原固定 200，重的恩情与轻的还同一个数，情分就成了摆设）；
- 实力差距：对方远超你（`power > 2.2×`）时借与助战会被拒，但**情分照扣**（开口的成本）；打听仍可。

**验收**：`tools/test_v11_p1.js` 24 项，验三式各自改账、情分递减与销账、反目、助战一场一次、实力边界。

## 六、已知取舍

1. **`craftQi` 的语义**：借 `S.craft` 既有四键（dan/qi/fu/zhen），`qi` 在本项目同时指「器道」与「灵气」。这里按四艺面板的叫法用（`qi` = 炼器），未改名以免动存档结构。
2. **本地双倍权重**：用「池里多放一份」实现，不是新机制。代价是 `encPoolFor` 返回的池有重复 id——测试按重复槽位验权重，不去重。
3. **助战伤害按你的战力折算**，不按 `foe.hpMax` 百分比：后者会让「越境助战」变成万能钥匙，与方案「不加新框架」的意图相悖。
4. **地点事件不覆盖神道**：五洲专属事件里没有神道专属条目（神道玩家仍走通用池 + 庙宇线）。这属于 P1-2 的合理边界，不是遗漏。
