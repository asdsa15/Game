## 一、手机端：修了 4 处

### 1.1 【严重】对战时「遁」被挤出首屏

```css
/* 旧 */
.fightacts{grid-template-columns:1fr 1fr}
@media(max-width:520px){.fightacts{grid-template-columns:1fr}}   /* ← 手机上一列 */
```

手机视口 412/496 都小于 520，所以行动区变成**一列 6 行**：

| 指标 | 修前 | 修后 |
|---|---|---|
| 每行按钮 | **1** | **2** |
| 行动区高 | 约 350px | **154px** |
| 第 5 个按钮（遁）底边 | 约 700px（屏幕外） | **600px（首屏可见）** |

**「遁」是这个游戏的保命键。** 它被推到首屏之外，等于让玩家在最危险的一回合找不到逃跑按钮——而这一回合往往决定死档。

修法：断点从 520 降到 340（其中 412 的手机保持两列），并给手机两列加了紧凑尺寸（`.opt` 46px 高、说明文字省略号收尾）。

### 1.2 【严重】指令坞排在页面最底部

```css
/* 旧：中栏 → 纪事 → 状态 → dockrow */
.stage:not(.stage-fight) > .col:nth-of-type(1){order:2}  /* 纪事 */
.stage:not(.stage-fight) > .col:nth-of-type(2){order:1}  /* 选项 */
.stage:not(.stage-fight) > .col:nth-of-type(3){order:3}  /* 状态 */
.stage:not(.stage-fight) > .dockrow{order:4}             /* ← 指令坞垫底 */
```

手机上想点「功法」「坊市」，得先滚过**纪事（725px）＋状态（648px）**两栏。

修后顺序：**选项 → 指令坞 → 纪事 → 状态**。实测确认：`页面顺序: col → dockrow → col → col`。

### 1.3 指令坞太高（396px → 242px）

12~15 个按钮 × 4 列 × 93px 高 = 396px，占 907px 视口的 **44%**。

修法（`@media(max-width:560px)`）：内边距 12→7px、图标 26→22px、字号降一档、副标题单行省略号。

| 项 | 修前 | 修后 |
|---|---|---|
| 单格 | 114×**93** | 114×**77** |
| 12 个按钮总高 | 396px | **242px** |
| 13 个按钮总高 | 396px | 325px |

（`≤360px` 才彻底隐藏副标题——之前是 400px，而 Ace 2 是 412，等于从没生效过。）

### 1.4 顶栏「系统」按钮触控目标 36px → 40px

`.sysbtn-top{min-height:36px}` 仍低于 40px 下限。已改 40px。
（注：这条只在 `(pointer:coarse)` 下生效，无头浏览器报 `pointer:fine`，所以实测仍是 29px——真机上才是 40px。）

### 3.2 【重要】往死函数里加代码，界面毫无反应

修 1.2 时把「人情 / 征兆」加进了 `renderStatus()`，实测却发现状态卡里什么都没有：

```
含 人情 欠=yes        ← 这是指令坞的「人情」按钮，不是状态卡
含 征兆(数你的呼吸)=NO
```

原因：右栏真正渲染的是 **`renderStateCol()`**，而 `renderStatus()` **从未被调用**（6,009 字符的死代码）。

已修：
1. 人情与征兆改写进 `renderStateCol()`
2. **删除 `renderStatus()`**，原位置留一段注释说明为什么删

留死代码在这里不是"占点空间"，是**下一个人（或 AI）还会改错函数**——这次就发生了。

### 3.3 顺带加的两道保险

| 保险 | 内容 |
|---|---|
| 气血归零兜底 | `render()` 开头若 `phase==='play' && hp<=0` → 直接 `die()`。目前只有 `foeTurn` 会打到 0 并立刻处理，但"状态机漏出口"是本作栽过三次的坑 |
| 同步防呆 | `sync_apk.py`：产物比源码旧就 `exit 1`；HTML 内容未变则**不递增** versionCode（调试期反复同步把版本从 625 抬到了 630） |

## 六、这一轮的方法论

三条都是这轮实际踩出来的：

**① 肉眼看着"没问题"，实测才发现一行 `@media` 把 6 个按钮堆成了一列。**
所有布局结论都来自 `getBoundingClientRect`，不靠看截图。截图只能证明"像素存在"，不能证明"元素在视口内"。

**② 改 UI 之前先确认哪个函数在真正渲染。**
`renderStatus` 与 `renderStateCol` 同时存在、内容高度相似，我改错了那个。删掉死函数比加注释更可靠。

**③ 自己的探针也会骗人。**
中途测到"索债弹窗底边 997 > 907 溢出"，结论是**探针自己造成的**（先 `openHooks` 再手动删 `.box`，残留了一个空 overlay）。干净复测后底边 897，正好贴合。**报 bug 之前先怀疑测量方法。**
