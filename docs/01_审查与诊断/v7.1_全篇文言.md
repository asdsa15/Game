## 一、先回答：能不能写古诗

能。我用的不是严格近体（不强行套平仄谱），是**古风**：守五点——

1. **五言或七言为主**，两句成联，上句落仄、下句落平
2. **对仗**（名词对名词、数量对数量），但不为对而对
3. **一句一个具体物**：冷馒头、伞骨、香灰、蒲团、槌子、骨烬
4. **不解释情绪**——写"手不抖"，不写"他很冷静"
5. **不用生僻字**。玩家是在玩，不是在考据

上一版的问题正是第 4、5 条之外的另一种病：**很多"诗"其实是白话短句分行**。比如：

> 铸基那一夜没有风。你听见体内有什么东西落定。

这是好句子，但不是诗。这次改成：

> 铸基是夜无风起，唯闻身内有物沉。

## 四、一个必须记下的事故

**这次我把 data.js 从 2,276 行砍到了 1,255 行。**

原因：替换 VERSES 时，我用

```python
i = d.find('    breakXian: [')     # ← 定位到了 LITURGY 里的同名键（第 536 行）
j = d.find('    places: {', i)     # ← 定位到了 46,814 字符之后的另一个 places
d = d[:i] + NEW + d[j:]            # ← 中间全部删除
```

`TRANSMISSIONS`、`ENCOUNTERS`、`SCENES`、`SECT` 四张表连同大量数据一起没了。`node --check` 仍然通过——因为删掉的是一整段合法的数组。

**恢复**：从 `_backup/wxcs3-data.js.bak-preclassic` 还原，再重做。

**防住的两次**：

1. 加距离断言
```python
assert j > i and j - i < 4000, 'VERSES 区间异常：%d~%d' % (i, j)
```
第二次跑立刻报 `VERSES 区间异常：31330~78144` —— 断言把人拦在了删数据之前。

2. 改为「从 `const VERSES` 之后搜索」
```python
vi = d.find('const VERSES')
i = d.find('    breakXian: [', vi)
```

**另一个坑**：成就条目以 ` },` 收在**同一行**，我用 `\n    },` 找块尾，一个都匹配不到（所以第一次报 0/108）。必须用「下一个条目 `\n    {`」或「数组结尾 `\n  ];`」作边界。

**结论**：批量改文本时，`node --check` 只能证明语法合法，证明不了数据还在。**每一项批量替换都要有"改前/改后条目数"的断言**，否则删掉半张表和改对一条诗报的是同一种成功。
