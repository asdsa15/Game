# 动工决策：把「时间」变成预算

> 日期：2026-11-17
> 前情：`v8.0_对标研究_12个样本.md`（12 个样本）、`v8.0_系统闭环诊断.md`（死字段与断链）
> 本文回答一个问题：**下一步从哪儿动工，为什么是这里。**

---

## 一、先修正此前的判断

前两轮的诊断说了两件事：死字段多、因果链断。这两件都对，但都是**症状**。

把它们修完之后，手感并不会变好。因为真正的问题在更下面一层：

> **这个游戏里的「时间」不是资源，是奖励。**

证据有三条，都是代码级的。

### 1.1 修为是时间的函数，不是选择的函数

```js
function monthXiuwei() {
  let v = r.base * qi * qual * root * gf * zt;
  if (S.body === 'dao') v *= 1.5;
  if (S.lu && S.lu.name === '行气吞灵') v *= 1.2;
  if (S.cultivation === 'both') v *= 0.8;
  if (S.meditate) v *= 2;        // ← 唯一的「你做了什么」开关
  if (S.cultBonus > 1) v *= S.cultBonus;
  return v;
}
```

这个公式里，**没有一项是「你本月做了什么」**。它只认：你是什么境界、什么灵根、什么功法、什么灵气环境。
而 `advanceMonth()` 一到月就把这笔修为加进 `S.xiuwei`：

```js
if (isXian() || S.cultivation === 'both') {
  const g = monthXiuwei();
  S.xiuwei += g;                  // ← 躺着不动也涨
}
```

而 `ACT.cultivate`（主界面的「打坐采气」）做了什么？

```js
ACT.cultivate = () => {
  S.meditate = false;
  const bx = S.xiuwei;
  advanceMonth(1);                // ← 全部内容就是「过一个月」
  const dx = S.xiuwei - bx;       // 然后报告「涨了多少」
  ...
};
```

**「打坐」按钮本身不产出任何东西。** 它只是在读一个已经自动发生的结果。
玩家点它，和点任何别的会过月的按钮，得到的修为完全一样。

这就是为什么「打坐攒修为」会变成唯一解——因为它其实是「跳过时间」，而时间就是修为。

### 1.2 八成动作不花时间

扫全部 155 个 `ACT` 动作，只有 30 个调用了 `advanceMonth`：

```
ACT 动作总数 155 ｜占月份 30 ｜不占 125
```

不占月份的动作里包括：

| 类别 | 动作 | 问题 |
|---|---|---|
| 买卖 | `do_buy` `do_sellitem` `do_sellmat` `do_miaobuy` | 无限次买卖，只要有钱 |
| 装备 | `do_equip` `do_eqsk` `do_setgf` | 换功法瞬息完成 |
| 家族 | `do_ind` `do_clanup` `do_clanabsorb` | 经营族产不花时间 |
| 人情 | `do_talk` `do_ask` | 送礼论道不花时间 |
| 道书 | `do_readbook` `do_buybook` | 读书不花时间 |
| 四艺 | `do_craftart` `do_equip` | 学艺不花时间 |
| 破境准备 | `do_prep` `do_xbreak` | 择地备药护法全免费 |

**结果是：除了那 30 个按钮，其余系统都是外挂。** 玩家可以在一个「月」里把坊市逛十遍、把族人都派出去、把该读的书全读完，时间一格都不动。

### 1.3 属性不进文本，也不进选择

`道心/悟性/资质/机缘/神识/身法` 六个数字，只出现在公式里。
它们不影响你能看到什么、能选什么、NPC 怎么对你。

对照《活侠传》：性情/处世/道德/修养四轴各五档，
「偷看洗澡」「杀人越货」这类选项**只有坏人个性才出现**；
同一段剧情，性格不同，台词与选项全不一样。
它的 120 万字里很大一部分是这么乘出来的。

## 二、三处「假」的共同根因

把上面三条并排看：

| 症状 | 直接原因 | 根因 |
|---|---|---|
| 打坐是唯一解 | 修为由时间自动产出 | **行动不稀缺** |
| 系统都是外挂 | 125 个动作免费 | **行动不稀缺** |
| 属性没有存在感 | 属性不进文本 | 属性只影响「效率」，而效率不稀缺 |

三个症状，同一个根：**没有任何东西是稀缺的。**

- 如果行动稀缺 → 修为就必须由「把旬花在打坐上」产生，修为重新变成选择的函数
- 如果行动稀缺 → 125 个免费动作就必须竞争，做事开始有成本
- 如果行动稀缺 → 属性就该决定「同样一旬能换到多少」，属性才有意义

所以第一刀必须切在这里。**在这之前加任何内容（师徒、御兽、对象槽、属性分档），都只是往漏的桶里加水。**

## 三、外部参照：他们怎么做的

| 作品 | 时间单位 | 每单位行动数 | 什么要花行动 | 内容单元 |
|---|---|---|---|---|
| **Fallen London** | 实时 | 烛火 20 点，10 分钟回 1 | **一切**，连「走到某个地点」都要 | 2000+ storylet |
| **活侠传** | 月 → 上/中/下旬 | 每旬 3 点，月 9 点 | **一切**：练功、打铁、炼丹、下山采买 | 120 万字 / 49 结局 |
| **太吾绘卷** | 月 | 1 主行动 + 脚程耗日 | 走路也耗 | — |
| **修仙模拟器** | 月 | 弟子每月批次行动 | 修炼、采集、建设 | — |
| **本项目** | 月 | **1 行动** | **30 / 155 个动作** | 45 动作 / 22 事件 |

两处关键差异：

**其一，他们把所有事情都放进同一个预算。** Fallen London 的 2000 段 storylet 共享 20 点行动；
活侠传的九处设施共享每月 9 点。所以「做这个就不能做那个」是结构性的，不是文案写出来的。

**其二，他们有「不做事就要付代价」的机制。** 活侠传每月固定扣 30 贡献，贡献不够会触发坏结果——
所以你必须在「赚贡献」和「练功」之间分配。这就是时间pressure（时间压力）。

我们这两样都没有：既没有共享预算，也没有固定开销。所以「时间」是白给的。

## 四、方案：月拆三旬

### 4.1 核心规则

```
1 月 = 上旬 / 中旬 / 下旬，共 3 旬
每旬 = 1 次行动

打坐 1 旬      → 修为 + 月修为 ÷ 3
全月打坐 3 旬  → 月修为（与现状完全一致）
做一件事 1 旬  → 少 1/3 月修为
整理（买卖/装备/看面板/翻背包）→ 免费，不限次
```

### 4.2 为什么是「3」而不是「9」

因为这个项目现有的全部数值，都是按「1 月 1 次打坐」校准的。

- 若拆成 3 旬且打坐 1 旬 = 月修为 ÷ 3，**全月打坐 = 月修为，曲线完全不动**
- 若拆成 9 点（学活侠传），全打坐 = 3× 月修为，所有境界时间缩短三分之二，曲线崩

所以 3 是唯一能不重算数值的选择。**这一步是纯结构改动，不是数值改动。**

### 4.3 这一刀改变了什么

| 系统 | 之前 | 之后 |
|---|---|---|
| 丹药 | 有材料就能炼，无限次 | 炼一炉 = 1 旬 = 少 1/3 月修为 |
| 护法 | 好感够就请，免费 | 请人一趟 = 1 旬 |
| 家族派遣 | 免费下达指令 | 安排族人 = 1 旬 |
| 宗门任务 | 白拿贡献 | 1 旬换贡献，机会成本显性化 |
| 四艺 | 学艺不花时间 | 学一门 = 1 旬 |
| 破境准备 | 择地备药护法顺手做 | 准备本身要占旬，**准备度成了真正的取舍** |
| 寿元 | 120~700 年，升境只要 1.5~42 年 | 每一旬都在消耗寿命，**命开始值钱** |

### 4.4 明确不做的事（这一轮）

- **不改数值**：月修为、境界需求、物价一律不动
- **不加内容**：不新增事件、不新增意图、不新增系统
- **不动战斗**：战斗本来就占月，这次只把它换成占旬
- **不加「不做事就受罚」**：固定开销（宗门月课、家族吃口）留到下一轮，先让「预算」成立

## 五、实现路径与风险

### 5.1 分五步

| 步 | 内容 | 风险 |
|---|---|---|
| 1 | 新增 `XUN_PER_MONTH = 3` 与 `advanceXun()` | 低 |
| 2 | 修为从 `advanceMonth` 的自动结算改为「打坐动作产出」 | **高**（影响所有依赖过月涨修为的路径） |
| 3 | 30 个「占月」动作改为「占旬」 | 中 |
| 4 | 界面显示当前旬与剩余行动 | 低 |
| 5 | 回归 240 项断言 + 数值平滑验证 | — |

第 2 步是唯一的高风险点。原因是：现在很多路径依赖「过月自动涨修为」——
闭关、被迫过月、事件推进、NPC 来访。改成「打坐才涨」之后，这些路径要么补上修为、要么明确不给。

处理原则：

- **主动打坐 / 闭关** → 按旬给修为（闭关 ×2 按原样保留）
- **被动过月**（事件、战斗、旅行的耗时）→ 不给修为，只推进时间
  这正是想要的：**时间流逝本身不带来成长，只有修行才带来成长**

### 5.2 回退方式

`XUN_PER_MONTH` 设成 1，即回到「1 月 1 行动」的旧行为。
所有改动集中在这一个常量与 `advanceXun()` 内，其余调用点只换了函数名。

### 5.3 验证口径

| 验证项 | 期望 |
|---|---|
| 3 次打坐的总修为 | = 改前的 1 月修为（±1 以内） |
| 从胎息到金丹的总月数 | 与改前一致（全打坐路径） |
| 做一件事后的修为 | = 月修为 × 2/3 |
| 测试断言 | 240 项全绿 |

## 六、这一轮之后，下一轮该做什么

行动预算成立之后，优先级会变。新的顺序：

1. **固定开销**（宗门月课、家族口粮、庙宇香火）——让「不做事」有代价，
   与「做事有成本」配对，时间压力才真正闭合
2. **对象槽**（Verb + Card）——现在做事有成本了，才谈得上「用什么去做」
3. **属性分档出文本**——属性直接影响「这 1 旬能换到什么」，然后才谈影响文本
4. **瓶颈**——修为满不等于能破，把道书/悟道接进主线
5. **师徒**——最后再做，因为它需要前面几样都成立才有意义

这个顺序与上一份文档不同。上一份把「对象槽」排第一，是在假设「系统已经会竞争」的前提下——
现在看清了那个前提不存在，顺序必须改。

---

## 七、一句话总结

> 之前所有修复都是在给系统「接线」。
> 但线接好了，电没通——因为**没有一处是稀缺的**。
> 这一刀把「月」拆成「旬」，让每一次行动都标上价格。价格一出现，取舍才出现。

## 八、实施记录（同日落地）

### 8.1 改了什么

| 位置 | 改动 |
|---|---|
| `wxcs3-game.js` 常量 | 新增 `XUN_PER_MONTH = 3`、`XUN_NAME`。**这是唯一的回退开关**：设成 1 即回到「一月一行动」 |
| `newGame` | 新增 `S.xun`（本月已过几旬）、`S.xiuAcc`（修为小数累积器） |
| 新增 `advanceXun(n)` | 全项目唯一的时间入口。跨旬不结算世界，跨月才走 `advanceMonth()` |
| 新增 `gainXiuwei(v)` / `gainXianghuo(v)` | 带累积器，保证「三旬之和 = 一月」不漏掉零点几 |
| `advanceMonth` | **移除修为与香火的自动结算**，只留世界变化（寿元、家族、行情、维护、信众生灭） |
| `ACT.cultivate` | 改为「打坐到月末」：自动填满剩余旬，修为 `+月修为×(余旬/3)`。**不拆成一次一旬**——打坐本身没有决策，点一千多次不是取舍是折磨；有决策的是「这一旬拿去打坐还是做事」 |

| 读书 / 扩祠堂 / 吸纳族人 / 升灵脉 / 建作坊 / 宗门晋升 / 学功法 | 各自接上 1 旬成本 |
| `timeLine` | 追加「上旬 / 中旬 / 下旬」 |
| `renderMainCol` | 场景下方加旬数条（已过划掉、当前高亮、右侧余几旬）；打坐按钮写「（一旬）」，满修时写「已满 · 白坐一旬」 |
| 存档迁移 | 旧档补 `xun` / `xiuAcc` 默认值，修为进度不需要折算 |
| 新手引导 | 第一条改成「一月三旬，每旬只够做一件事……做事就少修行」 |

### 8.2 验证

```
数值平滑（新写 /tmp 脚本单点验证）
  胎息  三次打坐 6+7+7 = 20  ← 与改前「一月」的月修为一致
  筑基  三次打坐 6+6+6 = 18
  金丹  三次打坐 5+5+5 = 15

行为（同一局对比，胎息·天灵根）
  纯打坐一个月：修为 20，时间走到次月上旬
  采集一旬 + 打坐两个月：修为 13   ← 少掉的 7 点就是那趟山的价格
  打两件事 + 打坐：修为 6~7（只剩三分之一）

断言
  test_econ 27 · smoke_econ 26 · test_play 14 · test_hooks 32
  test_v80 92 · test_text 18 · test_loops 44（+13 项行动预算）
  合计 253 通过 / 0 失败，连跑两轮稳定
```

新增的 11 项断言钉住了这件事：三旬进一月、一旬给三分之一、**做事的一旬不涨修为**、
世界按月而非按旬结算、界面必须写出剩余旬数、闭关吞掉余旬。

### 8.3 一个必要的连带改动

`maybeEvent()` 开头加了 `if (S.phase !== 'play') return;`。

原因：`advanceXun` 可能在推进中触发 `die()`，而好几处写法是
`advanceXun(1); maybeEvent(); render();`。原来的 `advanceMonth` 也有同样风险，
只是没暴露出来。这次顺手堵上。

### 8.4 仍然没解决的（下一轮）

1. **不做事没有代价**。现在「做事有成本」成立了，但「不动也一样」——
   还是要把时间花掉。活侠传靠「每月固定扣 30 贡献」制造这个压力。
   对应到本项目，是**固定开销**：宗门月课、家族口粮、庙宇香火、洞府维护。
   **这是下一轮的第一件事**，做完时间压力才真正闭合。
2. **免费动作仍多**。买卖、装备、派遣、看面板保持免费是对的（那是整理不是做事），
   但还有一些「做事」性质的没接旬成本，比如愿物制作、部分 NPC 交互。
   下一步应该做一次完整分档，并写进文档，而不是散在代码里。
3. **3 旬是否够**。现在一个月只能做三件事，系统不少，可能会显得紧。
   若手感偏紧，把 `XUN_PER_MONTH` 改成 6 即可——`gainXiuwei` 按 `/XUN_PER_MONTH`
   折算，全月打坐的量不变。**改这一个数就行，不需要动别的地方。**
4. **旬的概念还没有叙事重量**。它现在只是计量单位。真正的旬应该有自己的
   事件（比如「上旬的集市」「下旬的庙会」），这是内容层的事。

### 8.5 一句话

> 改之前，时间是白给的；改之后，时间是标价的。
> 「打坐」从「跳过一个月」变成了「用一旬换三分之一个月」——
> 这一句变化，让后面二十几套系统第一次开始互相抢东西。


### 8.6 落地的分档表

`docs/03_玩法设计/行动预算_分档表.md` 写了每个动作的时间口径：
42 个占旬、113 个免时间、0 个未分类。

配套 `tools/check_time.py` 会扫全部 `ACT` 方法，
读那份文档做比对——**新增动作如果既不占旬、又没写进分档表，检查就红**。
这样「这件事要不要时间」变成一个必须回答的问题，而不是随手就漏。
