## 二、乘区注册表（扩展协作的核心机制）

多个扩展要改同一处数值时互相不知道对方，因此 fate.js 提供
`EXT.registerMul(kind, fn)` / `EXT.registerAdd(kind, fn)` 注册表；
`game.js` 薄缝 `fateMul(kind)` / `fateAdd(kind)` 逐个询问注册者并连乘/累加：

- 乘区 kind：`pill`（丹药效力）/ `cult`（修炼收益）/ `sword`（剑系）/ `tal`（符系）/
  `xs`（香火）/ `dmg`（承伤）/ `loot`（缴获）/ `venv`（因果反噬）
- 加区 kind：`book`（读书感悟）/ `flee`（遁走）/ `defl`（卸力）
- 命格效果在 fate.js 注册；风劫余波（未淬体者破境后三旬修炼减半）在 trib.js 注册 `cult`。

## 三、关键实现点

1. **候选取向行为不取向数值**：`EXT.fateCandidates()` 按 `score(S)` 排序取前三，
   打杀多者见血债、服丹多者见丹火、功德厚者见万象；重悟时排除旧痕。
2. **天劫在开面板时掷定**（`openXianBreak` 顶部 `S.trib = rollTribulation()`），
   而非点破境时——预览的「劫类/克法/缺口/成功率/此劫若败」才有针对性；`do_xbreak` 不重掷。
3. **方案红线修复**：无灯焰（huo）原本只认神道庙宇，现 `(S.arts||[]).length > 0`
   即给仙道法器 0.10 克法加成——「每劫仙神都有克法」达成。
4. **失败余波逐劫落账**：雷劫心魔（heartBreak++）、水劫修为折二成、火劫卸下法宝或损 150 石、
   风劫三旬修炼减半（`S.fengUntil` 绝对旬计数 `S.turn*3+S.xun+3`）、骨劫人身因果（pendingVengeance）。
5. **重悟占旬**：`fate_rr` 走 `advanceXun(1)`、修为散到本境三成、一世一次（`S.fateReroll`），
   已登记入 `docs/03_玩法设计/行动预算_分档表.md`（命格分档）。
6. **旧档兜底**：`applyState` 补 `out.fate / out.fateReroll`，`newGame` 同步初始化。
