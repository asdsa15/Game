## 二、卡死诊断

### 2.1 复现步骤

1. 进战斗，把气血打到只剩十来点；
2. 点「攻击」，敌方回合把你打到 0；
3. **此时界面停在战斗面板，8 个按钮全部失效，只有顶栏「系统」还能点。**

或者更常见：气血归零后掷骰落在「重伤昏迷」那 60%，同样冻结。

### 2.2 根因

`foeTurn()` 有三个出口，只有第一个能正常回到界面：

```js
// 2424  function foeTurn()
    if (S.hp <= 0) {
      if (Math.random() < 0.4) { die(`被${c.foe.name}当场击杀，血溅当场。`); return false; }   // 出口 A
      S.combat = null; S.phase = 'play'; S.hp = 1;                                            // 出口 B
      S.stones = Math.floor(S.stones * 0.5);
      S.followers = Math.round(S.followers * 0.6);
      logLine('重伤昏迷。醒来时财物尽失。', 'danger');
      toast('重伤 · 财物被劫');
      return false;                                                                           // ← 没有 render
    }
    c.round++;
    return true;                                                                              // 出口 C（正常）
```

调用方：

```js
// 2516
    if (!foeTurn()) return;      // ← 直接 return，整个 render() 被跳过
    render();
```

于是：

- **出口 A（战死）**：`die()` 只把 `S.phase` 改成 `'over'`，界面不刷新。玩家看到的还是战斗面板，而 `ACT.do_cbt` 的第一行 `if (!c) return;` 又拦不住（`S.combat` 还在），于是每次点击都在"血量已是 0 → 再死一次 → 不刷新"里空转。
- **出口 B（昏迷）**：`S.combat` 被清空、`phase` 改成 `'play'`，但界面仍旧是战斗面板。此时**所有按钮都走 `do_cbt`，而它第一行 `if (!c) return;` 直接静默退出**——连「遁走」都点不动。

这就是"卡死"：**内存里的局面早就结束了，屏幕上的画面还在，两者失去同步。**

### 2.3 为什么不是浏览器卡死

顶栏在 `#stage` 之外（HTML 第 5 行 `.topbar`），`act:openSys` 不检查 phase，所以「系统」按钮始终可用，能读档或重置。所以这是**软锁（soft lock）**，不是进程假死——但对玩家来说体验一样。

### 2.4 修复（3 行）

**补丁 1 —— 调用方兜住返回 false 的情况**（`2516`）

```js
// 改前
    if (!foeTurn()) return;
    render();

// 改后
    if (!foeTurn()) { render(); return; }
    render();
```

`render()` 会按 `S.phase` 分流：`'over'` → 结算面板；`'play'` → 三栏主界面。两条出口都能正确落地。

**补丁 2 —— 渲染层兜住"phase 是 combat 但 combat 已空"**（`403`）

```js
// 改前
    if (S.phase === 'combat') { stage.innerHTML = renderCombat(); renderDial(true); scheduleAutoSave(); return; }

// 改后
    if (S.phase === 'combat') {
      if (!S.combat) { S.phase = 'play'; }        // 脏状态直接降级，走下面的正常渲染
      else {
        stage.className = 'stage stage-fight';     // 双栏（见第四节）
        stage.innerHTML = renderCombat();
        scheduleAutoSave();
        return;
      }
    }
```

**补丁 3 —— 三条"只提示不刷新"的静默 return 也补上 render**（`2471 / 2477 / 2478`）

```js
    if (S.mp < 25) { toast('灵力不足'); render(); return; }
```

虽然这几条不会锁死，但玩家连点三次"施法"毫无反馈，主观上就是卡了。

### 2.5 顺手把出口 B 的时间线补齐

昏迷与击杀都调用了 `advanceMonth(1)`，唯独昏迷没调用，导致"重伤醒来世界没动"。建议在 `S.hp = 1` 之后补 `advanceMonth(1);`——但注意 `advanceMonth` 内部有可能再次 `die()`（寿元耗尽），所以顺序应为：先 `advanceMonth(1)`，再判断 `S.phase` 是否已变成 `'over'`，最后才 `render()`。

## 三、为什么"只有一个血条就完了"

这是布局问题，不是内容问题。

```css
.stage{ display:grid; grid-template-columns: 272px minmax(0,1fr) 312px; }   /* HTML 42~49 */
```

主界面靠这三列放下"天时·纪事 / 主面板 / 状态"。战斗时 `stage.className` 依然是 `'stage'`，而 `renderCombat()` 返回的是**一个** `<div class="panel">`——它被放进**第一列 272px**，右侧约 600px 完全空着。

所以你看到的不是"战斗界面简化了"，而是**一个本该 900px 宽的面板被塞进了 272px 的窄条**：血条被压到最短、选项挤成一列、名字和数值换行。截图里那一小条正是这个。

## 四、双栏对战界面设计

### 4.1 线框

```
┌──────────────────────────────────────────────────────────────┐
│ 敌方 · 高你半境                        │ 我方 · 均势          │
├────────────────────────────────────────┼──────────────────────┤
│ 游方邪修                                │ 清微                 │
│ 紫府·一关 · 高你半境                    │ 筑基·后期 · 战力 96  │
│ ──────────────────────────────────────  │ ──────────────────── │
│ 气血 ████████████░░░░  264/400          │ 气血 ███████░░░░  76/100│
│ 战力 420            火                  │ 灵力 █████░░░░░░  42/100│
│ 状态 无                                 │ 功法《聚气诀》        │
│                                        │ 状态 守势（减伤50%）  │
├────────────────────────────────────────┴──────────────────────┤
│ 第 3 回合 · R=0.23 · 劣势                                     │
│ ┌──────────────┬──────────────┐                               │
│ │ 1 攻击  风险  │ 2 施法  平和  │                               │
│ ├──────────────┼──────────────┤                               │
│ │ 3 权柄  平和  │ 4 防御  平和  │                               │
│ ├──────────────┼──────────────┤                               │
│ │ 5 遁走  风险  │ 6 观察  平和  │                               │
│ ├──────────────┼──────────────┤                               │
│ │ 7 用丹  平和  │ 8 说话  机缘  │                               │
│ └──────────────┴──────────────┘                               │
└──────────────────────────────────────────────────────────────┘
```

要点：

- **左右等宽**，一人一卡，视线左右一扫就知道"我剩多少、他剩多少"；
- 气血条在两张卡里**同色系但不同色**（敌朱砂、我石绿），不靠文字分辨；
- 位格差与胜算档位**各放一处**：敌卡标题右侧写位格差，我卡标题右侧写胜算档——这两件事玩家最容易混，分开放反而清楚；
- 行动区**通栏两列网格**，8 项从竖排 8 行压到 4 行，高度省一半，且不再被 272px 挤成一条。

### 4.2 卡片字段与取值来源

| 卡片 | 字段 | 取值 |
|---|---|---|
| 敌 | 名号 | `c.foe.name` |
| 敌 | 位格折算 | `posText(c.foe.rank)` → 如「紫府·一关」 |
| 敌 | 位格差 | `diff = c.foe.rank - positionRank()` 六档文案 |
| 敌 | 气血条 | `bar(c.foe.hp, c.foe.hpMax, 'var(--cinnabar)')` |
| 敌 | 战力 / 五行 | `fmtNum(c.foe.power)` / `elemChip(c.foe.el)` |
| 敌 | 状态 | 恒「无」（敌人不会防御，除非后续扩展） |
| 我 | 道号 | `S.dao \|\| S.name` |
| 我 | 境界 / 战力 | `realmName()` / `fmtNum(computePower())` |
| 我 | 气血 / 灵力 | `bar(S.hp,S.hpMax)` / `bar(S.mp,S.mpMax)` |
| 我 | 香火（仅神道） | `bar(S.xianghuo, pillar().need, 'var(--cul)')` |
| 我 | 功法（仅仙道） | `getGongfa().name` |
| 我 | 状态标签 | 守势 / 下回合必中 |

### 4.3 位格六档文案

现有代码只有 `>=8 / >=4 / >=2 / 0` 四档，`diff===1` 被归进"你位格更高"，是错的（高你 1 档当然是劣势）。改成六档：

| diff | 文案 | 颜色 |
|---|---|---|
| ≥8 | 高你两个大境以上——你根本伤不到他 | 朱砂 |
| ≥4 | 高你一个大境 | 朱砂 |
| ≥2 | 高你半境 | 朱砂 |
| 1 | 略高于你 | 常规 |
| 0 | 同阶 | 常规 |
| <0 | 你占上风 | 石绿 |

### 5.5 `keMul` 修正（2257~2265）

`ELEMENTS` 里没有 `ke` 这个键，`ke` 是每个元素自己的属性。三行改完，五行相克才真正生效：

```js
  function keMul(myEl, foeEl) {
    if (!myEl || !foeEl) return 1;
    const me = D.ELEMENTS[myEl];
    if (!me) return 1;
    if (me.ke === foeEl) return 1.3;                  // 我克敌
    const fo = D.ELEMENTS[foeEl];
    if (fo && fo.ke === myEl) return 0.85;            // 敌克我
    return 1;
  }
```
