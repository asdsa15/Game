## 三、剩余缺陷

### 3.1 P0 · 金丹后证果位入口缺失

**现象：** 紫府最后一关渡过后，角色进入金丹（`xRealm=4`），但主界面 B 位显示「闭关快进」，不显示「设法仪证果位」。鼠标玩家在金丹阶段找不到继续主线（果位 → 道胎）的入口。

**证据链：**

1. `do_zifu()` 第三关成功只写 `S.xRealm=4`，没有调用 `openJindan()`，也没有设置 `S.guowei`（`3344-3368`）。
2. `renderMainCol()` 的 `full` 计算为：
   ```js
   // 821
   const full = isShen() ? (S.xianghuo >= pillar().need)
                         : (xrealm().need && S.xiuwei >= xrealm().need);
   ```
   金丹 `need=0`，`full` 恒为 false，于是 B 位落入 `闭关快进`（`823-829`）。
3. 「设法仪证果位」标签只在 `full` 为 true 时才生成（`823-825`）；`canDaotai()` 又要求 `S.guowei`（`3272`），所以底部也没有「化道胎」入口。
4. `openJindan()` 只在 `ACT.openBreak()` 的 `xRealm===4` 分支里调用（`1249-1265`）；键盘 `B` 可以绕过（`KEYMAP`），但界面没有提示。

**实测：**

```
紫府后: xRealm=4 xStage=0 guowei=false
主界面含「设法仪证果位」: false   含「闭关快进」: true
键盘/直达 openBreak 后弹窗含果位: true  标题: 金丹 · 果位
```

**影响：** 鼠标玩家会在金丹阶段以为主线结束；果位、道胎、锚系统、大部分结局仍无法自然进入。

**建议：** 让 `do_zifu()` 第三关成功后直接 `openJindan()`；或把 `full` 改成 `!xrealm().need || S.xiuwei >= xrealm().need`，并在 `xRealm>=4 && !S.guowei` 时始终显示「设法仪证果位」。同时给 `canDaotai` 之外补一个常驻入口。

#### P1-2　四艺品阶门槛全部失效，玄阶以上配方不可制作

**证据：**

```js
// 5064-5068
function canCraftTier(tier) {
  const myTier = tierIdx(craftTierOf(null));   // ← 永远是黄阶
  const gate = D.CRAFT_REALM_GATE[tier] || 0;
  return tierIdx(tier) <= Math.max(myTier, 0) && S.xRealm >= gate;
}
```

`craftTierOf(null)` 读 `S.craftLv[null]`，为 `undefined` → 取 `CRAFT_LEVELS[0].tier = 'huang'`。因此 `myTier` 恒为 0，玄/地/天/仙配方全部被判为「技艺/境界不足」。

**实测：** `xRealm=5`、四艺全部 9 品、配方全部已学，玄阶「生肌续骨丹」仍显示 `disabled` 和「技艺/境界不足」。

**影响：** 四艺只能做黄阶配方；炼器、阵法、高阶丹药、高阶符箓全部不可制作，新系统大半失效。

**建议：** `canCraftTier` 接收配方所属的 `art`（如 `r.kind`），用 `craftTierOf(r.kind)` 计算 `myTier`；或把 `tier` 与 `art` 一起传入。

#### P1-3　坊市/奇遇得到的材料进入 `S.bag`，四艺读取的是 `S.bagMat`

**证据：**

- `do_buy()` 材料分支：`S.bag[it.id] = ...`（`1961`、`1968`）

bagMat = {}

**影响：** 玩家在坊市/奇遇里拿到的材料在乾坤袋里看得见、却无法用于四艺；四艺材料只能靠宗门任务或炸炉返料，经济链断裂。

#### P1-5　钩子 `blocked` 在存档/读档后不重置，债务永久卡住

**证据：**

- `tickHooks()` 到期后设置 `h.blocked = true`、`S.hookPending = h.id`（`5743-5745`）
- `applyState()` 已经清空 `hookPending`（`2707`），但**没有清空每个 hook 的 `blocked`**
- `tickHooks()` 遇到 `h.blocked` 直接 `continue`（`5730`）
- `openHookClaim()` 的弹窗没有关闭按钮（`noClose`），只能选还/赖/斩

**实测：** 存档中 `hookPending='hook_pill'`、`h.blocked=true` → 读档后 `hookPending=null`，但 `h.blocked` 仍为 true；此后该钩子不会再被 `tickHooks` 索债，`openHooks` 只显示「已到期」，没有可用按钮。

**影响：** 玩家在钩子弹窗出现时存档/刷新，债务会变成永久挂起的死状态；debuff 还在，但无法还/赖/斩。

**建议：** `applyState()` 中对 `out.hooks` 逐个 `blocked=false`；或在读档时重建 `hookPending`。

#### P1-6　道书「道心 +N」收益永远不会生效

**证据：**

```js
// 5319-5320
if (/道心 +(d+)/.test(gain)) {
  const m1 = gain.match(/道心 +(d+)/);
  S.stats.heart = clamp(S.stats.heart + parseInt(m1[1], 10), 1, 20);
}
```

正则写成了 `(d+)`，匹配的是字母 `d`，不是数字 `\d+`。数据里的收益是「道心 +2」「道心 +1」。

**实测：** 读《玄景残卷》第三层（数据 `道心 +2`），`heart` 从 10 仍是 10（应 12）；`阅历 +1` 分支正常。

**影响：** 道书所有「道心 +N」层都只显示文字、不加属性，玩家会认为道书收益失效。

**建议：** 改为 `/道心\s*\+\s*(\d+)/` 与 `/道心\s*[-−]\s*(\d+)/`；同时把「+」和「−」统一处理。

#### P1-9　高基础灵气地点升级灵脉会「扣钱不升级」

**证据：**

- `do_upqi()` 用 `lingqiUp` 计算花费与升级（`1831-1846`）：
  ```js
  const up = clamp(parseInt(S.lingqiUp, 10) || 1, ...);
  const cost = (up + 1) * 800;
  S.lingqiUp = up + 1;
  syncLingqi(); // S.lingqi = max(地点基础, lingqiUp)
  ```
- 在中州（地点基础 3）且 `lingqiUp=1` 时，升级后 `lingqiUp=2`，`max(3,2)=3`，**有效灵气不变**，但灵石已扣。
- `openCave()` 显示的花费是 `(S.lingqi+1)*800`（`1809`），与 `do_upqi` 按 `lingqiUp` 实际扣费不一致。

**实测：**

```
中州(基础3) 升级后 lingqi=3 lingqiUp=2 stones=3400
（花 1600，实际未升）
```

**影响：** 在高灵气地点升级纯亏钱；玩家会认为灵脉升级无效果。`灵脉契` 同样有此问题（`do_buy` 也是 `lingqiUp+1`）。

**建议：** 升级应基于「当前有效灵气」：`lingqiUp = max(lingqiUp, base) + 1`，或把地点基础与升级档统一成一个有效等级；`openCave` 的显示成本改用同一函数。
