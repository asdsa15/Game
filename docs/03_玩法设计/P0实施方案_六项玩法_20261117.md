### 2.2 功能门轻接线（新增项）

**现状核对**：功能门实际存在**两套**，一套活着、一套死了：

- 活的：`S.unlockStage`（0~8），初始化于 game.js:75，在 2118/2119、2294、2323、2407（神道按柱推进）、5189 等处升档，已实际挡住道统（:880）、神通（:895）、洞天（:1393、:1648、:4706）的显示；
- 死的：`UNLOCK_XIAN`（data.js:1611，7 档）/ `UNLOCK_SHEN`（data.js:1620，9 档），逐境列了 `show / hide / phrase` 三字段，data.js:3180 已导出，**game.js 零引用**（实测全文件 0 命中）。

**实测口径核对（rev2 补）**：`unlockStage` 的**全部**写入点如下，缺口一目了然——

| 行号 | 代码 | 触发 |
|---|---|---|
| 75 | `unlockStage: 0` | 初始化 |
| 2118 | `if (nr.idx === 2) → 3` | 晋筑基 |
| 2119 | `if (nr.idx === 3) → 4` | 晋紫府 |
| 2294 | `→ 5` | 证位晋金丹 |

- **仙道**：晋练气（`nr.idx === 1`）无写入，`unlockStage` 从 0 直接被推到 3 → stage 1（胎息·六轮）、stage 2（练气·九层）**永不可达**；
- **神道**：2407 在 `S.pillar++`（2407 之前于 2396 行）之后执行，`pillar + 1` 最小为 2 → stage 1（一柱·立庙）**永不可达**；
- 16 条 phrase 中 3 条（仙道 2 条 + 神道 1 条）永不触发。

**改法（做软门，不做硬门——硬门锁功能容易把老档锁死）**：

1. **补齐前两档写入点**（这是"接地"，不是改玩法）：
   ```js
   // resolveXianBreak 内，紧邻 2118：
   if (nr.idx === 1) S.unlockStage = Math.max(S.unlockStage, 2);   // 练气
   ```
   并在 `finishCreate`（game.js:7311 段）按道途置初值：
   ```js
   S.unlockStage = isShen() ? 1 : 1;   // 胎息 / 一柱·立庙，同一档位语义
   ```
   > 双修（`S.cultivation === 'both'`）走同一行，后续仙道、神道各自的推进点会分别抬档，不冲突。
2. **境界突破词**：抽一个 `unlockTable()`（按 `isShen()` 选表）+ `unlockRow(stage)`，在升档处把该档 `phrase` 写进 `logLine`（金色里程碑行）。**16 条 phrase 全部用上**，零风险的叙事接线。
3. **帮助面板分级**：`openHelp` 顶部新增"你如今能做什么"（渲染当前档 `show` 数组），底部新增"还未显于你面前之事"（渲染 `hide` 数组）。文档式引导，不锁任何按钮。
4. **对齐断言**（改成可执行的正向表述）：对 `UNLOCK_XIAN` / `UNLOCK_SHEN` 的每一档，断言"存在至少一条把它置为 `S.unlockStage` 的代码路径，且该路径可被执行"。实现方式用行为断言：按境界推进模拟到该档，断言 `S.unlockStage >= stage` 且该档 `phrase` 出现在 `S.log`。断言红，就是真有档位漏了接线，而不是像"全覆盖"那样写出来就红。

### 2.3 M2 · 淬体纵深

**现状核对**：`BODIES`（data.js:840）8 种体质只在创角选一次（game.js:952 渲染、:1509 附近写入），此后终身只有一个 `mul`；`injuryLevel`（game.js:5332）与 `monthlyHeal`（:5342）均不读体质阶数。

**rev2 实测补正**：`S.hpMax` **不是计算字段**，全部赋值点只有四处——43（`hp:100, hpMax:100`）、4765（`力贯千钧` ×1.3）、7311（`finishCreate`）、9348（`m_hand` +20）。初始值恒为 100，气血上限不随境界增长（境界只影响 `monthlyHeal` 的回血比例）。因此"`S.hpMax` 计算 × `hpMul`"无处可挂。

**改法**：

- data.js 新表 `QUENCH`（9 阶）：每阶 `{name, stonesCost, herbCost, hpMul, blockBonus}`，消耗随阶递增；`plain` 凡体也可淬（低资质逆袭线，参照云隐修仙录）。
- game.js：`S.quench = 0`（旧档缺省）；新 ACT `openQuench` / `do_quench`，入口挂**洞府面板**（不占指令坞位）；**每旬一次行动**（对齐 v8.0 旬预算，走《行动预算_分档表.md》的档位）。
- 生效点三处（按 rev2 口径落）：
  1. **气血上限改"写入侧乘"**：新档 `hpMax = (100 + hpFlatBonus) * QUENCH[S.quench].hpMul`；每次淬体只按**增量倍率**改一次（`hpMul_new / hpMul_old`），同时乘 `S.hp` 保持比值不变，并记 `S.quenchApplied`。4765（力贯千钧 ×1.3）与 9348（m_hand +20）两处不动，因为它们是"对当前上限"的增减，不参与淬体复利。
  2. 战斗卸力（`renderCombat` / `do_cbt` 伤害公式）+ `blockBonus`；
  3. `injuryLevel` 恶化速度按阶数减缓（读 `QUENCH[S.quench].blockBonus`，不改比值函数本身）。
- **老档迁移（必须在 `applyState` 内做）**：`injuryLevel` 按 `hp / hpMax` 比值分级（<0.15 濒死、<0.35 重伤、<0.65 轻伤）。若只抬 `hpMax` 不同步抬 `S.hp`，老档伤势会整体漂移。迁移规则：
  ```js
  // applyState 合并段内：只补"存档尚未兑现的阶差"，按增量倍率等比放大
  out.quench = st.quench || 0;
  out.quenchApplied = st.quenchApplied || 0;
  if (out.quench > out.quenchApplied) {
    const q = QUENCH, lo = q[Math.min(out.quenchApplied, q.length - 1)];
    const mul = q[Math.min(out.quench, q.length - 1)].hpMul / lo.hpMul;
    out.hpMax = Math.round((st.hpMax || 100) * mul);
    out.hp = Math.min(out.hpMax, Math.round((st.hp || 1) * mul));
    out.quenchApplied = out.quench;
  }
  ```
  两端同乘一个倍率，`hp / hpMax` **比值不变**，伤势等级不漂移；`quenchApplied === quench` 时整段跳过，不重复复利。旧档（无 `quench` 字段）一律按 0 处理，等于整段不执行。
- 为批次 2 折骨风提供克法读数（淬体阶数 + `S.body` 体质双输入）。

**决策点 ①**：淬体是否允许凡体追平先天体质？
建议：允许，但凡体花 3 倍——保住"凡体逆袭"叙事，又不毁创角选择的意义。

**决策点 ①b（rev2 新增）**：是否在 M2 内一并接上 6 个未实现的体质加成？
实测 8 种体质中，只有 `dao`（193/217/5354 行）与 `chun`（512 行）有实际引用；`sword / nine / ice / xuan / chaos / plain` 的 `eff` 文本在 game.js **零引用**（`xuan` 的 5 处命中全是功法品阶枚举）。也就是说"凡体 vs 先天体质"目前只差 `dao` 的 1.5 倍转化率，不作用于气血与战斗。
**建议接**：每个体质 1~3 行，是 M2 内性价比最高的工作量；不接，"凡体 3 倍成本"就是在为一个不存在的差距定价。

## 三、批次 2 · M1 天劫五类化

**现状核对**：破境链 = `openBreak`（game.js:1781）→ 双修分线 `openBothBreakPick` → `openXianBreak`（~1925）→ `do_xbreak`（:1986）→ `xianBreakRate`（:1902）。**v8.0 已有现成的"考前准备"UI**——择地/备药/护法三段 chip + `prepBonus` 合计加成。天劫直接做第四段，UI 模式照抄，判定入口不动。

**rev2 补正一：克法误把神道专属当通用**。实测：

- `getGongfa()`（game.js:666）返回 `S.gongfa[0]`，是**仙道道基功法单槽**；神道玩家无此槽（神道另走 `S.daogong`，见 `getDaogong()` :669）；
- `S.dArt` 是**神道神器表**（:127），`dockItems` 里 `if (usesShenLine())` 才 push（:1350），`ACT.openDivineArts` 开头即 `if (!usesShenLine()) { toast('神器只认香火，仙道用不上'); return; }`（:2515）。

**改法：克法表按道分列**，每类劫给仙、神两套读数，缺哪套就写明"此道无克法，只有硬扛"：

| 劫 | 验什么 | 仙道克法 | 神道克法 |
|---|---|---|---|
| 三问雷 | 道心 | `st('heart')` 高 → 劫轻 | 同左（道心通用） |
| 倒天河 | 气海 | `getDaogong()` 五行为水 → 克 | `S.piety` / 信众规模 → 劫轻（香火压水） |
| 无灯焰 | 神器 | **无克法**（仙道无神器，文案写明"灯火照不到你"） | `S.dArt` 已请 → 克 |
| 折骨风 | 肉身 | `QUENCH[S.quench]` 阶数 + `S.body` → 克 | 淬体阶数（神道同样可淬）+ 庙宇维护 |
| 故人关 | 恩义 | `hookUnsettled().length === 0` → 劫轻（game.js:8848） | 同左（钩子通用） |

**rev2 补正二：定向轴不存在**。素材库五劫是"雷 / 水 / 火 / 风 / 心"，而主修五行 `ELEMENTS`（data.js:215）只有金木水火土——**既无雷也无风**（雷、风在 `MUT_ELEMENTS` 变异五行里）。"按主修五行定向抽一类"没有可实现的映射。

**改法**：放弃"定向"，改为**五类固定权重 + 主修五行只作池构成因子**：

```js
// 基础权重，五行只影响"哪一类更可能"
const TRIB_WEIGHT = { lei: 22, shui: 20, huo: 20, feng: 18, xin: 20 };
// 主修为水/木者水劫略升，为火者火劫略升，以此类推；雷/风不参与主修映射
```

抽类用 `weightedPick`，随机数走 §八 的可播种 RNG，保证"万次模拟"可复现。

- data.js 新表 `TRIBULATION`（5 条，名与形貌素材库已备：三问雷 / 倒天河 / 无灯焰 / 折骨风 / 故人关），每条含 `{id, name, test, xianCounter, shenCounter, phrase}`。
- **触发条件**：仅**跨大境界**（`xRealm` +1 或 `pillar` +1）时触发，一成概率上浮为"双劫"（P1 可留）；同境小阶突破不触发（避免烦扰）。
- **加成口径**：克法合计 +8~15%，走 `xianBreakRate` 同款 `clamp(0.05, 0.95)`，与 `prepBonus` 并列，不超上限。
- **失败后果（决策点 ②）**：**不掉级**，改为三重惩罚：
  - 重伤落到濒死档：`S.hp = Math.max(1, Math.round(S.hpMax * 0.10))`（比值 <0.15，回血乘 `healMul 0.35`）——`injuryLevel` 是按比例计算的纯函数，没有"拉满"这个状态，必须写数值；
  - 修为跌三成：`S.xiuwei = Math.round(S.xiuwei * 0.7)`；
  - 三旬锁：`S.tribLock = 3`，`openXianBreak` 入口读它并挡一次；
  - `故人关` 失败额外 `pushHook`（故人上门讨一段因果）——把失败也变成剧情。
