## 一、现状：这个世界现在只有敌人

先把数据摆出来，因为这决定了后面所有设计。

### 1.1 遭遇表里没有一个好人

`startCombat()` 4076 行：

```js
const names = ['邻庙庙祝', '散修', '血奉执事', '游方邪修', '宗门执法', '野祀孤魂'];
```

**六种，全是敌对。** 没有"路过的老者"、"同门师兄"、"卖药的行商"。

### 1.2 22 个奇遇里，"给好处"的那些没有人

22 个奇遇（`oldman / cave / dying / ruined / market / beast / storm / jade / debtor / scripture / pilgrim / spirit / donor / drought / plague / neighbor / prefect / wander / demon / draft / theft`）里，有相当一部分是"白给"：

| 奇遇 | 白给什么 | 给的人后来怎样 |
|---|---|---|
| `oldman` 崖边老者 | 递半块饼 → 或有回报 | **再也不出现** |
| `cave` 无名古洞 | 功法残卷 | 洞是死的，没人 |
| `dying` 濒死修士 | 灵石 / 人情 | 救完就没了 |
| `jade` 玉简 | 功法 | 玉简是死的 |
| `scripture` 残经 | 功法 | 经是死的 |

**所有"好处"都来自物，不来自人。** 这就在世界观上留下一个洞：**为什么没有人？**

### 1.3 `S.debt` 是一个死计数器

```js
// 3690 行，全项目唯一一处
S.debt = (S.debt || 0) + 1;   // 受伞不问，得地阶功法。你欠下一份人情。
```

`S.debt` 写入 1 次，**读取 0 次**。

```bash
$ grep -n "S\.debt" wxcs3-game.js
3690:  S.debt = (S.debt || 0) + 1;
```

这是一句已经很漂亮的设计——「受伞不问，欠一份人情」——但它**永远不会有下文**。玩家欠了，然后忘了，游戏也忘了。

> 这和之前三次断链是同一种病：**记录存在，结算不存在。**

### 1.4 所以真正缺的不是"更多敌人"，是"人"

现在的人际只有两个极端：

```
可结交的 NPC（好感 0~100，对你越来越好）
敌对目标（战力、血条、杀掉）
```

中间那一层是空的——**那种你不能杀、不好惹、给你东西但从不安好心、你欠他但算不清欠多少的人。**

玄鉴和魔门里，这一层恰恰是最多的。

## 二、两本书的五种写法

我把两本全本都搜了一遍，找到五种可实现的模式，全部带原文。

### 2.1 养肥 —— 「养肥了就可以交换宰杀的猪与牛」

> 你以为我们是什么，我们不过是这两家养的猪狗，是他们交易中投上天平的一小颗砝码……
> **他们只是在等我们养肥血肉，我们是养肥了就可以交换宰杀的猪与牛。**
> ——《玄鉴仙族》

这是最狠的一句。注意它的结构：**供养 → 长大 → 变成筹码 → 被交换**。中间没有任何一步是"恶意"，每一步都是"照顾"。

玩家体验到的会是：这个宗门对我真好，给我丹药、给我功法、替我挡灾——**直到有一天他们把你连人带修为一起交割出去。**

### 2.2 鱼塘 —— 「她的鱼塘很大，不缺这一条大鱼」

> 反正她的鱼塘很大，不缺这一条大鱼，之前种种就当是**结个善缘**，假以时日说不定会有奇效。
> 对症下药，看人下菜。……除此之外她还养着不少对她死心塌地的小鱼呢。
> ——《苟在初圣魔门当人材》

关键在「**善缘**」两个字。她不是骗子，她是**做投资组合**。对你好的时候是真的好，因为长期收益需要你真的成长。

这条给了设计上一个很重要的许可：**施恩者不必是坏人**。他可以真心待你，同时也在算账。两者不矛盾。

### 2.3 鼎炉 —— 「把她养肥了，然后再开宰」

> 盗天机之术直接将她转化为了人形鼎炉。此后，玉素真无论修行到什么地步，吕阳只要一个念头就能立刻抽干她的修为气数，然后反哺自身。
> 「不过不急。」「接下来再想个办法，**合理地将盗天机之术传给她**，接着让她去超别人，**把她养肥了，然后再开宰**。」
> ——《苟在初圣魔门当人材》

注意「**合理地将……传给她**」。手段不是强夺，是**送**。送的越合理，钩子越深。

对应到游戏：**你得到的每一本高阶功法，都可能是别人种在你身上的。**

### 2.4 亏欠 —— 「原来是为了让迟炙云愧疚」

> 宁和远这才明白真人的深意……『**原来是为了让迟炙云愧疚……让他觉得亏欠我了**……让他觉得我跟迟家是站在一条线的！』
> 他恍然大悟，脊背上皆是冷汗的同时也对待在这个鬼地方没了怨气，唯独剩下敬佩。
> ——《玄鉴仙族》

这是最精妙的一种：**让别人吃亏，是为了让第三个人欠你。**

用在游戏里：你被人当众羞辱、被派去守最苦的地方——不一定是惩罚，可能是有人要拿你的委屈去换别人的愧疚。

**这条可以做成"你看不懂的好意"**：玩家明明被欺负了，几年后忽然发现那是保护。

### 2.5 钓鱼 —— 「什么洞府机缘，鱼饵罢了」

> 这是在钓鱼啊！**什么洞府机缘，鱼饵罢了。** 看来是露富了，见我一个刚入门的弟子购买了这么多灵丹，想要把我骗出去宰了。
> ——《苟在初圣魔门当人材》

关键在「**露富了**」。钩子不是随机撒的，是**你暴露了什么，就有人来钓什么**。

## 三、核心设计：恩义（钩子）

### 3.1 一条规律，撑起整个世界

我把上面五种提炼成一条规则，这条规则本身就是设定：

> **恩的纯度，与施恩者的境界成反比。**

| 施恩者 | 给的东西 | 纯度 |
|---|---|---|
| 山道上的樵夫、村口的老妇、同门师弟 | 半块饼、一碗水、一句提醒 | **真的**，因为他们没能力布局 |
| 筑基散修、坊市掌柜 | 一次赊账、一条情报 | 八成真，可能日后要你还 |
| 金丹、紫府 | 一本玄阶功法、一次救命 | **五成**，几乎都有账 |
| 元婴以上 | 一本天阶功法、一个洞府 | **基本是钩子**，只是你还不知道要还什么 |

这条规则一旦成立，玩家会自己学会：**化神老怪白送你东西，千万别接。**

而这正好是玄鉴和魔门的味道——不是"世界充满恶意"，是"**世界对你有善意，但善意有价格**"。后者比前者可怕得多。

### 3.2 数据结构：`S.hooks`

不要再加计数器。用对象数组，每个钩子是一条完整记录：

```js
// newGame() 里
hooks: [],        // 欠别人的（可能被收割）
hooksGiven: [],   // 别人欠你的（可以讨，但可能赖账）

/* 一条钩子的完整形态 */
{
  id: 'hook_umbrella',
  from: '柳姓散修',          // 施恩者（可能只是化名）
  fromRank: 3,               // 施恩时他的位阶（决定这钩有多硬）
  given: '地阶功法《流火剑诀》',
  givenAt: { y: 387, m: 5 }, // 何时给的
  hint: '伞面上的墨迹干得太快了，像是昨夜才写的',  // 破绽（给玩家察觉的机会）
  known: true,               // 明钩（你知道欠了）/ 暗钩（你根本不知道）
  due: { kind: 'realm', at: 4 },   // 期：金丹时
  claim: { /* 索 */ },
  refused: false
}
```

用数组而不是计数器，因为玩家需要**看见一张账单**，而不是一个数字。

### 3.3 四个字段决定一切：恩 / 期 / 索 / 拒

| 字段 | 回答什么 | 可选值 |
|---|---|---|
| **恩** `given` | 你拿到了什么 | 功法、灵石、法宝、救命、情报、一次庇护 |
| **期** `due` | 什么时候来要 | `realm`（到某境）/ `year`（N 年后）/ `item`（你得某物时）/ `kill`（你杀人时）/ `weak`（你重伤时）/ `guowei`（你证位时） |
| **索** `claim` | 要什么 | 功法+修为、灵石 N 倍、一件法宝、替你杀一个人、你的仙基、你的寿元、你的命 |
| **拒** `refuse` | 赖账的代价 | 业力、道心、debuff、被追杀标记、当场翻脸开战 |

**「期」的设计是这个系统的灵魂。**

如果钩子在给的时候就兑现，那它只是个骗局，玩家下次不上当就完了。
但**期放在三十年后**，玩家会忘——然后在最不该出事的时候出事。

而"最不该出事的时候"是可以设计的：

| 期 | 触发时机 | 为什么狠 |
|---|---|---|
| `realm` | 你破境成功那一夜 | 你最虚弱、最放松、最相信世界 |
| `weak` | 你气血 < 30% | 你打不过 |
| `guowei` | 你设法仪、动不了 | **这是全篇最狠的一刀** |
| `year` | 到期自动 | 你已经忘了这回事 |

### 3.4 明钩与暗钩

| | 明钩 | 暗钩 |
|---|---|---|
| 玩家知道欠了吗 | 知道 | 不知道 |
| 表现 | 「得法，但欠一份人情」（已有一句） | 什么提示都没有 |
| 玩家能做什么 | 提前准备、攒钱、找人说情 | 只能在破绽里察觉 |
| **破绽** | 不需要 | **必须有** |

暗钩必须留破绽，否则不公平。破绽写在哪？

```js
hint: '他给的价，比市价低了一半'
hint: '他记得你三个月前随口说的一句话'
hint: '伞面上的墨迹干得太快了'
hint: '他说「不必还」，说的时候没有看你'
```

**破绽不是提示，是质感。** 玩家读到会心里一沉，但不会立刻明白。这才是好的伏笔。

### 3.5 双向：你也可以是放贷的人

这一条我认为不可省。**只有"被收割"的世界是压抑的，只有"收割别人"的世界是油腻的。**

```js
hooksGiven: [
  { to: '云栖', what: '救她一命', at: 387, weight: 3, note: '她当时说不出话，只抓着你袖子' }
]
```

你可以"讨"回来：一次救命、一次挡刀、一次借灵石、一次在宗门投票时站你这边。

但**讨债有风险**：

| 对方状态 | 结果 |
|---|---|
| 好感 ≥ 60 | 痛快还，好感 +5 |
| 好感 20~60 | 还，但好感 −10 |
| 好感 < 20 | 找借口，或反过来恨你 |
| 对方境界已远超你 | **他可以选择不还，而且你不能怎样** |

最后一行是这套系统的骨气：**债的效力，取决于你现在打不打得过他。**

这也是玄鉴的逻辑——恩义是有的，但它不高于实力。

### 3.6 怎么接进现有代码（五个已有入口）

不改现有结构，只把已经存在的"给好处"动作标记上钩子：

| 位置 | 行号 | 现在 | 改成 |
|---|---|---|---|
| `tx_di2:quiet` 受伞不问 | 3690 | `S.debt++`（死） | `pushHook('hook_umbrella')` |
| `tx_tian:follow` 跟着念 | — | 可能被夺舍（随机） | 明钩 + `soul_lien` debuff |
| `tx_tian2:draw` 拔剑 | — | 剑意入体 | 钩子：「持此，去把该了的事都了了」→ 期=`kill` |
| `enc:oldman:share` 递半块饼 | — | 或有回报 | 反向：你放出一钩（老者是真人） |
| `enc:dying:save` 施药救人 | — | 得人情（无机制） | `hooksGiven.push` |

**「雪中授剑」那句台词已经是钩子了**——「持此，去把该了的事都了了」。现在的代码把它当成"得一把剑"，实际上它是一份**外包杀人合同**。

这句话不用改，只需要在三十年后有人来收。

## 四、负面 buff：让"欠着"有实感

用户要的"做成负面 buff"，我设计成五条。原则是：**debuff 不直接扣钱，扣的是"你做事开始不顺"。**

### 4.1 五条因果 debuff

| id | 名 | 触发 | 效果 | 怎么消 |
|---|---|---|---|---|
| `karma_tangle` | **因果缠身** | 任一暗钩过期未还 | 破境 −8%；历练遇人概率 +30% | 还清该钩，或散 30 业力 |
| `debt_weight` | **人情压身** | 明钩 ≥ 2 且全部超期 | 道心 −1/年；NPC 好感增速 −30% | 还掉任意一钩 |
| `borrowed_luck` | **借来的运** | 使用钩子给的功法修炼 | 修炼 **+20%**，但每次破境 1d100 ≤ 15 走火（气血 −30%、修为 −20%） | 弃用该功法（战力骤降） |
| `marked_rich` | **被人惦记** | 单次卖出 ≥ 1,000 或 灵石 ≥ 5,000 | 遇袭概率 +50%，敌人战力 +15% | 散财到 1,000 以下，或买护身之物 |
| `soul_lien` | **神魂暗契** | 接受「洞天传音」类钩子 | 每月 1d100 ≤ 10 被窥视；不可在洞天过夜 | 斩契（道心 −3、气血 −50%），或反过来重创对方 |

### 4.2 为什么 `borrowed_luck` 是这套系统的题眼

它是唯一一条**先给你好处**的 debuff：

```
修炼速度 +20%（真金白银的收益）
     ↕
每次破境 15% 概率走火（三十年后才可能出事）
```

玩家会算：我练到金丹只要 40 年，破境 4 次，走火概率 = 1−0.85⁴ ≈ 48%。

**一半概率。** 但那是四十年后的事，而 +20% 是现在的事。

**这就是"贪"的机制化。** 玩家不是被骗，是明知道还往里跳——因为现在划算。

而这恰恰是《魔门》那句「把她养肥了，然后再开宰」的本质：**被养的人从来没有觉得自己被养。**

### 4.3 debuff 的显示：不许明说

状态卡不能写「因果缠身：破境 −8%」。那太像仪表盘，会毁掉气氛。

改成**征兆**：

```
异常　夜里总觉得有人在数你的呼吸
异常　你的影子比你先动
异常　丹田里有一处不属你的暖意
```

| debuff | 状态卡写法 |
|---|---|
| `karma_tangle` | 夜里总觉得有人在数你的呼吸 |
| `debt_weight` | 你开始记不清自己欠了谁 |
| `borrowed_luck` | 气海里有一缕不属你的气，很听话 |
| `marked_rich` | 走过坊市时，有三道目光跟着你 |
| `soul_lien` | 你在洞天里听见有人叫你的名字，用的不是你的道号 |

数值影响可以在「详情」里给（点开异常看明细），但**默认不写**。

这一条我建议写进不做原则：**debuff 不许把公式写在脸上。**

### 4.4 数值校验

| debuff | 影响幅度 | 是否可接受 |
|---|---|---|
| `karma_tangle` 破境 −8% | 破境率基准 60~95 → 降到 52~87 | 可接受，是压力不是死刑 |
| `borrowed_luck` −20% 走火 | 走火 = 气血 −30%、修为 −20%（不跌境） | 可接受，痛但不毁档 |
| `marked_rich` 遇袭 +50% | 遇袭本已存在，只是变密 | 可接受 |
| `soul_lien` 月 10% 被窥视 | 主要是叙事压力 + 洞天不能用 | 可接受 |

**没有任何一条直接扣命、扣档、扣境界。** 这是边界：debuff 让你难受，不让你死。

## 五、十二个钩子实例（可直接抄进 `data.js`）

按"恩的类型"分组。每条的 `from`/`given`/`due`/`claim` 都可直接对应 3.2 的结构。

### 5.1 送法类（4 条）

| id | 施恩者 | 表面 | 实际 | 期 | 索 |
|---|---|---|---|---|---|
| `hook_umbrella` | 柳姓散修（实为紫府） | 雨中递伞，伞面写着半篇地阶法诀 | 你是他的鼎炉候选人 | `realm: 金丹` | 收回功法 + 你三成修为 |
| `hook_sword` | 无名（雪中留剑） | 「持此，去把该了的事都了了」 | 外包杀人 | `kill`（你杀第一个金丹时） | 替他杀一个指定的人，否则剑反噬 |
| `hook_voice` | 洞天深处的念诵声 | 天阶功法 | 夺舍预备 | `realm: 道胎` | 你的身体 |
| `hook_tablet` | 残碑 | 地阶功法 | 碑下埋着原主的残魂 | `year: 30` | 替他续命（你的寿元 −20%） |

**`hook_tablet` 是"最不像钩子的钩子"**：一块碑，一段法诀，没有一个人。三十年后你才知道碑底下有人。

### 5.2 救急类（3 条）

| id | 施恩者 | 表面 | 实际 | 期 | 索 |
|---|---|---|---|---|---|
| `hook_pill` | 路过的丹师 | 你重伤时给一颗救命丹 | 丹里有一味"引" | `weak`（下次重伤） | 他会来取你一滴心头血 |
| `hook_debt` | 叩门的旧识 | 留他一夜 | 他把仇家引来了 | `year: 3` | 不是索，是连坐（你替他挡灾） |
| `hook_shelter` | 宗门长老 | 替你压下一桩祸事 | 你从此是他的"人" | `sect`（你升真传时） | 替他做一件脏事 |

### 5.3 供养类（3 条，宗门/家族用）

| id | 施恩者 | 表面 | 实际 | 期 | 索 |
|---|---|---|---|---|---|
| `hook_sect_feed` | 宗门 | 丹药、功法、替你挡灾 | 你在被"养" | `guowei`（你证位时） | 你的果位归宗门 |
| `hook_clan_raise` | 家族 | 祠堂栽培、族运倾斜 | 你是族运的抵押 | `realm: 紫府` | 你必须留下一个继承你道统的后代 |
| `hook_dowry` | 联姻之家 | 送资源、送人情 | 你是一枚盟约的钉子 | `year: 10` | 你必须履行婚约，否则两家翻脸 |

`hook_sect_feed` 就是《玄鉴》那句「养肥了就可以交换宰杀的猪与牛」的直接实现。**而且它的期设在证位那一刻——你一生最不能被打断的时候。**

### 5.4 反向类（2 条，你施恩）

|---|---|---|---|---|
| `given_life` | 濒死修士 | 一颗疗伤丹 | 任何时候 | 他可能已经死了，或已经不认 |

`given_food` 是这个世界仅剩的温柔：**你给出去的时候不知道他是谁，他还你的时候也不说。**

## 六、功法逻辑：五处不严明

功法的骨架已经很清楚了（道基定上限、招式装配、同源共鸣），问题都在接缝上。

### 6.1 【最严重】神通从不进战斗

```js
// 神通只有三处作用，全在算战力
441:  let sd = 0.8 + S.shenTong.length * 0.05;
460:  if (r.idx === 3) base = 350 * Math.pow(1.15, S.shenTong.length);
467:  let sd = 0.8 + S.shenTong.length * 0.05;
```

`S.shenTong` 里存的是「溪上翁」「浩瀚海」「靖平敕」这种名字——**听起来全是绝招**。

但玩家在战斗里点「术」，`openSkills` 列的是 `equippedSkills()`，那来自 `D.SKILLS`（藏经阁招式），**和神通完全无关**。

结果：一个紫府修士集齐 4 道神通，战力从 350 涨到 612，但**打架时一道都用不出来，也看不见**。

**这是"数值上有、体验上没有"。** 玩家会觉得神通是假的。

**修法**（两选一，推荐 A）：

**A. 神通作为被动词条**（改动小）——每道神通给一条明确的战斗修正，并在战斗面板显示：

```js
// 神通 → 战斗词条
const SHENTONG_TRAIT = {
  '溪上翁': { tag: '水势', eff: '灵力消耗 −20%' },
  '浩瀚海': { tag: '海压', eff: '每 3 回合使敌方气势 −1' },
  '靖平敕': { tag: '敕令', eff: '首次施法必中' },
  '九重擭': { tag: '重擭', eff: '受击时 20% 减半伤害' }
};
```

战斗面板「我方 · 神通」一行列出 tag，玩家看得见，也就相信了。

**B. 神通作为绝招**（改动大）——每道神通 = 一个高耗大招，一场战斗限一次。更像"绝招"，但要重做战斗选项。

### 6.2 装配上限与境界无关，散修永远是 2 格

```js
3825:  function equipLimit() {
3826:    if (S.sect) return (D.SECT.ranks[S.sect.rank] || D.SECT.ranks[0]).equip;
3827:    return 2;
3828:  }
```

散修散到金丹，还是 2 格。而宗门真传一进门就有 4 格。

后果：**散修不只是资源少，是永远打不出组合。** 而"散修"是这个游戏很重要的一条活法（不入宗门、不立族、单干）。

**修法**：`2 + floor(境界/2) + 宗门加成`，上限 6。

```js
function equipLimit() {
  const base = 2 + Math.floor(S.xRealm / 2);          // 散修也能长
  const sect = S.sect ? (D.SECT.ranks[S.sect.rank] || {}).equip || 0 : 0;
  return Math.min(6, Math.max(base, sect + 1));        // 取高者，不叠加
}
```

### 6.3 换功法零代价，可以反复横跳

`ACT.do_setgf` 1714 行：校验拥有 → 直接 `S.daogong = id`。

没有冷却、没有损失、没有道心代价。玩家可以在破境前换高上限功法、破境后换高倍率功法。

而下限已经处理了（换低阶功法会把自己钉死），**上限没处理**。

**修法**：换道基 = 散功重铸。

| 换法方向 | 代价 |
|---|---|
| 同阶互换 | 修为 −20%，道心 −1 |
| 升阶（黄→玄） | 修为 −10%（理顺气机，反而顺） |
| 降阶 | 修为 −40%，且上限被钉死（现有逻辑） |
| 每局第 3 次起 | 额外道心 −2，且 1d100 ≤ 20 走火 |

理由：**道基是"你走哪条路"，不是"你今天穿哪件衣服"。**

### 6.4 两套"你会什么"，没有分工说明

| | 神通 `S.shenTong` | 招式 `S.skillsKnown` |
|---|---|---|
| 从哪来 | 道统池（紫府每关三选一） | 藏经阁（宗门身份限制） |
| 数量 | 上限 1~4（仙基所限） | 上限 2~4（宗门所限） |
| 作用 | 战力 ×1.15ⁿ | 战斗里点「术」用 |
| 玩家看得见吗 | **看不见** | 看得见 |

两套并存本身没问题（神通=道统给的，招式=学来的），但**界面上没有任何一句话解释这件事**。

`openSkills` 的提示只有一句：「道基与招式同源 +20%…」。**没有提神通。**

**修法**：状态卡两行分开写，并各给一句人话：

```
神通 3/4　道统所授，改的是你的底子
招式 4/4　自己学的，斗法时点「术」用
```

### 6.5 相克判定不对称

`resonResult` 里：

```js
if (g.el === sk.kind) return { mul: 1.20, txt: '同源' };
if (D.SHENG[g.el] === sk.kind) return { mul: 1.10, txt: '相生' };
const my = D.ELEMENTS[g.el];
if (my && my.ke === sk.kind) { ... 1.50 / 0.85 }
```

- 同源 +20%
- 相生 +10%
- 相克 **−15%，但 30% 概率翻成 +50%**

问题：**相克逆用 30% × +50% + 70% × −15% = +4.5% 期望**。

也就是说，**玩家选了相克招式，长期看和"无关"持平，但方差极大。**

这不是错，但**玩家不会这么算**。他会记住那三次 +50%，然后一直打相克，然后觉得这游戏随机性太大。

**修法**：既然要"逆用"，就把它做成**明牌**：

```
相克 · 逆用（+50%）：需先「观察」一回合，看破其气机走向
相克 · 硬打（−15%）：直接上
```

把随机变成**选择**。这才是"手段"，随机不是。

## 七、对战逻辑：六处漏洞

### 7.1 【真 bug】胜算档的颜色永远不会生效

```js
// 4259 行：档位名是新的一套
const tier = R >= 3 ? '碾压' : R >= 1.5 ? '压制' : R >= 0.8 ? '相持' : R >= 0.4 ? '下风' : '绝境';

// 4345 行：判断用的还是旧的一套
'<b class="' + (tier === '必死' || tier === '劣势' ? 'danger'
              : (tier === '碾压' || tier === '优势' ? 'good' : '')) + '">' + tier + '</b>'
```

`tier` 的取值只有 **碾压 / 压制 / 相持 / 下风 / 绝境** 五个。

`'绝境'` 永远不等于 `'必死'`，`'下风'` 永远不等于 `'劣势'`。

结果：

| 实际档位 | 应该显示 | 实际显示 |
|---|---|---|
| 绝境（R<0.4，必死） | 朱砂红 | **灰** |
| 下风 | 朱砂红 | **灰** |
| 相持 | 无 | 无（对） |
| 压制 | 青玉绿 | **灰** |
| 碾压 | 青玉绿 | **灰** |

**除了「碾压」碰巧能命中 `'碾压'`，其余四种全错。**

这是全篇唯一一个**真正的 bug**（其余都是设计问题）。而且它和之前三次是同一个病：

> `'火' === 'fire'`（元素名比英文键）
> `foeTurn` 返回 false 不 render
> `dispatch` 不认 `enc:` 前缀
> **现在：`'绝境' === '必死'`**

**共同形态：改了枚举值，没改所有比较点。**

**修法**（一行）：

```js
const bad = ['绝境', '下风'].includes(tier);
const good = ['碾压', '压制'].includes(tier);
... (bad ? 'danger' : good ? 'good' : '')
```

**建议顺手加一条自检**：凡是 `X === '字面量'` 且字面量出现在 3 处以上，就抽成常量。这次的 tier 就该是常量表。

### 7.2 敌人性格四种，只有一种有行为

```js
4081:  const traits = ['brute', 'veteran', 'slippery', 'normal'];
4084:  trait: traits[Math.floor(Math.random() * traits.length)]
4379:  if (c.foe.trait === 'slippery' && c.foe.hp <= c.foe.hpMax * 0.5 && Math.random() < 0.35) { 跑 }
```

`brute`（莽夫）、`veteran`（老练）、`normal`（寻常）**在代码里没有任何分支**。

但界面上会显示这四个字：

```js
4278:  const traitName = { brute: '莽夫', veteran: '老练', slippery: '滑头', normal: '寻常' }[c.foe.trait];
```

**玩家看到「老练」，然后发现它和「寻常」一模一样。**

**修法**——每种给一条明确行为，不用多，一条就够：

| trait | 行为 | 为什么这样设计 |
|---|---|---|
| `brute` 莽夫 | 伤害 ×1.25，但命中率 −15% | 猛而糙，可被"御"耗死 |
| `veteran` 老练 | 每 3 回合必有一次「守势」（减伤 50%），且不会踏入陷阱 | 难打，逼你换手段 |
| `slippery` 滑头 | 半血有 35% 遁走（已有） | 已有 |
| `normal` 寻常 | 无特性 | 基准 |

三种行为都是**已有字段可实现的**（`dmg`、`hit`、`c.defending`），不需要新状态机。

### 7.3 阵盘在战斗里用不上，与设定直接冲突

`ARRAY_DISKS` 里有一条：

```js
{ id: 'zhenSuoLing', name: '锁灵阵', tier: 'xuan', eff: '战斗中禁敌遁走', upkeep: 50 }
```

「战斗中禁敌遁走」——**这是一条战斗效果**。

但战斗面板写着：

```js
4295:  if ((S.disks || []).length) tips.push('已布阵盘在洞府，野外的仗用不上');
```

而 `S.disks` 实际只在两处生效：洞府灵气 +1、洞府不被窥探（1751 行面板 / 270 行维持费）。

**所以「锁灵阵」的效果从来没被实现过，界面还明确告诉玩家"用不上"。**

这和《四艺设计总纲》里"阵法是资产，布下持续生效"、"四艺在战斗中均为消耗品"的设计**正面冲突**。

**修法**（改法最省的一条）：把阵盘分成**洞府阵**和**随身阵**两类。

| 类 | 例子 | 生效场景 |
|---|---|---|
| 洞府阵 | 聚灵、迷踪、五行轮杀 | 洞府（被袭击时自动生效） |
| 随身阵 | 锁灵（禁遁）、困敌（降敌命中） | **战斗第一回合可布一次** |

随身阵消耗灵石或阵盘耐久，一场一次。这样「器」那一栏才真的包含四艺全部四样。

### 7.4 位格判定与战力判定在同一屏上互相打脸

这是最影响沉浸感的一条。

```js
// 4257 行：R = 战力比
const R = computePower() / Math.max(1, c.foe.power);

// 4256 行：位阶差 = 境界序号差
const diff = foeR - myR;
if (diff >= 8) odds = '高你两个大境以上——你根本伤不到他';
```

`positionRank()`：

```js
478:  if (isShen()) return S.pillar * 4 + S.pos;   // 八柱正位 = 31
479:  return S.xRealm * 4 + S.xStage;              // 道胎圆满 = 23
```

战力表：

| 仙道 | 战力 | 神道 | 战力 |
|---|---|---|---|
| 道胎 | 6,000 | 八柱 | 8,000 |

**同一个对局，两个结论：**

```
道胎圆满（rank 23, 战力 6000） vs 八柱正位（rank 31, 战力 8000）

战力判定：R = 6000/8000 = 0.75  → 「相持」
位阶判定：diff = 31 − 23 = 8     → 「高你两个大境以上——你根本伤不到他」
```

**这两个字同时出现在战斗面板顶部。**

玩家会看到：「R=0.75 相持」旁边紧跟着「你根本伤不到他」。

**修法**：位阶差不能直接用 rank 数字，必须按**战力档**折算：

```js
// 用战力比反推"相当于几个大境"，而不是用境界序号相减
const pDiff = Math.log2(c.foe.power / Math.max(1, computePower())) / 1.9;  // 每大境约 ×1.9
```

或者更简单、更符合设定：**跨体系对局时，只用品格倍率，不用 diff。**

因为设定里已经写了「先判位格，再判战力」，而**位格只属于果位**。八柱和道胎之间没有位格关系，只有战力关系。

### 7.5 气势只涨不落，且只有敌方有

```js
4370:  if (c.round > 0 && c.round % 3 === 0) c.momentum = Math.min(3, c.momentum + 1);
```

`c.momentum` 是**敌方**的气势，每 3 回合 +1，最高 3，伤害 ×1.0/1.1/1.2/1.35。

玩家没有对应的东西。这造成一个隐含规则：**拖得越久越吃亏**——这是对的，符合设计意图（逼速战）。

但有个漏洞：**玩家如果一直「御」（减伤 50%），气势涨到 3 也只有 ×1.35 × 0.5 = 0.675，比第一回合还低。**

于是"无限防御"成了一步稳赢的棋——只要你不怕耗时间，而时间上是 `advanceMonth(1)` 每次战斗才 1 个月。

**修法**：气势到 3 时给一个不可防御的效果——**「破势」**：第三档气势的攻击无视「御」的减伤（或减半减伤）。

这样"御"不能无限用，玩家必须在第 7~9 回合做出决定：换手段，或者跑。

### 7.6 敌人不会求饶，也不会叫人

现在敌人只有两种结局：被打死，或者（滑头）遁走。

缺的两件事，恰好最符合这个世界的残酷：

| 缺什么 | 为什么值得加 |
|---|---|
| **求饶** | 让"杀不杀"变成一个有重量的选择。杀了业力 +，放了可能结仇也可能结缘 |
| **叫人** | 高阶敌人半血时唤来同门，把一场单挑变成逃亡。这是"死仇会找上门"的具体实现 |

求饶的写法很简单（`foe.hp < 25%` 时 30% 触发）：

```
「道友饶命！」他跪下去，手还按在储物袋上。
```

三个选项：**放**（业力 0，可能得人情 / 可能被记恨）、**杀**（业力 +5，得全部身家）、**废其修为**（业力 +2，得一半，结死仇）。

第三项是最"修仙"的选项，也是最狠的。

## 八、项目整体：还能优化什么

按"会影响玩家"到"只影响维护"排序。

### 8.1 五件影响体验的事

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **卖出只有一条渠道** | `SELL_CHANNELS` 零引用；`do_selldan` 只用 `sellMul().dan` | 设计里的「宗门 70% / 坊市 100% / 拍卖 120~180% / 黑市 140%+业力」**四条渠道一条都没做**。玩家只会摆摊 |

| 5 | **胜算档不上色** | 见 7.1 | 最该一眼看懂的信息，反而最不显眼 |

第 1 条我要多说一句：**它比"四艺没做完"更严重。** 因为四艺的生产端做得很完整（配方、品相、熟练度、行情、收支账本全有），唯独出口只有一个——玩家辛苦炼出来的东西，只能按市价卖掉，**宗门贡献、拍卖溢价、黑市风险全都不存在**。

### 8.2 结构性问题：单文件 5,473 行

`wxcs3-game.js` 已经五千多行，函数 190 个，全在一个 IIFE 里。

现在还能维护，是因为有 `check_actions.py` 兜底。但这只是止血。

**真正的问题是"改一处要跨三个系统读代码"**：

改一个战斗数值，要同时看 `computePower`（433）、`positionRank`（478）、`keMul`、`artBonus`、`resonResult`、`foeTurn`（4359）、`do_cbt`（4401）。

**建议（不是现在做，是记住这个方向）**：按域拆成 4 个文件，用 `window` 挂载，不引入打包器：

```
js/core.js     状态、存档、时间、日志
js/cultivate.js  修炼、破境、功法、神通
js/combat.js   战斗、招式、敌人
js/world.js    奇遇、NPC、宗门、家族、四艺
js/ui.js       渲染、面板、样式
```

`mobile/build.py` 只需要多内联几个文件。**这是唯一能阻止它变成 8,000 行的办法。**

### 8.3 三个"看起来做了但其实没做"的地方

这三处不是 bug，是**玩家会误以为有**：

| 项 | 看起来 | 实际 |
|---|---|---|
| 生肖六冲 `ZODIAC_CLASH` | 有表 | 零引用 |
| 释修 `SHIXIU` | 有六位 | 零引用，没有释修线 |
| 人材 `RENCAI` | 有下材/中材/上材/绝材 | 零引用，魔门线只有血奉事件 |

**建议要么接上，要么从设定文档里删掉。** 留着比删掉更糟——它会让读设定的人以为游戏里有。

## 九、落地顺序（恩义系统单独拆）

| 步 | 做什么 | 工作量 | 验证点 |
|---|---|---|---|
| 1 | `S.hooks / S.hooksGiven` + 存档兜底 | 2 小时 | 旧档读入不崩（这个项目已经因此崩过两次） |
| 2 | 把 5 个已有入口改成 `pushHook` | 半天 | 「受伞不问」之后，状态卡出现「人情 1 未清」 |
| 3 | 结算：`due` 判定 + `claim` 面板 | 1 天 | 强行把期改成 1 年，看会不会来要 |
| 4 | 五条 debuff + 征兆文案 | 半天 | 状态卡写的是人话，不是公式 |
| 5 | 「还 / 赖 / 斩」三选项 | 半天 | 赖账之后真的会被追杀 |
| 6 | 反向：`hooksGiven` + 讨债 | 1 天 | 救过的人真的能求一次 |

**第 3 步是验收点**：钩子能不能"到期"。

这个系统最容易做成"只记录不结算"——就像 `S.debt` 那样。所以**先把到期判定跑通，再往里填 12 条内容**。顺序反了就会得到一堆漂亮的空账本。

## 十、不做原则

1. **钩子不许无限叠加**——同时最多 3 条未清，超出时新钩子替换最旧的（并给出叙事理由：有人替你平了账）。
2. **debuff 不许直接扣命、扣境、删档**——它让你难受，不让你死。
3. **debuff 不许把公式写在脸上**——状态卡写征兆，明细藏进「详情」。
4. **暗钩必须留破绽**——没破绽的暗钩是不公平，不是伏笔。
5. **施恩者不必是坏人**——真心待你和在算账，可以同时成立。**这才可怕。**
6. **债的效力取决于实力**——对方境界远超你时，他可以不还，你不能怎样。这是骨气，不是 bug。
7. **不要让玩家永远赢不了**——钩子必须有"还清"的路径，哪怕是倾家荡产。
8. **反向的恩要有**——只有被收割的世界是压抑的。要让玩家也能给人半块饼。
