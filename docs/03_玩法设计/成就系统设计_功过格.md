## 一、为什么这个游戏需要一个"不给你任何好处"的成就系统

先说结论：**成就系统在这个游戏里必须零数值影响。** 理由三条。

### 1.1 给数值就会变成刷子

一旦成就给战力、给灵石、给悟道点，玩家就会为了成就而行动。而"为了成就而行动"和这个游戏的灵魂——**"你不是龙傲天，你会死，你的选择有代价"**——直接冲突。

想象一个玩家为了拿「屠妖王」而去越境打妖王，他不是在求生，他是在打卡。那一刻游戏就退化成清单。

### 1.2 这个游戏已经有"分数"了，不需要第二个

| 已有 | 作用 |
|---|---|
| 功德 / 业力 | 道德记账，影响破柱与结局 |
| 声望 | 社会地位 |
| 年谱 `S.chronicle` | 事情发生过（已实现，可导出 .txt） |
| 结局 `D.ENDINGS` | 这一生怎么收场（12 种） |

再加一个"成就分数"就是重复。所以功过格**只记，不算**——它不参与任何公式。

### 1.3 但这个游戏真的缺一样东西：跨局的记忆

这是关键。现在**死了就是全没了**：

```
你玩了 400 回合，金丹后期，被一个高你半境的散修一剑砍死
→ 结局页 → 烧一页百世书 → 回到创角那一日
→ 世界只记得你（血债 +10%）
→ 而你，什么都不记得
```

`百世书` 的设定写得很狠："世界记得你，你却不记得世界。"**但代码里只有前半句。**

功过格补的就是后半句——**它是唯一能跨过死亡留下的东西**。不是力量，是"我来过"。

> 功过格不是奖励清单，是天道的账本。
> 你死了，账还在。

## 二、命名：为什么叫「功过格」

「成就」这个词太现代，也太像游戏外的东西。

**功过格**是道教真实存在的东西（《太上感应篇》配套的修行记账法）：把每天做的善事记在"功格"，恶事记在"过格"，月底结算。它在这个设定里完美贴合——

- 游戏已有**功德 / 业力**（当下分数）
- 神道有**香火 / 信众**（人间记得你多少）
- 年谱有**纪事**（事件流水）
- 功过格是**总账**：一生做成了什么，做错了什么

### 三格结构

| 格 | 记什么 | 数量 | 显示条件 |
|---|---|---|---|
| **功格** | 做成了什么 | 75 | 显示条件与进度 |
| **过格** | 做错了什么、以及怎么死的 | 18 | 显示条件与进度 |
| **隐格** | 不该被知道的 | 15 | **条件显示为「？」** |

过格不是惩罚。它是**墓志铭的另一半**——一个只有功格的账本是不可信的。

## 三、五档：以"被记住的范围"分级

不用青铜／白银／黄金，用**这件事被多少人记住**——正好接上香火那套逻辑。

| 档 | 名称 | 含义 | 条数 | 色 | 占比 |
|---|---|---|---|---|---|
| 一 | **传闻** | 村口有人说 | 35 | `#8C8578` 灰 | 32% |
| 二 | **载录** | 郡志里有一行 | 33 | `#5E8FAE` 青 | 31% |
| 三 | **立传** | 有人为你写过传 | 24 | `#6FA698` 青玉 | 22% |
| 四 | **入典** | 入了道典，千百年后还有人查 | 12 | `#A87E2E` 金 | 11% |
| 五 | **天书** | 天自己记的，不给人看 | 4 | `#8B6FA8` 玄紫 | 4% |
| | | | **108** | | |

> 显性格（功 75 + 过 18 = 93 条）的档位分布是 21 / 33 / 24 / 12 / 3；
> 隐格 15 条里有 14 条是传闻、1 条（`ach_pure` 一字不改）是天书，加上去就是上表。

**为什么档位要和"范围"挂钩而不是"难度"**：因为它同时是叙事——你拿了一个「入典」成就，意味着传说里有你一笔。这给玩家的是**身份感**，不是数值。

天书 4 条：

| id | 名 | 条件 |
|---|---|---|
| `dao_ascend` | **补天** | 补回上古断掉的四境，登仙 |
| `dao_zhi` | **至尊** | 证得至尊位格（×15） |
| `dao_alone` | **孤证** | 无护道者设法仪，且成功（−40 惩罚下） |
| `ach_pure` | **一字不改** | ≥ 300 回合，全程未读档、未烧页 |

最后一条是全篇最狠的：**它奖励的是"你没作弊"**。而这个游戏恰好有读档功能，所以它是一条真正意义上的荣誉。

### 4.3 跨局永久记录：**独立存储键**

```js
const ACH_KEY = 'wxcs3.ach';   // 不在存档 envelope 里！
```

这一条是**整个设计的地基**：

| 存储 | 存什么 | `do;reset`（烧页） | 换存档 |
|---|---|---|---|
| `wxcs3.save.*` | 本局状态（含 `S.ach`） | **清空** | 跟随存档 |
| `wxcs3.ach` | 永久功过格 | **保留** | **保留** |

如果功过格跟着存档走，那"百世书"就是个普通的重开按钮——死了什么都没留下，这游戏最狠的一条设定就白写了。

## 五、判定：一个函数、五个钩子

### 5.1 核心函数

```js
let achBusy = false;

function achDisk() {
  try { return JSON.parse(localStorage.getItem(ACH_KEY) || '{}'); }
  catch (e) { return {}; }          // 隐私模式 / 坏数据：退化成"没有前世"
}

function achHas(id) {
  return !!(S.ach && S.ach[id]) || !!achDisk()[id];
}

function unlockAch(id) {
  const a = D.ACHIEVEMENTS.find(x => x.id === id);
  if (!a || achHas(id)) return false;
  S.ach[id] = { y: S.year, m: S.month, age: S.age, realm: realmName() };
  try {
    const d = achDisk(); d[id] = { y: S.year, age: S.age }; 
    localStorage.setItem(ACH_KEY, JSON.stringify(d));
  } catch (e) {}
  achToast(a);                       // 竖笺滑入，不与错误 toast 共用容器
  logLine('功过格 · ' + a.name + '　' + a.txt, 'good');
  return true;
}

function checkAch() {
  if (achBusy) return;               // 防递归：unlockAch → logLine
  achBusy = true;
  try {
    const disk = achDisk();          // 只 parse 一次，别在循环里读 108 次 localStorage
    for (let i = 0; i < D.ACHIEVEMENTS.length; i++) {
      const a = D.ACHIEVEMENTS[i];
      if ((S.ach && S.ach[a.id]) || disk[a.id]) continue;
      let ok = false;
      try { ok = !!a.test(S); } catch (e) { ok = false; }
      if (ok) { unlockAch(a.id); disk[a.id] = 1; }
    }
  } finally { achBusy = false; }
}
```

> `achHas()` 保留给面板用（一次调用一次 parse 无所谓），但**判定循环里必须用缓存**。`localStorage.getItem + JSON.parse` 单次约 0.05~0.2ms，108 次就是 5~20ms——每月一次会在手机上明显感到卡顿。

### 5.2 五个调用点（带真实行号）

| # | 位置 | 行号 | 为什么在这里 |
|---|---|---|---|
| 1 | `advanceMonth()` 末尾（`maxXianghuo` 截断之后、函数收尾括号前） | 307 | 覆盖境界、寿元、香火、信众、灵石、势力、时间类成就 |
| 2 | `afterCombatCheck()` | 3313 | 战斗类、越境、击杀、夺祀、死亡 |
| 3 | `ACT.do_craftgo()` 结束处 | 4970 | 四艺：品相、熟练度满级、四艺齐全 |
| 4 | `ACT.do_selldan / do_selltal / do_sellmat` 结束处 | 5067 | 经济类：第一桶金、单笔最大、月净入 |
| 5 | `resolveEnding()` 开头 | 4608 | 结局类、过格里的死亡条目 |

> 第 1 个钩子要放在 **`for` 循环之外**（`advanceMonth(n)` 一次推进 n 个月，放循环内会跑 n 遍）。

**不要放在 `render()` 里。** 渲染函数有副作用会让每一帧都可能弹成就，且难调试。

**也不要放在 `logLine()` 里。** 因为 `unlockAch()` 自己会调 `logLine()`——虽然有 `achBusy` 兜底，但这是把"可能递归"当成设计。宁可多写四个调用点。

### 5.3 隐藏成就怎么判

隐藏只是**不显示条件**，`test` 照跑：

```js
{ id:'ach_zero', cat:'隐', tier:'wen', name:'空囊', hidden:true,
  cond:'？', txt:'你把最后一块灵石放在柜台上，正好够。',
  test: s => s.tally.buyAtZero === true }
```

## 七、过格总表（18 条）——这个游戏真正的灵魂

### 7.1 为什么必须有这一格

绝大多数游戏的成就是"我多厉害"。但这个游戏的核心体验是"**我会死，而且我死得其所或死得很难看**"。

如果只有功格，那它就退化成一张荣誉榜，等于把"残酷修仙"偷换成"修仙打卡"。

**过格是让失败也被记住的地方。** 而且它不扣任何东西——这一点很重要：玩家不会因为"死过"而被惩罚第二次。

| `guo_same` | 同阶而死 | 载录 | 被同位格者杀死 |
| `guo_crush` | 不知深浅 | 载录 | R < 0.4 仍强行开战并死 |

### 7.3 三条设计说明

**① `guo_lonely`（无人送终）是最狠的一条。**
它不看战力、不看境界、不看钱——只看**有没有人在你死的时候难过**。一个八柱圆满、香火百万、孤身证位的人，很可能拿到它。

这正是"孤证"那条天书的代价。两条成就互为镜像，一起看才有味道。

**② `guo_never`（一生未战）不是嘲讽。**
这游戏里有一种活法叫"我只想炼丹、种药、娶妻、老死"。这条成就承认它成立——**你不是没打，你是不必打。**

**③ 过格与功格可以同时拿。**
「正统」+「血祭」+「孤证」+「无人送终」是一个人。这就是"魔道至尊"的画像，四条各自记录，系统不评判。

## 九、百世书：前世残忆

### 9.1 机制

只有「入典」及以上（16 条）能解锁残忆。达成 1 条 → 解锁 1 项可选。

**每局开局只能带 1 项**，不叠加、不消耗（它是"记得"，不是"花掉"）。

| 来源成就 | 残忆 | 效果 |
|---|---|---|
| `dao_daotai` 心外无天 | 记得一线天光 | 开局洞府灵气 +1 级 |
| `mi_book4` 读到真意 | 记得一句真意 | 开局悟性 +2 |
| `art_9` 九品炉火 | 记得火候 | 开局选定一艺直接三级 |
| `shen_8` 八柱圆满 | 记得香火的味道 | 立庙时初始信众 +50 |
| `war_ji` 断人道途 | 记得那一手 | 开局天赋 +2 点 |
| `shi_found` 开宗 | 记得山门的方位 | 开局声望 +30 |
| `dao_zheng` 正统 | 记得位格的重量 | 证位成功率 +5 |
| `shen_qian` 香火百万 | 记得怎么求人 | 传教成功率 +10% |
| `war_zhenjun` 弑神 | 记得它怎么死的 | 对高境敌人首战伤害 +20%（一次性） |
| `guo_xueji` 血祭 | 记得血的味道 | 血香火转化 +10%，开局业力 +20 |

### 9.2 代价（必须有）

| 代价 | 说明 |
|---|---|
| 血债 +5% | 接上"世界记得你"，与百世书原有的 +10% 叠加 |
| NPC 有 20% 概率说「我好像见过你」 | 纯文本，但玩家会心里一紧 |
| 本局年谱开头多一行 | 「你记得一些不该记得的事。」 |

### 9.3 为什么残忆给的是"信息"而不是"力量"

这是全篇唯一容易做崩的地方。

如果残忆给战力，那"轮回"就变成了滚雪球——死得越多越强，正好和"残酷"相反，玩家会主动送死刷残忆。

所以 10 项里 8 项是**信息或位置**（灵气、悟性、配方、声望、方位），只有 2 项直接涉及战斗，且都是**一次性、幅度小**（+5 证位率、首战 +20%）。

**知道秘境在哪 ≠ 打得过秘境。** 这就是"记得"和"强大"的区别。

## 十二、数值校验

### 12.1 对现有平衡的影响：**零**

功过格不改任何字段。`unlockAch` 只写 `S.ach` 和 `localStorage`，`S.ach` 不参与任何公式（我已核对 `computePower`、`monthXiuwei`、`monthXianghuo`、`craftRateOf`、`breakRate` 全部不读它）。

### 12.2 残忆的收益上限

| 残忆 | 折算 |
|---|---|
| 灵气 +1 级 | 修炼速度 ×(1.0/0.8)= **+25%**（以普通→浓郁为例），仅炼气期明显 |
| 悟性 +2 | 月修为 +10%，约等于 2 年进度 |
| 一艺三级 | 省 300 熟练度 ≈ 20~30 炉 |
| 天赋 +2 | 约 +10~15 战力 |
| 声望 +30 | 一次宗门任务的三倍 |

最大一档（灵气 +1）在 52 年金丹的总盘里，约等于**提前 2~3 年**——不到全程 5%。可接受。

### 12.3 触发性能

108 条 `test`，绝大多数是 `s.xRealm >= n` 这类单次比较，开销可忽略。

真正的开销在存储读取：`localStorage.getItem + JSON.parse` 单次约 0.05~0.2ms。若在循环里每条都读一次，108 次就是 **5~20ms**——手机上每月结算会明显一顿。

**所以 5.1 的 `checkAch` 把 `achDisk()` 提到循环外只读一次。** 这是这个系统唯一的性能坑，很容易写错：`achHas()` 单看是有缓存语义的名字，但它每次都真的 parse。

### 12.4 达成曲线估算

一局到金丹约 300~600 回合：

| 档 | 一局预期 | 说明 |
|---|---|---|
| 传闻 | 12~15 / 21 | 大部分必得 |
| 载录 | 8~12 / 33 | 看玩法 |
| 立传 | 3~5 / 24 | 需要偏科 |
| 入典 | 0~2 / 12 | 长线 |
| 天书 | 0 / 4 | 多局 |
| 过格 | 3~6 / 18 | 死的次数 |
| 隐格 | 1~3 / 15 | 偶然 |

**一局 30~45 个。** 这个密度刚好：总有 3~5 个"就差一点"，但不会变成清单一屏。

## 十四、不做原则

1. **不给任何数值奖励**——不给灵石、不给战力、不给悟道点、不给突破加成。
2. **不做"累计击杀 1000"这类刷量成就**——一旦可刷，玩家就会刷。
3. **不在死亡时清空**——功过格是唯一跨死亡的东西，这是它的全部价值。
4. **不做全服排行 / 不做完成度百分比**——完成度会诱导补齐，补出来的都不是故事。
5. **过格不扣分**——已经死过一次了，不用再罚。
6. **隐藏成就的条件必须真的藏住**——不要写「？(达成 3 次后显示)」，那等于没藏。
7. **称号不许有数值**——它是别人怎么看你，不是你多强。
