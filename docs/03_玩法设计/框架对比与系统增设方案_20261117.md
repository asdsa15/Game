# 框架对比与系统增设方案

> 日期：2026-11-17
> 性质：**方案稿，未修改任何代码。** 经评审确认后再排实施。
> 方法：取五个同类项目做参照（两款商业标杆、两款开源代表作、一款 AI 前沿项目），与本项目 v8.0 现状逐系统对比，得出「修改项 / 增设项 / 不采纳项」三张清单。
> 参照对象：
> - 《想不想修真》——文字放置九年长青标杆，体系最全
> - 《一念逍遥》——吉比特水墨放置，养成深度标杆
> - 《云隐修仙录》（开源）——文字放置 RPG，单机叙事标杆，与本项目定位最接近
> - vue-XiuXianGame「我的文字修仙全靠刷」（开源 1.8k★）——纯前端单文件，与本项目技术栈最接近
> - Cultivation World Simulator（开源 1.7k★）——AI Agent 修仙世界模拟器，趋势参照

---

## 一、先说结论

**本项目的框架底子不输参照项目，差异不在"系统数量"，在三处：**

1. **缺的是"人"的玩法线**：参照项目都有"师徒—收徒—开宗"的人才纵向线，本项目 NPC 只有平辈关系（恩义/好感/道侣），上下级关系整条缺失。v8.0 归档的 10 条成就里有 4 条（逆徒/杀师/开宗/断人道途）都卡在这里。
2. **缺的是"养成纵深"**：参照项目的法宝/灵兽都有"从小养到大"的纵深（本命法宝、灵兽内丹、器魂），本项目法器是买断式、御兽有字段无系统，养成长线在金丹之后就断了。
3. **缺的是"劫的分量"**：渡劫在参照项目里是独立系统（云隐五类天劫各有克制法、想不想修真失败掉级），本项目渡劫是一个判定按钮——而素材库的五类天劫（三问雷、倒天河、无灯焰、折骨风、故人关）已经备好，只差接上。

另有一条**趋势判断**：2026 年同类项目前五名里三个深度集成 AI（NPC 自主决策、动态叙事）。本项目已有 `INTENTS` 文字意图系统，是这个方向的地基——但纯前端单文件的定位决定了 AI 只能做"可选增强"，不能做依赖。

## 四、修改清单（对现有系统动刀）

### M1. 天劫五类化（P0）

- **现状**：渡劫是一个成功率判定；天劫只是战斗的一种败因。
- **改法**：新增 `TRIBULATION` 表（5 类：三问雷 / 倒天河 / 无灯焰 / 折骨风 / 故人关——素材库已备名与形貌）。每类劫对应不同克制条件：三问雷验道心、倒天河验气海（吞海功等水系功法克制）、无灯焰验神器、折骨风验肉身（BODIES）、故人关验恩义（钩子清账则劫轻）。破境时按主修属性随机/定向抽一类。
- **收益**：渡劫从"赌一次"变成"考前准备"，五行功法、肉身、恩义账全部被劫串联起来。
- **改动范围**：`openBreak` / `xianBreakRate` / 新表；`test_play` 补劫类断言。
- **风险**：低。判定入口不变，只加"劫类选择"与"克法加成"两层。

### M2. 肉身线核对与补齐（P0，先核对）

- **现状**：`data.js` 行 717 有 `BODIES` 表，但 README 未列其为已实现系统。**先核对**：若已实现淬体，则只需数值校准；若只是数据，则按"九阶淬体"补一条支线（消耗灵石+草药，抬气血卸力，给折骨风的克法一个落点）。
- **改动范围**：`BODIES` + 打坐/战斗属性面板。
- **风险**：低。纯增量，不动现有判定。

### M3. 黑市渠道落地（P1）

- **现状**：`SELL_CHANNELS` 设计了宗门/坊市/拍卖/黑市四条，实际卖出仍按单一市价。
- **改法**：卖出面板按渠道分页：宗门（贡献结算，声望+）、坊市（现市价）、拍卖（走拍卖会流程）、**黑市**（价高 3~5 成，但业力+、被祀部/宗门察觉的概率+）。黑市与"业力"直接挂钩，魔道线多一条真实收入。
- **改动范围**：`openSell` / `sellMul` / `SELL_CHANNELS` 接线。
- **风险**：低。v6.3 就有设计稿，只是没接。

### M4. 百世书深化：转世起点修正（P1）

- **现状**：百世书可烧页重来，前世残忆解锁跨世成就与记忆加成。
- **参照**：云隐"轮回道果"——每一世的路沉淀为下一世的底子，转世改变**起点与可选流派**。
- **改法**：前世结局类型决定来世创角加成（登仙→来世灵根 +1 档；真君→来世香火起点 +N；魔道→来世业力事件频发但神通上限 +1）。加一张 `DAOGUO` 道果表，读档时按前世最末结局注入。
- **改动范围**：`applyMemory` / `draftInit` / 新表。
- **风险**：中。多周目数值平衡需要实测；先只做"起点修正"不做"流派锁定"，可控。

### M5. 两层指令坞（P0，体验项）

- **现状**：常驻区 18 项挤一排，手机要滚两屏。v8.0 报告列为"下一步最该做的体验改造"。
- **改法**：按「修炼 / 经营 / 人事 / 其他」四组折叠；首屏常驻 6 项高频（打坐、破境、历练、坊市、宗门、恩义）。
- **改动范围**：`renderDock` / `dockItems`。
- **风险**：低。纯 UI。

### M6. 叙事扩写：道书 2 → 6 部（P0，纯文本）

- **现状**：`DAOSHU` 仅 2 部。素材库《03_文本库》已备齐 6 部 × 4 层全文（《九寰天书·地字卷》《梅花易·残页》《太阴吐纳养轮经·注本》《香火成神法·邪注本》《百炼成仙道法·凡本》《渡厄三则》）。
- **改法**：六部文本按 `do_readbook` 的层读结构直接灌入；其中《渡厄三则》四读带跨世钩【前世一命】，与 M4 联动。
- **改动范围**：纯 `DAOSHU` 数据；`do_readbook` 门槛字段对齐。
- **风险**：低。`test_text.js` 护栏已有，文与账不一致会被抓。

## 五、增设清单（新系统）

### A1. 师徒系统（P0）

- **参照**：参照项目里没有现成的"收徒"玩法（想不想修真只有门派），这是本项目差异化机会，也是 v8.0 建议下一步的第 3 位。
- **设计要点**：
  - 收徒条件：金丹以上、声望 ≥ N、无逆徒记录；
  - 徒弟即 NPC：从 `NPC_POOL` 低境界者中生成，带资质随机；
  - 授业：每月传功（耗自身修为，徒修为+）、赠功法（同源共鸣对徒生效）；
  - 徒的三条出路：出师立谢（人锚+"传道"成就）、叛师（业力+、可追杀→"逆徒"成就）、先我而亡（葬礼、"白发人"事件）；
  - 与锚定联动：**徒是人锚的最强形态**（v8.0 钩子系统直接复用）。
- **改动范围**：新表 `DISCIPLES`；ACT 入口 `openApprentice` / `do_teach`；成就接线（逆徒/杀师/传道）。
- **解锁 3 条成就、接 3 条既有线**（人锚、宗门、恩义）——性价比最高。

### A2. 御兽系统（P0）

- **参照**：想不想修真（散仙解锁御兽）、一念逍遥（灵兽内丹共鸣）、vue-XXG（灵宠）。
- **设计要点**：
  - 兽栏挂在洞府（上限按灵气档位）；
  - 妖物来源复用既有"妖物认亲"奇遇与猎妖历练；
  - 培养两轴：亲密度（喂食/同行）与妖力（吞噬同类材料）；
  - **出战**：进战斗的"战前准备"入口（v8.0 报告建议与既有入口合并），灵兽作第 4 个战斗位，出招由亲密度决定（高亲密护主挡卸力，低亲密可能反噬）；
  - 神道线特例：灵兽可封"兽官"（参照 SHENWEI 品级），吃香火俸禄。
- **改动范围**：新表 `YAOSHOU`；ACT `openKennel` / 战前准备合并；战斗 `renderCombat` 第 4 位。

### A3. 开宗立派（P1）

- **参照**：一念逍遥宗门是加入式，无自立线；AI 模拟器有组织意志。本项目做**单人开宗**：自立门户、立规（从古语短语素材选誓词）、收徒（接 A1）、招外门（NPC 流入）。
- **设计要点**：宗门等级五档（茅庐→山门→宗派→大宗→仙统）；门规影响收徒资质与叛徒率；宗门月耗（灵石）与月入（供奉）；开宗后与青云宗关系变化（友/仇/中立）。
- **改动范围**：新表 `SECT_SELF`；复用 `CLAN`（家族）与 A1 的大量逻辑。

### A4. 本命法宝（P1）

- **参照**：一念逍遥本命法宝（心意相通）、云隐器魂。
- **设计要点**：金丹后可祭炼一件法器为本命；本命四阶（认主→通灵→共命→合道）；祭炼材料=同五行材料+自身修为；**本命法宝可作物锚**（道胎锚定系统"物锚"的最强形态），同时是"共命"——本命碎，人重伤。
- **改动范围**：`ARTIFACT_EXT` 加 `natal` 字段；新 ACT `openNatal`；锚定 `resolveAnchors` 加分支。

### A5. 上古遗迹（P1）

- **参照**：一念逍遥秘境层层解锁；想不想修真刷图。
- **设计要点**：舆图碎片来源（历练/拍卖/道书三读线索）；集齐开启一处遗迹，遗迹为**一次性 Rogue 短程**（5~7 个事件节点，走完得一件天阶/仙阶遗物或断篇线索）；与"补回断掉的四境"主线（登仙结局）绑定。
- **改动范围**：新表 `RUINS`；复用 ENCOUNTERS 的选项结构。

### A6. 魔道/争斗线补全（P1，v8.0 清单打包）

- 夺仙基（对战胜利后可选"夺基"，对应"断人道途"成就）、血祭（魔门献祭换取速成，业力大增）、凡人杀戮（凡人作为战斗单位）、旧仇寻仇击杀（`S.enemy` 接战斗路径）、自定庙号（真君命名，撞名真君触发"僭越"事件）。
- **注**：这五项 v8.0 报告已列明，本方案仅确认"打包做"的顺序——都挂在战斗与业力两个既有轴上，建议与 A1/A3 同批（都需要 NPC 存活/死亡判定）。

### A7. 释修与魔门人材表现层（P2）

- `SHIXIU`（僧侣→世尊）、`RENCAI`（下材→绝材）数据闲置。释修线挂神道（寺=庙的平行形态，香火互通）；魔门人材挂 A6 血祭（人材价值=献祭收益）。
- **改动范围**：先表现层（面板/事件文案），后数值层。

### A8. LLM 论道增强（P2，可选，默认关）

- **参照**：AI 模拟器 NPC 双驱动；CSDN 文章结论"AI 已成同类标配"。
- **设计要点**：现有 `INTENTS`（规则层）保持为默认与保底；增加可选开关"道友论道 · 通玄版"——论道与自由输入接 LLM API（用户自填 key），规则层结果作为 LLM 不可用时的回退。
- **改动范围**：`do_ia` / `do_iaans` 附近加 provider 抽象。
- **风险**：中。联网依赖与费用由用户自担；**必须保证关闭时零功能损失**。

## 六、明确不采纳项（及理由）

1. **千人宗门战 / 跨服 / 异界入侵**（一念逍遥）：多人在线与本项目"单文件单机"定位冲突，不采纳。
2. **离线挂机收益**（想不想修真/云隐核心）：本项目节奏是"按月决策"，每个决定都有代价；引入"秒涨修为"会摧毁决策制。若未来要做，只做"结存：读档时间戳→一次性补算少量修为"，且默认关。**列入 P2 观察，不排期**。
3. **氪金线 / 抽卡古宝**：商业模式不采纳；"古宝收集"的玩法骨架可借（作遗迹遗物）。
4. **小游戏**（vue-XXG 骰子/猜拳）：与题材气质不符，不采纳。
5. **双修育崽**（一念逍遥仙崽梦园）：道侣线已有；育崽超出单人文字叙事的承载，不采纳（道侣结胎另议）。
