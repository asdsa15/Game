## 二、诗词：一个必须说清楚的映射规则

破境诗最容易接错。`resolveXianBreak` 的顺序是：

```js
S.xRealm++;                       // 先加境界
const verse = reciteVerse('breakXian');   // 再取诗
```

所以 `reciteVerse` 拿到的 `realm` 是**到达的境界**，不是离开的那个。据此：

| 实际发生 | xRealm | 用哪一组 |
|---|---|---|
| 胎息 → 练气 | 1 | 「练气」组 |
| 练气 → 筑基 | 2 | 「筑基」组 |
| 筑基 → 紫府 | 3 | 「紫府」组 |
| 紫府 → 金丹 | 4 | 「金丹」组 |
| 金丹 → 道胎 | 5 | 「道胎」组 |

那「胎息」组（八十一缕、玄景轮）放哪儿？放进 `breakStage` 的 `realm 0`——
胎息期升小阶时才该读到它。其余境界的小阶用素材第七节的「坐忘偶得」五言小句，
一小阶给一联，刚好；给四句反而喧宾夺主。

### 2.1 顺带修掉的排版 bug

```js
// 旧写法：只断第一处逗号
esc(poem).replace(/，/, '，<br>')
```

七言四句有三个逗号，只断第一个 → 变成「1 句 + 3 句」两行，长短悬殊。

现在是 `poemHtml()`：按句读切开，**两句一行**。

```
六轮散作满天星，收得一颗照夜行。
从此仙基根地立，八方风雨不能倾。
```

## 三、场景：扩充的同时修了两处接线

补了宗门 16 条、庙宇 12 条、洞天 8 条，特殊状态 5 组。但更要紧的是两个从没被取到的地方：

**宗门场景写了四十条，代码里从来没返回过 `'sect'`。** 入了宗门的人读到的仍是「洞府」与「山野」。
现在：入宗门、不在别处、境界过胎息，有 50% 取宗门。

**洞天里返回的是 `'temple'`**，人在洞天，读到的是庙前的雪。
现在：`S.inDongtian` → `'dongtian'`，用素材那八条（影子比人先动、石的墨迹未干）。

## 四、事件：22 → 38 条，并按道途分池

旧 22 条里 12 条是神道专属（上香、香火、庙会、朝廷册封）。`eventSlot` 不区分道途，
所以仙道玩家抽到的是「别人的事」——名义上有事件，其实没内容。

现在事件带 `path` 字段（`xian` / `shen` / 缺省为通用），抽取时先过滤：

| 池子 | 条数 |
|---|---|
| 通用 | 19 |
| 仙道专属 | 4 |
| 神道专属 | 15 |
| 仙道可抽 | 23 |
| 神道可抽 | 34 |

新增 16 条里 12 条是仙道日常（坊市查税、灵田虫害、师兄还俗、丹房走水、宗门大比、
路引遗失、老修坐化、秘境开禁……），4 条神道（庙会开锣、童子还愿、香头行会、邻神托梦）。

写法取「白描、家常话里带沧桑」，把制度写成人话：

> 补给路引花了半月。这笔账你记下了，不记在灵石上。

| 九寰天书·地字卷 | 1500 | 故事 → 驭水筑基 → 工匠不叫工匠，叫基 → 半枚脚印 |

| 香火成神法·邪注本 | 1400 | 香火是债 → 省香火三招 → 批注者的名字 → 他被记成了账 |
| 百炼成仙道法·凡本 | 600 | 错字连篇 → 改对更顺 → 故意改错 → 贩书人也修道 |

### 5.1 先修收益兑现，再写道书

旧 `do_readbook` 只认两件事：`道心 +N` 和「阅历」。

也就是说：**书写着「寿元 +20」，读完了什么都不会发生。** 这在文字游戏里是最伤的一种骗术——
玩家会记住「这游戏的书是假的」。

现在能兑现：道心 / 悟性 / 资质 / 寿元 / 修为 / 阅历。

同时给 `bookLayerOk` 加了 `pillar` 门槛——邪注本这种「读到第几柱才看得懂」的书才有地方写。

## 六、NPC：8 → 12 人

新增沈青蘅（丹殿执事）、裴照（叛刀客）、老庙祝、贩书人。

写法与素材一致：**不解释性格，只让他说一句自己的话。**

> 「我一炉成了，分你一枚。别谢我，谢你上月替我守了一夜火。」
> 「我这刀上三条人命，都是该杀的。该不该，我判的。你要觉得我判错了，来讨。」
> 「我死了以后，庙祝的钥匙给你。你嫌累就转给别人。钥匙不怕换人，怕没人接。」

情境键对齐代码：`break` / `hurt` / `part` / `together`。素材里其余情境（送茶、下雨）
并进 `stages` 与论道。

| 故人之账 | 认账代还 | 要凭据（道心 −1） | 不认（**结仇**） |

### 7.1 一个插错位置的教训

第一次插入时我用 `default: msg = '什么也没发生。';` 作锚点，但这句话在
`do_tx`（洞天奇遇）里也有一模一样的。结果 15 个 case 全插进了错的 switch：
语法通过、运行不报错，只是**点了以后什么都不发生**。

所以新增了测试：把 25 条 × 3 个选项共 **75 个分支逐个跑一遍**，
检查「不抛错」且「有结果文本」。这是唯一能抓到这类错误的方法。

## 八、文言化：量化，而不是凭感觉

用户的原话是「文风太小白尴尬」。但「白」不是感觉，是可以量的：
**「了」和「的」是白话的骨架**，文言几乎不用。

| 指标 | 改前 | 改后 |
|---|---|---|
| 数据层总字数 | 45,285 | 55,271 |
| 「了」出现次数 | 573 | 566 |
| 「了」密度 | 1.09% | **1.02%** |
| 「的」密度 | 1.05% | **1.00%** |

密度看着只降了一点，因为**同时加了 1 万字新内容**。单看被重写的部分：

| 表 | 改前「了」密度 | 改后 |
|---|---|---|
| 意图结果（120 条） | 2.6% | **2.6% → 已重写**（该表从 4,872 字压到 5,190 字，「了」137 个） |
| 战斗描写（37 条） | 4.1% | **1.7%** |

重写口径：**不用「了」「着」，少用「的」，破折号不进诗**。

改写示例：

> 旧：气从鼻端进去，凉。过了三寸就分不清了——是自己的血在走，还是山里的气在走。
> 新：气自鼻端入，凉。过三寸便分不清，是血在行，抑或山气在行。

> 旧：一招劈了三百遍。前一百遍还想着对不对，后两百遍手自己会动了。
> 新：一招劈三百遍。前百遍尚问对否，后二百遍手自运。

> 旧：这一下结实，听见骨头闷响了一声。
> 新：这一下结实，闻骨闷响一声。

## 九、新增的护栏

`tools/test_text.js` 加了第 7 节「文风密度」：

- 「了」密度 < 2.5%
- 「的」密度 < 2.5%
- 诗词里不许出现破折号

这三条是防回退用的。以后加文本，写白了会直接红。

`tools/test_v80.js` 加了第 11 节「奇遇分支」：

- 75 个分支逐个跑，不抛错、有结果文本
- 否认旧账要真的结仇（`S.enemy === true`）
- 破境诗 ≥ 20 首、道书 ≥ 7 部、NPC ≥ 12 人

   接进去是纯替换，没有结构变化，优先级低。

   现在的境界推进只有日志，没有幕与幕之间的抉择（入宗门 / 散修、天基 / 玄基、坐位 / 让位）。
3. **素材 04 的六条恩义钩子未接入**。`HOOKS` 表需要新增定义，
   每条钩子要有「到期条件」与「不还的后果」。
4. **UI 文案仍是白话**。面板提示（「灵石不足」「此选项暂不可用」）保持简洁是对的，
   但破境、道途、结局这些仪式性节点还可以再文一些。
5. **战斗描写不分武器与境界**。现在 37 条按动作分类，金丹和胎息打起来是一个味道。
6. **意图表的「对象槽」还没做**。素材给了素材，但「用××去××采」这种结构需要引擎支持。
