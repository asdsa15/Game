## 一、这一批做了什么（三句话）

1. **P0 立骨架**：`packages/{contracts,content,core,sim}` 四个包 + 根 tsconfig / ESLint 边界 / Prettier / CI / `.env.example` / 统一脚本；`npm run verify` 一条命令跑完 lint→format→typecheck→test→内容校验。
2. **P1a 搬数据**：旧 `wxcs3-data.js` 的 **116 张表**由脚本抽成 JSON，同时生成**签入仓库的类型快照**与 zod schema，配套语义校验（id 唯一 / 数值域 / 交叉引用）与**逐表 deepEqual 旧版对照**。
3. **P1b 立内核**：`GameState` 外壳、状态携带的随机源、`apply(进快照 → 出新快照 + 事件流)`、显式迁移链（旧档整包进 `domains.legacy`），以及四个骨架命令。

一处没变：**旧单文件版一行源码没动**，玩家侧行为与 P2 前完全一致（方案 §8.3 的并行期约束）。

## 二、P0 基建

### 2.1 工作区与任务图

```text
package.json            npm workspaces：packages/* + apps/api + apps/web
tsconfig.base.json      ES2022 / nodenext / strict / verbatimModuleSyntax
eslint.config.mjs       扁平配置 + 包边界规则
.prettierrc.json        100 列 / 单引号 / 无分号偏好之外的默认
.github/workflows/ci.yml  lint → format:check → typecheck → test → 内容校验
.env.example            与 apps/api/src/env.ts 的 zod Schema 一一对应
```

| 命令 | 作用 |
|---|---|
| `npm run verify` | 五道闸门串起来跑，CI 与本地同一条命令 |
| `npm run build:packages` | contracts / core 产出 `dist`（其余两个包无产物） |
| `npm run typecheck` | 四包 + 两个应用 |
| `npm run test` | api 53 项 + 四包 46 项 |
| `npm run check:content` | 116 表类型 + 语义 |
| `npm run check:content:fresh` | 产物必须与 `wxcs3-data.js` 同步（防"改了数据忘了重抽"） |

**顺手修掉一个潜伏的破坏**：根 `package.json` 里的 `"type": "module"` 会让 `tools/*.js`
（39 个 CommonJS 测试脚本）全部报 `require is not defined`——上一轮建工作区时加上的，
此后没人跑过旧版全量回归，所以一直没暴露。本轮把它删掉：新代码里没有根级 `.js`
（`scripts/dev.mjs`、`eslint.config.mjs` 都是 `.mjs`，各 app/package 自己的 `package.json`
也都声明了 `type: module`），删掉后 `python tools/run_all.py` 恢复 **ALL GREEN（39 tests + 6 checks）**。

### 2.2 边界不是写在文档里，是被 lint 拦下来的

`packages/core/src/**` 禁止：`window` / `document` / `localStorage` / `fetch` / `navigator`、`Math.random`、`Date.now`、`node:*`、任何前端框架。

理由只有一条：**服务端要用同一个内核做重放校验**（方案 §5.3）。内核一旦碰了宿主，重放结果就不可信，"防改分"就是句空话。时钟与随机数因此都从 `ctx` 注入，唯一读系统时钟的地方被关在 `engine/clock.ts` 一个文件里，带一行 `eslint-disable` 与理由。

### 2.3 契约包

`@wendao/contracts` 收敛了存档信封、账号、结局、榜单、内容版本、错误体六组 schema。
本轮由 `@wendao/core` 真实消费（存档进出都走它），不是空包。

`apps/api` 仍用它自己那份 `lib/save.ts`——**这是有意为之**：服务端运行时读的是 `dist`，若此刻切过去，`npm ci` 后不 build 就起不来。切换点放在 P4（那时前端也要这份契约，一次改三处不如一次改完）。

## 三、P1a 内容包

### 3.1 抽取：跑一遍旧文件，而不是手抄

`tools/extract-content.mjs` 在 `vm` 里执行旧 `wxcs3-data.js`，取 `window.WXCS3_DATA`，按 10 个域切成 `packages/content/tables/*.json`。

- 不手抄、不正则抠字面量：数据里有大量转义与换行，手抄必丢。
- 域映射**严丝合缝**校验：未归类 / 表里没有 / 重复，三者任一出现就抛错。第一次跑就抓到 `UNLOCK_XIAN` / `UNLOCK_SHEN` 两张漏网的表。
- 产物可重复：同输入必然同输出，`--check` 模式只比对不写，CI 用它防漂移。

**实测：116 表 / 1,092 条 / 文本 90,370 字 / 指纹 `ce7cca50c29007f7`。**
（方案写"117 张表"，实测旧对象是 116 个键；以实测为准。）

### 3.2 类型快照：签入仓库，而不是运行时推断

`tables.schema.json` 是 116 张表的 shape 快照（object / array / 标量 / 可选 / 可空），由抽取器一次生成并随数据一起 review；`src/schema.ts` 拿它构建 zod schema。

为什么不"运行时从数据推断"：那样等于**自己验自己**，永远通过。快照签入后，谁把数字改成字符串、把可选改成必填，CI 当场红。

### 3.3 语义校验：类型管不到的那一半

`src/validate.ts` 逐条查会真出事的东西：

| 检查 | 为什么 |
|---|---|
| id 重复 | 后一条静默覆盖前一条，玩家永远拿不到那件东西 |
| 交叉引用（配方→材料/产物、坊市→商品、技艺书→四艺、杀招→招式、奇遇/传法的 `enc:`/`tx:` 跳转、`bookOpt.book` → 道书） | 引用写错 = 点了没反应，最难查 |
| 价格非负 | 买一次倒赚灵石 |
| 品相权重和 = 1 | 高品质掉落率悄悄漂移，没人看得出来 |
| `lv` 递增 / 成功率 0~1 / 区间 min≤max / 渠道倍率 >0 | 同上，都是"看起来对、其实穿"的项 |

**实测：116 表 0 issue。** 校验器自身也有反向测试（喂坏数据必须报错），避免"永远返回空"的假绿。

### 3.4 旧版对照：比"文本差 <1%"更狠

`test/legacy-parity.test.ts` 在测试里重新跑一遍旧 `wxcs3-data.js`，**逐表 deepEqual** + 文本总量逐字相等。

方案写的验收是"差 <1%"，这里收紧成 0：1% 允许丢 900 字，正好是一段判词或一首诗——丢了玩家不会报错，只会觉得"这里怎么没味道了"。

## 四、P1b 内核骨架

### 4.1 状态只定外壳

```ts
GameState = {
  meta: { format, stateVersion, contentVersion, seed, rngState, rngDraws,
          turn, year, month, xun, phase, started, createdAt, importedFrom? },
  domains: { legacy? , ... }   // 各域 P2 分批搬入
}
```

方案 §11 自己写了风险："`GameState` 反复改，存档 schema 天天变"。对策照做：**P1b 只定外壳 + 元字段**，旧 state 的二百多个字段原样进 `domains.legacy`，P2 每搬完一个域加一条迁移、`stateVersion` +1。现在就把字段抄一遍，等于把旧形状复制进新结构，之后每搬一域都要再修一次迁移。

### 4.2 `apply`：可变草稿，不可变边界

```ts
apply(state, cmd, args) → { state, events }
```

三条性质都有断言：

| 性质 | 测试 |
|---|---|
| 不原地改 | 入参深比较后不变；返回新对象 |
| 同 seed 同结果 | 同状态 + 同命令 → 指纹相同 |
| 出错不留脏 | 命令里改一半再抛错，旧快照完好 |

不引 immer：`GameState` 是纯 JSON，`structuredClone` 足够，少一个依赖、少一层 Proxy 开销。方案写 immer 的地方注释了取舍，P2 若出现巨型状态再换，接口不变。

### 4.3 随机源与指纹

- `rngState` 住在存档里，`apply` 读出 → 跑 → 写回；`rngDraws` 记录掷了几次（诊断"有人绕过 ctx.rng"）。
- mulberry32 十行实现，便于逐行对着旧版 `RULES.mulberry32` 核对——重构期最怕"随机源换了实现但没人发现序列变了"。
- `hashState` 用稳定序列化 + FNV-1a 64（BigInt），不依赖 `node:crypto`，浏览器与 Node 同结果。

### 4.4 迁移链：显式、缺环即报错

`migrations/001_from_legacy.ts` 把旧 blob 规整成外壳：

- 种子：旧档整数 `seed` 直接当 `mulberry32` 状态（旧版 `setSeed(n)` 就是这么做的），**不换成字符串再哈希**——否则"读档后继续玩"的随机序列第一步就分叉。
- 没有种子的极老档用版本号派生，并写 `importedFrom`。
- 版本高于程序 → `SAVE_VERSION_UNSUPPORTED`；格式认不出 → `SAVE_UNRECOGNIZED`；迁移后不合 schema → `SAVE_STATE_INVALID`。**一律显式失败，不兜底**。

### 4.5 四个骨架命令

`cmdStart`（create→play）、`cmdAdvanceXun`（唯一时间入口，三旬一月）、`cmdLog`（只发事件、不改状态）、`cmdSetFlag`。
刻意不含任何玩法数值：打坐给多少修为、破境成功率多少，属于 P2a，不在这里发明。

## 六、与方案的差异（都已落在实现里）

| 方案 | 实际 | 为什么 |
|---|---|---|
| pnpm workspace + Turbo | **npm workspaces**，不引 Turbo | 方案 §14.3 已改 npm；单机无远程缓存收益，任务图由 `verify` 与 CI 承担。四包体量下 Turbo 只增加一个二进制依赖 |
| docker-compose + 托管 PG | 不引入 | §14.1 已取消；数据库走 PGlite |
| immer | `structuredClone` | 纯 JSON 状态足够；少一层依赖，接口不变 |
| 117 张表 | **116 张** | 以实测旧对象键数为准，域映射脚本强制全覆盖 |
| ESLint 边界管整个 `core` 包 | 只管 `packages/core/src/**` | 测试与 `vitest.config.ts` 需要 `node:url`；边界要管的是"会被打进产物的规则代码" |
| 旧档校验"zod 全量校验 GameState" | 信封层不解析、内核层强校验 | 与 §13.2 的既有决定一致：服务端不该随玩法字段变动而改 |
| 「文本差 <1%」 | 逐表 deepEqual + 逐字相等 | 1% 的口子足够丢一整段判词 |
| apps/api 立即切到 contracts | 暂不切，P4 一次改三处 | api 运行时读 dist，`npm ci` 后不 build 就起不来；契约现由 core 真实消费 |
| lint / format 覆盖 `apps/**` | **本轮只覆盖 `packages/**` 与根配置** | 工作区里 `apps/**` 还有上一轮未提交的改动（文档重整与前端外壳微调），把它们一并格式化会混进别人的未完成工作。等那批改动落库后，把 `apps` 加回 `lint` / `format:check` 两个脚本即可（配置本身已就绪，`eslint.config.mjs` 对 apps 不设特例） |
