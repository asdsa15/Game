# 后端化改造方案 · 三形态对比与渐进路线

> 日期：2026-11-17
> 性质：**方案稿，未修改任何代码。** 架构级改动，评审确认后再动工。
> 缘起：《框架对比与系统增设方案》中，纯前端单文件定位压住了三项潜力——LLM 动态叙事、NPC 世界演化、多人/云存档。本文回答"能否换后端实现、怎么换、代价多大"。

---

## 一、先回答：能，而且有一条便宜的路

**关键事实：本项目是纯 JavaScript。`wxcs3-game.js` 已经在 Node DOM 桩里跑 209 条断言——这意味着游戏逻辑天然可以在后端复用，不需要重写成 Python。**

但"改后端"有三个不同的档位，代价差一个数量级：

| 形态 | 做法 | 能得到 | 代价 | 适合 |
|---|---|---|---|---|
| **A. 维持纯前端** | 什么都不改 | 现状 | 0 | 只想单机玩到底 |
| **B. 混合架构**（推荐） | 前端保留为"玩家层"，新增薄后端作"世界层 + 服务层" | 云存档、LLM 论道、NPC 世界演化、排行 | 低~中，渐进 | 想要 AI 与世界感，又不肯放弃单机 |
| **C. 全盘后端重写** | 逻辑整体迁 Node 后端，前端只留壳 | 世界模拟器形态、真多人、后端权威数值 | 高（数月级） | 做成 AI 修仙世界模拟器的野心 |

**推荐 B**。理由三条：

1. v8.0 刚打稳（209 断言、战斗重构、文字系统），全盘重写等于推翻自己验收过的东西；
2. B 的每一步都独立可玩、可回退——与项目"单批回退"的工程习惯一致；
3. B 的远期形态就是 C：等世界层稳定了，逻辑迁移只是"把 game.js 搬个地方跑"，路是通的，不锁死。

## 二、B 形态的架构设计

### 2.1 分层原则：玩家层与世界层分离

```
┌────────────────────────────┐
│ 前端（保持 v8.x，不动核心）    │
│  wxcs3-game.js  玩家层逻辑    │  ← 月推进、战斗、四艺、恩义、成就……
│  api.js（新增）  按需调后端    │  ← 云存档 / 论道 / 世界简报
└──────────┬─────────────────┘
           │ REST（+ 可选 SSE）
┌──────────▼─────────────────┐
│ 后端（新增，Node.js）         │
│  存档服务  save.js            │  ← 账号 + 多端云存档
│  论道代理  llm.js             │  ← LLM key 在服务端，规则层保底
│  世界层    world/             │  ← 玩家之外的一切：
│    tick.js  世界月推进        │     NPC 演化、势力消长、
│    orgs.js  组织意志(规则AI)  │     宗门/朝廷/魔门动向
│    npc.js   NPC 自主决策      │
│  数据  SQLite / JSON          │
└────────────────────────────┘
```

**一句话：玩家手里的账还在前端算（权威在前端），玩家之外的世界归后端管。**

这是 B 与 C 的本质区别。C 里前端只是渲染壳；B 里前端仍是完整的游戏，后端是"同时还在运转的那个世界"。

### 2.2 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 运行时 | **Node.js** | game.js 是 JS——`require('./wxcs3-game.js')` 直接复用逻辑与既有测试 |
| 框架 | **Hono 或 Express** | 轻；Hono 与项目"单文件轻量"气质相符 |
| 存储 | **SQLite**（better-sqlite3） | 单文件数据库，符合项目气质；存档/世界状态/排行一张库搞定。首版也可退化为 JSON 文件 |
| LLM | OpenAI 兼容接口代理 | key 存服务端 `.env`；支持本地模型（如 ollama）走同一接口 |
| 通信 | REST 为主，SSE 可选 | 世界简报用拉取即可；SSE 只为"世界发生大事"的即时提示，可后置 |
| 部署 | 本机 `node server/index.js` → NAS/服务器 → Docker 可选 | 从一台电脑到云，同一条命令 |

### 2.4 世界层怎么运转（不依赖 LLM 也成立）

参照 AI 修仙世界模拟器的"组织意志"概念，先用**规则 AI**落地（LLM 后挂）：

1. **世界月推进**：后端维护自己的世界时钟（独立于玩家存档）。每月 NPC 按既有 `NPC_POOL` 规则演化（境界突破、寿命、迁居、结仇结缘）；三大势力（朝廷/宗门联盟/魔门）按各自目标做简单决策（收税、征讨、扩张、封庙）。
2. **世界简报**：前端每月推进后 `GET /world/brief`，拿到本月世界事件包，注入既有 `EVENTS` 叙事流（"山下发生了……"）。世界事件与玩家事件共用 `EVENTS` 的三段式结构。
3. **势力影响玩家**：宗门联盟与魔门的战争状态影响坊市物价（接 `tickMarket`）、巡逻密度（接历练风险）、任务类型（接宗门任务）。
4. **LLM 增强（可选开关）**：论道问答、NPC 对白润色走 `/llm/discuss`；LLM 不可用时自动回退到 `INTENTS` 规则层——**关闭时零功能损失**（对齐上轮方案 A8 的承诺）。

### 2.5 手机端与 APK 的处理

| 端 | 离线模式 | 在线模式 |
|---|---|---|
| 浏览器/PWA | 双击即玩（现状保留） | 打开即连服务器 |
| APK（HBuilderX） | **保持现状**：内嵌离线版 | webview 指向服务器地址 |

APK 做成**双模式**：默认离线单机（现有 649KB dist 不动），设置里填服务器地址即切换在线。`api.js` 所有调用都带"失败静默降级"——后端不可达时游戏照跑，只是没有世界简报和云存档。

## 三、渐进路线（六步，每步独立可玩可回退）

| 步 | 内容 | 量级 | 解锁能力 |
|---|---|---|---|
| **S1** | 后端骨架 + 云存档（账号/多槽/多端同步） | 1~2 天 | 手机电脑存档互通；APK 换机不丢档 |
| **S2** | LLM 论道代理 | 1 天 | 论道/自由输入接真模型，key 不再暴露在客户端 |
| **S3** | 世界层规则 AI（tick + orgs + npc） | 3~5 天 | NPC 自主演化、势力消长——**无需玩家在线，世界照跑** |
| **S4** | 世界简报注入叙事 | 1~2 天 | "你闭关三月，山下已是另一番光景"——世界与玩家剧情咬合 |
| **S5** | 排行 / 多角色 / 传记库 | 2 天 | 历代角色名入"仙谱"；成就跨角色统计 |
| **S6** | （远期）逻辑迁移评估 | 视野心 | 若要真多人/后端权威数值，把 game.js 核心循环迁后端（同代码，成本可控） |

**与上轮玩法六批方案的关系**：
- S3 世界层落地后，上轮方案的 A3 开宗立派（宗门竞争）、A5 遗迹（世界事件触发）、A6 魔道线（势力冲突）都获得更大的舞台；
- S2 落地后，A8 从"可选增强"升级为"服务端标配"；
- 原六批玩法实施**不受阻**——B 形态下玩法照旧在前端做，后端只添世界，两边并行不冲突。

## 四、成本与风险

### 4.1 收益代价总表

| 维度 | A 维持纯前端 | B 混合架构 | C 全盘后端 |
|---|---|---|---|
| 双击即玩 | ✅ | ✅（降级保底） | ❌ |
| 离线可玩 | ✅ | ✅（APK 离线模式保留） | ❌ |
| 云存档/多端 | ❌ | ✅ | ✅ |
| LLM 安全接入 | ❌（key 裸奔） | ✅ | ✅ |
| NPC 世界演化 | ❌（只能随玩家月动） | ✅（独立时钟） | ✅ |
| 数值防作弊 | ❌ | ❌（前端权威） | ✅ |
| 真多人 | ❌ | ❌（要等 S6） | ✅ |
| 改造成本 | 0 | 低~中（S1~S5 约 1~2 周） | 高（数月起） |
| 部署运维 | 无 | 需跑一个进程 | 需服务器运维 |

### 4.2 风险与对策

| 风险 | 对策 |
|---|---|
| 双端状态不一致（玩家月 vs 世界时钟） | 世界 tick 独立于玩家存档；简报按"玩家上次推进至今"取差量，玩家不推进则世界不投喂——**世界跟着玩家的节奏走，只是内容不再全是围着玩家转的** |
| 存档一致性 | S1~S5 保持**前端权威**：后端只存不算；数值作弊防护留给 S6 再议 |
| 复杂度膨胀、忘了单机底线 | 铁律：`api.js` 全部静默降级，后端不可达 = 单机模式，任何测试断言不得依赖后端 |
| 手机体验回归 | APK 保留内嵌离线版作为默认形态，在线模式是增值选项 |
| LLM 费用/滥用 | 服务端限流（每日 N 次）；无 key 或超限时自动回退规则层 |

### 4.3 回退点

- 每步独立提交；S3 世界层可整目录删除，游戏回到 S2 状态无任何残留；
- `api.js` 未接通时与 v8.0 行为逐字节等价（用 209 断言 + 新增 `test_offline.js` 断言"断网可玩"）。

## 五、待你拍板的三个决策点

1. **选哪个形态？** A 维持现状 ／ B 混合架构（推荐）／ C 直接全后端。若选 B，S1（云存档）和 S2（论道代理）可以先做——这两步不碰游戏逻辑，几乎无风险。
2. **世界时钟怎么走？** 建议初版**跟随玩家**（玩家推一月，世界动一月，取差量简报）——叙事密度可控；纯现实时间 tick（离线也在跑）更"活"但会稀释玩家对世界的感知，建议 S3 稳定后再试。
3. **部署目标？** 只在自己电脑玩（localhost 即可）／ 想挂 NAS 或云服务器（要考虑简单鉴权）——影响 S1 是否需要做账号体系（本机玩可以不做账号，单文件 token 即可）。
