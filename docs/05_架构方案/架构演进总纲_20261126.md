## 一、三条已经执行的决策

### 1.1 不做全盘后端重写，保留"混合架构"作为远期选项

后端化方案给了三档：A 纯前端（现状）、B 混合（前端玩家层 + 薄后端世界层）、C 全盘后端。评审结论是 **B 为推荐、C 为远期形态、A 为当下**。

- 项目是纯 JS，`wxcs3-game.js` 能在 Node DOM 桩里跑完整断言，**逻辑天然可后端复用**，不必重写。
- B 的每一步都可独立回退，与项目"单批回退"的工程习惯一致。
- **至今未动工**：没有 `api.js`、没有服务端代码。文档里所有"云存档 / LLM 论道 / 世界演化"仍是设计，不是实现。

### 1.2 不物理拆分老文件，只做"新代码分文件"

`源码拆分评估` 的核心结论，今天仍然成立且已被执行：

1. **单文件大小不是问题**，问题是"改一处要读多少上下文"。
2. **硬拆老文件是高风险**：69% 的函数直接读写全局 `S`，403 个内部函数互调、共享 210 个 `S` 字段，硬拆要动 2786 处引用；且 `S` 会在读档时整体换对象，缓存引用必出静默 bug。
3. **先拆数据、再拆新玩法**：`wxcs3-data.js` 独立（116 表）、`wxcs3-rules.js` 独立（34 纯函数）、新玩法一律进 `wxcs3-ext-*.js`（14 个功能扩展）。

这套"数据 → 规则 → 表现 → 扩展"的分层，是本项目最成功的一次结构改造，也是后续所有扩加能维持 2034 项断言的基础。

### 1.3 分层判据：看调用链，不看函数自身

判断一个函数能不能进 `rules.js`，判据不是"它看起来纯不纯"，而是**它调用链上还有谁在读 `S`**：

| 函数 | 看起来 | 实际 | 结论 |
|---|---|---|---|
| `currentGoal` | 只调 `goalsForLine` | `goalDone` 读 `S.goals` | 留 game |
| `dArtUpkeep` | 只是求和 | `dArtRaw` 读 `S.dArt` | 留 game |
| `fmtNum` | 格式化 | 只依赖参数 | 可搬 rules |

## 二、当前的结构临界点

| 指标 | 实测 | 判断 |
|---|---|---|
| `game.js` | 15,364 行 / 790.8 KB / 533 函数 / 195 ACT | 已到单文件承载上限 |
| 最大执行块 | `ACT.do_cbt` 629 行、`ACT.do_enc` 579 行、`applyState` 332 行 | 四职责混装（规则/文案/结算/渲染） |
| 扩展层 | 15 个文件 / 4,638 行 / **42 个 EXT_ACT**（含模板 1 个） | 正常，模式可持续 |

结论：**扩展机制能吸收"新系统"，吸收不了"对既有流程的反复加厚"**。v11 的杀招、势、符箓乘区三次改动全部落在 `do_cbt` 内部，就是这个临界点的表现。

### 建议路径（未执行）

1. 在 `do_cbt` 内按阶段抽纯函数：`calcGap()`（位格压制）、`resolveCombo()`（杀招链）、`resolveShi()`（势）、`resolveTalisman()`（符箓乘区）；入口只留调度。
2. `do_enc` 同理抽 `resolveEncBranch()`（分支结算）与渲染分离。
3. 抽出后若确实无 `S` 依赖，进 `rules.js`；有依赖则留同文件顶部，**不强行搬文件**。
4. 每抽一步跑一次全量断言（当前 2034 项），保证行为等价。

## 三、扩展协作的四种模式（现行约定）

| 模式 | 机制 | 用于 |
|---|---|---|
| 乘区注册表 | `EXT.registerMul/Add(kind, fn)` → `fateMul/fateAdd` 薄缝 | 命格、天劫、遗物、本命被动 |
| 钩子注册数组 | `preFightRowsHooks` / `fightRowsHooks` / `foeHooks` / `onMonthHooks` | 战斗 UI、敌方回合、月结 |
| 薄缝 + 链式包装 | `fixedCosts2()` / `dockItems()` / `schoolAdmitFav()` | 月账、指令坞、收徒门槛 |
| 状态迁移 + 创角结算 | `applyFruit` / `fruitSnapshot` / `migrateBenming` | 道果、轮回、旧档迁移 |

四条约定（扩展文件头已写死）：不缓存 `S`、动作注册 `EXT_ACT`、自报占旬并登记分档表、只做加法。违反第 1 条会产生**不报错的静默 bug**，是本项目历史上最容易踩的坑。
