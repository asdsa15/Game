## 二、构建链已生效

`mobile/build.py` 的 `art_data_script()` 会把 `art/scenes/*.jpg` 全部转 base64 内联：

```python
for jpg in sorted(art_dir.glob('*.jpg')):
    b64 = base64.b64encode(jpg.read_bytes()).decode('ascii')
    data[jpg.stem] = 'data:image/jpeg;base64,' + b64
```

实测后果：`mobile/dist/index.html` 从 803 KB 增至 **约 8.3 MB**。这是**预期行为**，不是异常——

| | 说明 |
|---|---|
| 为什么这么大 | 33 张 JPEG（5.6 MB）经 base64 编码后膨胀约 1.37 倍，加上源码 657 KB |
| 值得吗 | 值。单文件双击即玩的代价就是体积；抽出去就得起服务器 |
| 想减体积 | 只能压 `art/scenes/*.jpg`（见 `art/pipeline/compress_art.py`），不能压 base64 本身 |

## 五、后续若要加图

```
1. 生成 → art/generated/art/<新键名>.png
2. 跑   → python art/pipeline/compress_art.py --only <新键名>
3. 三处同步：
     wxcs3-art.js 的 KEYS
     compress_art.py 的 KEYS
     game.js 里对应的挂载调用
4. 重建 → python mobile/build.py
```

第 3 步的三处必须一起改，漏一处就会出现「图在但永不显示」或「要显示却找不到图」。
