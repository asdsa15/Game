## 三、图键体系（`sceneArtKey()` 的推导规则）

**原则：新增一个纯渲染函数，不碰 `scenePlace()`。** `scenePlace()` 管文案（`scene()` 依赖它），改它就是改逻辑。新函数只读 `S`，不写 `S`，对游戏零侵入。

```js
/* 纯渲染层：只读 S，不写 S。不影响 scene()/scenePlace() 的文案逻辑。 */
function sceneArtKey() {
  // 1) 特殊状态优先（与 scene() 的优先级链同序，但独立维护）
  if (S.justBroke)     return 'break';     // game.js:1695
  if (S.hp / S.hpMax < 0.33) return 'hurt'; // game.js:1696
  if (S.justClosed)    return 'closed';    // game.js:1697
  if (S.visitorIncoming) return 'visitor'; // game.js:1698
  if (S.famine)        return 'drought';   // game.js:1699  ← 上游清单漏项

  // 2) 固定场景
  if (S.inDongtian)    return 'dongtian';  // game.js:1678
  if (isShen())        return 'temple';    // game.js:1679
  if (S.cultPlace === 'market') return 'market'; // game.js:1683
  if (S.sect && S.xRealm >= 1) return 'sect';     // game.js:1687

  // 3) 大洲主景（新增层：S.place 真正参与选图）
  const z = ZHOU_ART[S.place];   // qingyue/nanyue/xisha/beiyuan/zhongzhou
  if (z) return z;

  // 4) 兜底
  return (S.xRealm >= 1 ? 'cave' : 'wild');
}
```

## 四、图片清单

### 4.1 风格骨架（全部 85 张共用，只换主体）

> 中国水墨淡彩游戏概念插画，墨线为骨，青金淡彩晕染，米白宣纸底色，柔和光影氛围感，横构图 16:9，画面干净无文字无印章无 UI 元素

**批量生成的关键约束**（沿用上游方案 §二 + 本次新增）：

1. **参考图**：一律用 `generated-images/样张C_水墨淡彩概念.png` 作 `reference_images[0]`，prompt 内以"图1"指代，并明确"**只沿用图1的笔触与调性，不沿用其具体画面内容与人物形象**"。这是 85 张不漂移的唯一保证。
2. **不许模型画字**。所有画面**不得出现任何文字、题跋、印章、牌匾题字**。地名、结局名、州名一律用 HTML/CSS 叠加渲染——模型的中文文字不可靠，且会破坏风格统一。
3. **人物只画剪影或远景**，不画正脸特写。水墨淡彩里写意人形最稳，正脸容易崩且风格跑偏。
4. **构图留白**：横幅类主体占画面宽度 30%~60%，且**偏置于下 2/3**，上 1/3 留给天光与云气——界面里的文字条会盖住下缘，主体需要在中上部有视觉锚点。

## 五、技术规格

### 5.1 五类资产的规格差异（不能一套参数打天下）

| **B 衬底** | S4 / S5 | 2048×1152 PNG | JPEG q78 | **1600×900** | 否 |
| **C 立绘** | S7 | 1536×2048 PNG（3:4） | PNG | 768×1024 | **是** |
| **D 图标** | S8 | 1024×1024 PNG | PNG | 256×256 | **是** |
| **E 地图** | S6 | 2048×1152 PNG | JPEG q80 | 1320×570 | 否 |

### 5.2 透明底资产的两步法

C/D 两类必须走 `connector__matrix__remove_image_background`：

1. **生成时用纯色对比底**（推荐纯品红 `#FF00FF` 或饱和青），prompt 写"人物立于纯品红背景之上，无投影、无地面、无渐变"，模型更容易切干净
2. **生成后调用** `connector__matrix__remove_image_background --args '{"image_url":"<temp_url>"}'`
3. 交付时**同时交付带底原图与透明结果**，不只给透明图

> A/B/E 三类是**满幅图**，不做抠图，避免误伤画面内的青绿山水。

### 5.3 裁切与压缩

压缩管线已实跑验证：`tools/compress_art.py`

```bash
python tools/compress_art.py                 # 默认 generated-images/art/ → assets/scenes/
python tools/compress_art.py --only cave,wild
python tools/compress_art.py --class backdrop # 强制按衬底规格（16:9 不裁切）
```

脚本**按键名自动判规格类**：`dying` / `over` / `map` / `end_*` → 衬底类（1600×900，16:9 直接缩放，**不裁**）；其余 → 横幅类（1320×570，21:9 裁切）。

- 横幅类裁切：21:9 从 16:9 裁**上下**（纵向取景偏上，45%/55% 分），横向满幅不裁
- 重采样：LANCZOS → 目标尺寸
- JPEG / optimize / progressive / 4:2:0；横幅 q80，衬底 q78
- 逐张打印体积并判定是否落在方案的 180~280KB 区间

实测：`样张C 6.9MB PNG → cave.jpg 1320×570 146KB`（该图留白多、笔触简，低于区间下限但完全可用）；同一张按衬底规格输出为 `1600×900 260KB`。16:9 的正式生成图内容更满，预计落在 180~280KB 区间。
