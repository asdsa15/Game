> 2026-11-18 ｜ 状态：📝 方案稿（待评审）

> 本方案只做**插画层**；氛围装饰层、文字动效层另立小方案。

> ③ **12 个结局共用一张图** —— `ENDINGS` 有 12 个，`renderOver()`（L7637）按 id 取，结局是全游戏情绪顶点。
> 另：本文 §5.2 的压缩规格已扩展为**横幅类**（1320×570 / 21:9 裁切 / q80）与**衬底类**（1600×900 / 16:9 不裁 / q78）两套，
> 由 `tools/compress_art.py` 按键名自动判定。

## 四、挂载逻辑

### 4.1 主场景横幅（play 页中栏）
- 位置：`.main-panel` 内部顶部、境界条上方；桌面高约 190px，手机约 140px（21:9 视窗裁切，`object-fit: cover`）
- 实现：新增 `renderSceneArt()`；图键直接取 `scenePlace()` 的返回值——**图随文走**
- 图文对齐：特殊场景（破境/重伤/出关/来访）的取文优先级已存在于 `scene()`，挂图沿用同一优先级，图文永远匹配
- 过渡：换图 300ms 淡入；同图不重放动画
- 下边缘用面板底色渐变羽化，让图"长"在纸面上

### 4.2 斗法页（combat）
- 斗法双栏顶部通栏窄幅，高约 120px，单独用 `combat` 图（combat 阶段 `scenePlace()` 虽强制 wild，但斗法页不用 wild 图）

### 4.3 创角页（create）
- 创角页顶部大图，高约 220px

### 4.4 临终 / 结局（dying / over）
- 作为整页低不透明度衬底（约 0.25 + 去饱和），不抢文字

### 4.5 弹窗不挂图
- NPC 遇见 / 传法 / 坊市等弹窗保持纯文字（NPC 立绘放二期）

## 五、技术方案

### 5.1 资源组织
- 新建 `assets/scenes/`，源图与键同名：`cave.jpg`、`wild.jpg`…
- 新建 `wxcs3-art.js`：`const ART = { cave: 'assets/scenes/cave.jpg', … }`，index.html 在 data.js 之前引入

### 5.2 压缩规格
- 生成原图 2048×1152 PNG → 裁 1320×570（21:9）→ JPEG q80 → 单张约 180~280KB，14 张合计约 3MB

### 5.3 构建管线兼容（关键）
- `mobile/build.py` 追加一步：`assets/scenes/*.jpg` 转 base64 生成 `ART_DATA` 注入 dist；`wxcs3-art.js` 检测到 `window.ART_DATA` 则优先用内嵌数据
- dist 保持"单文件双击即玩"；体积 776KB → 约 4.8MB，本地单机可接受
- **fallback**：图加载失败时 `sceneart` 容器静默隐藏，界面回退纯文字——现有布局零风险

### 5.4 加载策略
- `<img>` 原生加载（file:// 协议无 CORS 问题）+ JS 预载：开局预载当前图，切地点后台预载、就绪后再淡入，避免闪白

## 八、风险与护栏

| 风险 | 护栏 |
|---|---|
| 批量生成风格漂移 | prompt 模板锁定 + 逐张过目，不合格重生成 |
| dist 单文件膨胀 | JPEG q80 + 21:9 裁切；超预算则降 990px 宽（内嵌约 2.8MB） |
| 渲染改动碰坏逻辑 | 只动渲染函数与 CSS；263 断言全跑 + `check_actions.py` |
| file:// 协议加载 | 用 `<img>` 非 fetch，无 CORS 问题；dist 走 base64 双保险 |
| 存档兼容 | 不动存档结构，旧档直接可用 |
