## 二、四艺为什么用不了：三个真 bug

### B1 · 花钱买的材料，四艺永远看不见（总闸）

```js
// ACT.do_buy 里，材料分支
S.bag[it.id] = (S.bag[it.id] || 0) + 1;   // ← 写进 bag
```

而四艺查的是另一个字段：

```js
function hasMats(recipe) {
  for (const k in m) {
    if ((S.bagMat[k] || 0) < m[k]) return false;   // ← 查 bagMat
  }
}
```

**结果**：在坊市花了灵石买齐材料，回到四艺界面，`hasMats()` 一律返回 false，只弹一句「材料不足」。

修：改为 `addMat(it.id, 1)`（写入 `bagMat`）。

**老存档迁移**：读档时把 `bag` 里的材料 id 全搬到 `bagMat`，已花的钱不白花：

```js
Object.keys(out.bag).forEach(function (k) {
  const isMat = (D.MATERIAL_EXT || []).some(function (m) { return m.id === k; });
  if (isMat && out.bag[k] > 0) {
    out.bagMat[k] = (out.bagMat[k] || 0) + out.bag[k];
    delete out.bag[k];
  }
});
```

### B2 · 制符永远做不出来（缺朱砂）

配方需要的材料 vs 宗门任务能给的：

| 材料 | 哪张配方要 | 旧任务是否给 |
|---|---|---|
| `zhuSha` 朱砂 | **火符、增益符（制符必备）** | ✗ 从来不给 |
| `gulingHua` 骨灵花 | 生肌续骨丹 | ✗ |
| `longYan` 龙岩铁 | 九转飞剑、五行轮杀阵 | ✗ |
| `starSand` 天璇星砂 | 九转飞剑 | ✗ |

所以「制符」这条最短的产业链，在旧版里**从材料端就断了**。

修：五个宗门任务各自补齐，每个任务至少能凑齐一条完整配方。

```js
const drops = {
  caoyao:  [...{ id: 'gulingHua', n: 1 }],
  liandan: [...{ id: 'gulingHua', n: 1 }],
  xunshan: [{ id: 'tieMu', n: 2 }, { id: 'fuZhi', n: 3 }, { id: 'zhuSha', n: 3 }],
  lieyao:  [...{ id: 'longYan', n: 1 }],
  zhensou: [...{ id: 'starSand', n: 1 }]
};
```

### B3 · 散修没有任何材料来源

旧版唯一给料的地方是**宗门任务**。不入宗门 = 一点料都拿不到 = 四艺不存在。

修：新增**采集**（`ACT.openGather` / `ACT.do_gather`），占一月，不花灵石，三个方向各有偏重：

| 方向 | 产什么 | 适用 |
|---|---|---|
| 山野采药 | 蓝幽草 / 补气草 / 合神花 / 骨灵花 / 玉华宝鱼汁 | 炼丹 |
| 溪畔掘砂 | 符纸 / **朱砂** / 金灵砂 / 幻属石 | 制符 |
| 废弃矿洞 | 铁木心 / 龙岩铁 / 天璇星砂 / 幻属石 | 炼器、阵法 |

- 每次 2~4 份（神识 ≥15 多一份）
- 只有境界够得着的品阶才进池子（`CRAFT_REALM_GATE`）
- 稀有一份的概率 = `10% + 境界×5% + 灵气×4%`

## 四、新东西弹窗

新增 `queueGain()` / `flushGain()` / `openGain()` 三个函数。

**为什么不在获得时立刻弹**：`advanceMonth()` 里可能已经开了奇遇或事件面板，直接弹会把它顶掉。所以先入队，由流程末尾调用 `flushGain()`；并且检查 `modalBusy()`——面板已经开着就不弹。

弹窗覆盖的场景：

| 场景 | 触发 | 是否强制 |
|---|---|---|
| 采集所得 | 每次采集 | 是（列出全部） |
| 炼制所得 | 每次制作 | 是（成品 + 品相） |
| 宗门任务所得 | 每次交任务 | 是（材料 + 贡献） |
| 学技艺 | 买技艺书 | 是（列出解锁的配方） |
| 得神通 | 抽取时 | 是（类别 + 效果说明） |
| 买功法 | 首次买到 | 是（提醒要参悟） |
| 买法宝 | 每次 | 是（提醒要佩戴） |
| 买材料 | **仅首次见到该种料** | 否（连买十份不弹十次） |

示例（采集）：

```
采集所得
  蓝幽草    ×2    最常见的疗伤草药
  朱砂      ×1    制符定属性，赤色最灵
采集占去一个月。料在「四艺 → 材料库存」里，做东西时点配方就能看见够不够。
```

## 五、战斗：神通终于能用了

### 5.1 断在哪

```js
// 战力计算里，神通只在这里出现过
let sd = 0.8 + S.shenTong.length * 0.05;   // 每道 +5%
```

玩家辛苦集齐四道「溪上翁」「入坎窞」「浩瀚海」「长云暗」，战斗里**一道都用不出来**，界面上也看不见。

而「术」按钮打开的面板只列**招式**（`equippedSkills()`）——散修装配上限 2，所以全程只有 2 个攻击手段 + 1 个普攻。

**这就是「攻击方式单一」的全部来源。**

### 5.2 四类神通，各管一件事

原著里只有 27/162 道神通标了类别（如「分阳钗（命）」）。没标的按**名字稳定哈希**分配，同一道神通每次都是同一类。

| 类 | 倍率 | 灵力 | 效果 |
|---|---|---|---|
| **命** | ×1.85 | 45 | 必中，正面破防 |
| **术** | ×1.55 | 40 | 压势：敌两回合伤害 −30% |
| **身** | ×1.15 | 30 | 自愈一成二 + 本回合护体 |
| **目** | ×1.30 | 35 | 看破破绽：敌两回合受伤 +25% |

**抽取时轮转**：`S.stKind` 记录类别，没标注的神通优先挑「手上还没有的类型」，避免四道全是同一手感。

实测：连续抽四道 → 类别 **命/术/身/目 全部不重复**。

### 5.3 三条硬规则

1. **不占装配格**——神通是你的道，不是学来的手法
2. **每道每场只能出一次**——它是大招，不是第二个普攻
3. **必中**（术类 82%）——灵力花得多，不该被 72% 命中率气死

## 七、踩到的坑（记录下来）

**弹窗调用顺序**：`openGain()` 如果写在 `closeModal()` 之前，会被后者当场关掉——面板一闪而过，等于没弹。所有「先关旧面板再弹新面板」的地方，`openGain` 必须放在 `closeModal(); render();` **之后**，并加 `if (!modalBusy())` 保护。

**测试用的敌人要够强**：第一次测神通时我设了个 200 战力的练气敌人，玩家紫府一击 309 伤害直接秒杀，`S.combat` 变 null，我还以为是「用神通导致战斗异常结束」。**测战斗要保证敌人能撑过测试的回合数。**
