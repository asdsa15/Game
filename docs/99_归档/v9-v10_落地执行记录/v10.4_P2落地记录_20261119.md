## 一、一句话总结

P0 兑现已有承诺，P1 让选择分岔，P2 把**神通与功法这两套系统接上**：
功法决定「你擅长什么」，神通决定「你这一场怎么打」，两者在回合结算里相遇。
另外补上神通取舍面板与功法熟练度，让「带哪几道」「练了多久」都成为可见的决定。

## 二、P2 三项

### P2-1 神通 × 功法五条联动（方案第四节）

神通的五行从哪里来？**神通本身没有 `el` 字段**（178 个裸字符串，按方案不改表）。
只能从「这道神通出自哪个道统」推导：`S.daotong` → 道统大类 → 五行。
于是同一道神通在不同道统下吃到的功法加成不同——这正是「我修什么」与「我这一击」首次相遇。

| # | 联动 | 实现 | 实测 |
|---|---|---|---|
| 1 | 功法 `dims[el]` × 同属神通 | 新增 `EXT.gongfaShenTongMul(el)`；只读 `dims`，不乘品阶与 `all`；**封顶 1.5** | 烈火掌（火 1.25）配火属道统：伤害 ×1.25，战报标 `功法×1.25` |
| 2 | 炎上气质 × 带 `burn` 的功法 | `foeBurnMul` 从 0.5 提到 `min(0.9, 0.5 + gongfa.burn×0.5)` | 0.5 → 0.75，战报标 `焚身` |
| 3 | `heal` 功法 × 身神通 | 自愈量 ×`(1+heal)` | 1.2e8 → 1.5e8，标 `自愈 N+功法` |
| 4 | `fate` 功法 × 目神通 | 破绽 2 → 3 回合 | 标 `破绽 3合` |
| 5 | 四象归元 × 功法品阶 | 归元时品阶乘区额外生效一次，取半权重 | 仙阶 1.55 → ×1.275；黄阶 ×1.0 |

**关键取舍**：
- 联动一**不做惩罚**——功法与神通不同属就是 ×1.0，不是打折。否则玩家会被迫「功法与神通配对」，那是指令不是选择。
- 联动一封顶 1.5：功法 `dims` 最高 1.40（玄元剑经），留余量但封死，避免与归元、偏执叠成打穿。
- **反例有断言**：无态势时功法品阶绝不影响神通（`无态势 聚气 = 百炼`）。这是「神通是独立的道」这条设定的底线。

### P2-2 神通取舍面板（`S.stEquip` 子集）

方案原意是「让全持有全可用变成选带 N 道」。落地时有个前提必须先说清：

**本项目已有 `shenTongLimit`（1~5 道）这道持有上限。**若再叠一层装配上限，等于双重限制——玩家本来就只有几道，再砍一刀，战斗会变得局促而不是有趣。

所以口径改成：

- **拥有即默认装配**（旧存档零迁移，读档行为不变）
- **装配数 = 持有数**，不新造上限
- 玩家可**主动卸下**，用途只有一个：**调整入场态势的类别构成**——卸掉两道术，把「偏执」换成「四象归元」

于是装配的意义不是「省着带」，而是「为了态势取舍」，与 S4 咬合。

| 实测 | 结果 |
|---|---|
| 全装四类 | 战力 110，态势含「四象归元」 |
| 卸到两类 | 战力 99，「四象归元」消失 |
| 只剩一类 | 战力 92 |
| 未设置 `stEquip` | 等同全装（旧档不变） |
| 卸最后一道 | 拒绝（不让玩家从此无法出手） |
| 未装配的神通 | 点了出不来，扣 0 灵力、不记已出 |

战斗菜单只列已装配，标题写明 `1/4 道（已卸 3 道）`。

### P2-3 功法熟练度 / 领悟点（方案标注「可选」）

方案对这项附了前提：**只有玩家已经能感知功法差异，成长维度才值得加**。P0/P1 做完后这个前提成立，所以做了。

设计上刻意避开「练得越久数字越大」的纯循环：

| 决定 | 理由 |
|---|---|
| 只随「真正用这本功法做事」增长（以它为道基修炼/闭关） | 换着功法乱试不涨、把书买来不读也不涨——熟练是「用过」的痕迹 |
| 三阶封顶（60 / 180 / 400），每阶只乘**主特征** ×1.25/1.5/1.75 | 不做全局乘区，否则熟练度就退化成「又一个数字」 |
| 主特征定义：有 heal 乘 heal、有 craftArts 乘该门手艺、有 ward 乘 ward | 增长的是「这本功法的性格」 |
| **纯战力功法（`all`/`dims`）不吃熟练度** | 否则剑经练到化境就等于全局加伤，与「性格」无关 |

实测：

| 功法 | 所长 | 初习 | 化境 |
|---|---|---|---|
| 长春功 | 疗伤 | heal 0.25 | heal 0.4375 |
| 造化丹经 | 技艺 | 炼丹 +25% | 炼丹 +43.75% |
| 天河剑诀 | 杀伐 | 招式 ×1.831 | ×1.831（**不变**，纯战力不吃） |

面板显示「熟练 小成　60 / 180　｜　所长：疗伤　｜　该长已 ×1.25」。
各功法各记各的：换到梅花易后熟练度从 0 起。

## 三、过程中修掉的一个 bug（P1 遗留）

### `curStance()` 把「显式无态势」误判成「还没设过」

```js
// P1 写法
const id = c.stance || (stanceList()[0] || null);
```

`c.stance = null` 时会回退到「第一个已达成的态势」。于是**测试里想验「没有态势」的场景，实际一直在吃「四象归元」的归元乘区**——表现为「百炼（仙阶）比聚气强 1.275 倍」，看起来像功法品阶穿透到了神通，其实是归元 ×1.275。

修法：用 `hasOwnProperty` 区分「没设过」与「设成 null」：

```js
const id = Object.prototype.hasOwnProperty.call(c, 'stance')
  ? c.stance                                   // 设成 null = 本场明确不要态势
  : (stanceList()[0] || null);                 // 没设过 = 自动判定（旧存档兼容）
```

**为什么值得记一笔**：这是「用 `||` 给可选字段兜底」的经典坑。`null` 与 `undefined` 在这里语义不同——一个是「明确没有」，一个是「还没决定」。本项目的战斗态是临时对象，读档不会带 `stance`，所以两种语义都必须支持。

## 七、风险与后续

1. **联动叠加上限是拍的 1.7**。五条同时开（火属道统 + 火功法 + 化境 + 四象 + 偏执）时实测 ×1.25，远低于上限，但这不代表所有组合都安全。若后续加入更多乘区，应在 `do_cbt` 的神通分支入口做一次总乘区封顶，而不是逐个调。
2. **熟练度增长速率偏慢**：每月 4 点、闭关 8 点，到「小成」需 15 个月，到「化境」需 100 个月。这是刻意的（长期维度不该几旬到位），但若玩家反馈「感觉不到」，优先调 `GF_PROF_STEPS[0]`（60）而不是月增量——门槛低一点比涨得快更有获得感。
3. **装配与上限的关系是我做的判断**，方案原文只说「选带 N 道」。我选择「不新造上限、卸装只用于调态势」，理由写在 P2-2 表格上方。若后续想要真正的「带 3 道里选 2 道」，需要同时放宽 `shenTongLimit`，否则双重限制会很难受。
4. **`test_m3` 的种子钉死**是修了测试脆弱性，不是修功能。那条断言此前 1/5 概率失败，与 P2 无关，但既然撞上了就一并处理。
5. **方案已完成 P0→P2**。下一版若要继续，方向应在方案之外：神通/功法的**获取与养成节奏**（现在神通靠紫府三关、功法靠坊市买/传法），而不是继续加乘区。
