# 源码地图（虚拟归类 · 2026-11-20）

> **为什么是"虚拟"归类**：根目录的 `wxcs3-*.js` 被主 HTML（19 处 `<script src>`）、`mobile/build.py`（硬编码路径 + `glob('wxcs3-ext-*.js')`）、`desktop/scripts/sync-app.js`（扫描根目录）、28 个测试脚本（`path.join(ROOT, 'wxcs3-...')`）共同引用。

## 二、"看起来杂乱"怎么处理

根目录平铺 20 个 js 是**构建系统的硬要求**，不能靠移动解决。可行的"整洁化"手段：

1. **资源管理器里按类型排序**：点表头"类型"或"名称"，`wxcs3-*.js` 会自动聚在一起，视觉上就成组了。
2. **编辑器里用折叠/筛选**：VS Code 资源管理器可按 `wxcs3-ext-*` 过滤；或用 `files.exclude` 临时隐藏不关心的组。
3. **靠本文档定位**：改代码前先查 `docs/00_项目地图.md`（行数与函数索引）+ 本源码地图，不用在文件堆里翻。

> ❌ 不要做的事：把 `wxcs3-*.js` 拖进新建的 `src/` 文件夹。会同时打断 19 处 HTML 引用、`build.py` 的路径与 glob、`sync-app.js` 的目录扫描、28 个测试脚本的路径拼接。

## 三、新增文件该放哪（决策表）

| 你要加的东西 | 放到哪 | 要不要改引用 |
|---|---|---|
| 一张新数据表 | 加进 `wxcs3-data.js` | 否 |
| 一个新玩法 | 新建 `wxcs3-ext-<序号>-<名>.js`，照抄 demo | HTML 加一行 `<script>`；`build.py` 自动收集 |
| 一个纯函数 | 加进 `wxcs3-rules.js` | 否 |
| 一段插画数据 | 加进 `wxcs3-art.js` | 否 |
| 图标映射 | 跑 `art/pipeline/build_icon_map.js` 重新生成 | 否 |
| 一篇文档 | `docs/` 对应主题号目录 | 更新 `README` 文档索引 |
| 一个测试 | `tools/test_*.js`，ROOT 用 `path.join(__dirname,'..')` | 否 |
